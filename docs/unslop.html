1 — 概要

UI redline skill for Claude Code and Codex

unslop は、vibecoding で生まれた「AI が作ったと一目で分かる UI」を、設計された画面に直すためのスキルです。作者は X で Unslopping シリーズを始めた Damir Sokolovsky（@heydamir）です。紫のグラデーション、グロー、絵文字ラベル、叫ぶコピー、揃っていない余白といったスロップ（slop）の兆候をまず列挙し、製品そのものから方向（direction）を決め、デザイナーがレッドラインを引いて直すように、画面全体を 1 レイヤーずつ 9 回のパスで修正します。

機能、コンテンツ、セクションの順番は変えません。変わるのは、あらゆるサイズ・色・言葉・画像が意図を持ったものになることです。スロップを除くだけでは「どの製品にも置ける次のテンプレート」になるため、毎回この製品にしかあり得ない画面で終わることを求めます。豊かさの置き場所が核心です。スロップは色と効果をクローム（背景、ボタン、枠、ラベル）に撒き、クラフトはクロームを静かに保ち、記憶に残る 1〜2 か所のコンテンツに豊かさを集めます。

Next.js、React、Vue、Svelte、Tailwind、素の HTML と CSS のどれでも動き、ダッシュボード、アプリ、ランディングページを対象にします。コードが無くリンクしか無いライブサイトも、Playwright でスナップショットして扱えます。

3 — インストールと起動

Claude Code

スキルフォルダをユーザーのスキル置き場へコピーします。1 つのプロジェクトだけで使うなら、そのプロジェクトの .claude/skills/ へ入れます。

git clone https://github.com/heydamir/unslop
mkdir -p ~/.claude/skills && cp -r unslop/skills/unslop ~/.claude/skills/

Codex

skill-installer でリポジトリから直接入れるか、~/.agents/skills/（プロジェクト単位なら .agents/skills/）へ手でコピーします。

$skill-installer install https://github.com/heydamir/unslop/tree/main/skills/unslop

# または
git clone https://github.com/heydamir/unslop
mkdir -p ~/.agents/skills && cp -r unslop/skills/unslop ~/.agents/skills/

任意の依存

ライブサイトのスナップショットとストーリー動画には Playwright と Chromium が要ります。スキルを実行するプロジェクトのディレクトリで入れます。ストーリー動画にはさらに ffmpeg が PATH に必要です。

npm install -D playwright
npx playwright install chromium
# story video: ffmpeg を PATH に（macOS の例）
brew install ffmpeg

呼び出し

Claude Code では /unslop、Codex では $unslop に続けて要望を書きます。自然文で「AI っぽく見えないように直して」と頼んでも、エージェントがスキルを拾います。

/unslop this dashboard
/unslop the hero of https://example.com
/unslop my landing page and make the story video so I can post it
編集前に止まる。監査と方向を提示してからユーザーの返事を待ちます。方向を後から変えるとすべてやり直しになるためです。質問ツールがあればそれで、無ければ平文で尋ねて止まります。「とにかくやって」と最初に言われたときだけ待たずに進みます。

4 — 実行の流れ

1 look→ 2 audit→ 3 decide how much→ 4 direction + wait→ 5 nine passes→ 6 check→ 7 report→ 8 record (optional)
手順内容
1. 画面を見る画面を描いているファイルを探す。アプリを起動するか HTML をブラウザで開いてスクリーンショットを撮り、コードだけでなく人が見るものを判断する。リンクしか無ければ snapshot.mjs で保存したコピーに対して作業し、スクリーンショットしか無ければまず 1 枚の静的 HTML として再現する。どちらも成果物は「サイトの持ち主に渡せる再設計済みのコード」であり、報告にそう書く
2. 監査signs.md の全群を順に見て、見つけた兆候を場所付きで 1 行ずつ列挙する
3. 変える量を決める監査を正直に読んでから計画する。下の 3 段階
4. 方向を書いて止まる5 行（方向づけ）を書き、監査と一緒に提示し、返事を待つ
5. 9 つのパス各パスを画面全体に当て終えてから次へ。ほぼ全行が変わる場合は順に計画した上で新しい画面を一度に書いてよいが、全パスが適用されていること
6. 確認チェックリストを通し、再描画して監査リストと突き合わせる。残っていれば直す
7. 報告方向、パスごとに数行の変更点、書いた画像プロンプト、未確認の主張
8. 記録（任意）求められたときだけストーリーファイルを作り動画を書き出す。最初から頼まれていれば、パスごとにストーリーファイルへ書き足していく

スロップの量による 3 段階

Heavy 重いスロップ

色、書体、アイコン、コピーにまたがって多数の兆候がある。フルプロセスを実行する。

Light 軽いスロップ

ほぼ設計済みで兆候が少し残っている。ポリッシュモード。監査で見つけたものだけ直し、方向は既存のブランドから取り、パレット、書体、レイアウト、ビジュアルは維持する。大きな案は変更ではなく報告の提案に回す。

None スロップなし

そう明言し、正確な値を添えた小さな改善を最大 2〜3 個提案する。ユーザーが同意したときだけ適用し、そこで止める。良い画面を「違うものにするため」に変えない。

実行は短く。確認のための再描画は 1 回の実行で最大 3 回。画像を生成するときは方向が確定した直後に始め、生成を待たずに最初のパスを進めます。ストーリーファイルと動画の確認はこの回数に含めません。

5 — 方向づけ（Direction）

何かに触る前に、短い 5 行を書きます。ページが語る「製品が何をするか、誰のためか」から導き、流行からは導きません。例は答えの形を示すだけで、例が当てはまりそうでも目の前の製品から導き直します。

行書くこと例の形
Product何を、誰のためにするか。平易な 1 文—
Character具体的な語を 2〜3 個。clean、modern、sleek、minimal、premium は禁止。あらゆるテンプレートを形容してしまうためcalm, exact, a little warm / fast, technical, playful
World製品が自然に属する場所や素材。ニュートラルの色味、アクセント、ビジュアルを決めるメモアプリは紙とインク、監視ツールは計器と夜勤、旅行アプリは地図と窓の光
Moments豊かな色、素材、細部を置く 1〜2 か所。製品が見せているものから選ぶプレビュー内のレンダリングされたカードや端末、色がそれぞれ系列を表すチャート、世界の物をコンテンツの隣に
Signatureこの製品だけが持つ小さな細部を 1 つ、一貫して使う。5 つではなく 1 つ監視ツールのライブ状態ドット、開発ツールのキーキャップ、教育アプリの手描き下線、配送アプリのルート線
本物のブランドは残す。ロゴファイル、色、書体がスロップでなければ、それを軸に方向を組みます。ただし紫から青へのグラデーション、キラキラ、グローはロゴに入っていてもスロップであり、ユーザーが明言しない限りブランドと見なしません。

6 — 9 つのパス

順番には理由があります。余白が最初なのは、リズムが整うと他のすべての見え方が変わるからです。コピーが書体とレイアウトより前なのは、見出しの長さがサイズと位置を決めるからです。ビジュアルとモーションが最後なのは、それ無しで成立している画面に載せるべきだからです。各パスの正確な値は tokens.md にあります。

1 spacing→2 color→3 icons→4 copy→5 type→6 layout→7 details→8 visuals→9 motion
パス主な規則
1. 余白すべて 4px グリッド。同じものは同じサイズ。グループ内の間隔はグループ間より小さい。アイコン、ラベル、数字は各 1 列に揃う。密度に応じたパディング（パネル 16、カード 20〜24、ページ端 24〜32）。ナビはアプリで最も密な場所で、行 32〜36、間隔 2〜4。mt-[13px] のような一回限りの値は捨てる
2. 色世界に向けて色味を付けた 1 本のニュートラルランプから、背景、面、枠、文字を取る。アプリとダッシュボードの面はグラファイト級に灰色のまま。文字は primary / secondary / muted の 3 役。クロームのアクセントは 1 色をまれに。瞬間の中だけは色が豊かでよい。アクセント上の文字はコントラスト 4.5:1。面の色相グラデーション、グラデーション文字、色付きグロー、色付き影、放射状の色、ネオン枠を除く。枠は文字色の 6〜10% のヘアライン。ダークテーマの深さは面の段差とヘアラインで出し、影に頼らない
3. アイコンアイコンや装飾の絵文字を 1 セットのラインアイコンへ（既存のセット、無ければ lucide）。16 か 18px、ストローク 1.5 で統一。色は文字の役割の色。アイコン枠の幅とラベルとの間隔を固定。意味のないアイコンは落とす
4. コピー見出しは「何を誰のためにするか」。感嘆符なし。Welcome back, Damir! 👋 のような挨拶見出しは、ページ名や期間（October 2026）へ。短いラベル。変化は比較対象付き（+12% vs last month）。短い文字列は末尾ピリオドなし。supercharge、seamless、unlock、magic などの煽り語を除く。検証できない主張（Loved by 10,000+ teams）は本物なら静かに具体化し、違えば除き、報告に列挙する。モックデータは本物らしく
5. タイポグラフィ方向の性格に合う書体をトークンの一覧から。本物のブランドの書体は残し、誰も選んでいない Inter は換えてよい。インターフェイスに 1 書体、パートナーは最大 1 つ（数字とメタ用のモノ、または大見出し用のディスプレイ）。ウェイトは 400 と 500、強調でも 600 まで。階層はサイズと色で、太さに頼らない。すべて sentence case で、PAID THIS MONTH のような追跡の広い大文字ラベルは Paid this month へ。小さな文字に負の字間は使わない。数字は tabular-nums と 1 つの書式。イタリックでの強調なし
6. レイアウトセクションと順番は維持。アプリはビューポートを満たし、サイドバー 240〜280 に流動的なコンテンツ（1440〜1600 程度で上限）。アプリを狭い中央カラムへ縮めない。最も強いランディングのヒーローは情景で、生成画像が端から端まで広がり、見出しは画像の静かな部分に、製品ビューが下端から立ち上がる。情景が無ければ非対称の分割か、大きな製品ビューの上に文字。全部を縦積み中央揃えにしない。主アクション 1 つと副アクション最大 1 つ。ナビは静かに。ファーストビューを全体として構成し、死んだ空白の帯を作らない。小さな画面では読む順に積む
7. 細部入れ子の角丸は「内側 = 外側 − パディング」、4 未満にしない（コントロール 8〜10、カード 12〜16、パネル 14〜20）。件数やメタは静かな文字（しばしばモノ）に。ショートカットはキーキャップに。チャートは落ち着いたグリッドとモノのラベルで、1 つの主チャートが明らかに最大、他のデータは種類の違う小さなもの。チャートのアクセントは 1 色。統計カードは「ラベル、大きな数字、比較付きの変化」で、スパークラインや飾りのミニバーは入れない。カードの幅に変化をつける。アクティブ状態は面の段差とヘアライン。ホバーとフォーカスの状態を用意し、キーボード用のフォーカスリングを見せる。ロゴは製品名を主書体で
8. ビジュアル装飾の埋め草（光沢の塊、オーブ、星雲、浮いた立方体、光るグリッド、ホログラムの脳やロボット）を消す。ランディングのヒーローには本物を示すビジュアルを。ダッシュボードとアプリには生成画像はほぼ不要で、瞬間は製品自身（丁寧に描いたチャート、美しく組んだ数字、実データ）から出す。詳細は ビジュアル
9. モーション理由なく繰り返す動き（animate-pulse、animate-ping、見出しのシマー、呼吸するグロー、浮遊、パララックス）を除く。transition-all、弾むスプリング、カードの hover:scale を除く。説明になる動きだけ残す。遷移対象は color、background、border、opacity、transform に限り名指しで書く。width、height、top、left、margin、大きな blur は動かさない。イージングは 1 本、持続時間は数種類。読み込み時の登場は最大 1 回

7 — スロップの兆候

signs.md は、監査でなぞる兆候の一覧です。各行が「兆候 → 修正」の対になっています。10 群から代表例を抜粋します。

群兆候修正
表面と色背景、カード、ボタン、アクティブなナビ項目の紫→青や紫→ピンクのグラデーション。見出しや数字のグラデーション文字。shadow-[0_0_20px_rgba(139,92,246,0.5)] のような色付きグロー。コンテンツの奥の放射状の色や滲んだ塊。ガラスカード→ 1 つのニュートラルな面、意味のある場所だけにアクセント。単色の文字。面の段差とヘアラインで深さを出す
タイポグラフィウェイト 800〜900 の見出し。追跡の広い大文字ラベル。サイズとウェイトが多すぎる。$48,210 の隣に $124,860.40。小さな文字の負の字間。強調のイタリック→ 400〜500 とサイズで階層。sentence case。数行のスケール。1 つの書式と tabular figures
アイコンナビアイコン、ラベル装飾、状態の絵文字（🏠 📥 🚀 💰 ⚠️）。18 👤 のようなピル内の絵文字。AI を表す ✨→ 1 セットのラインアイコンか無し。素の数字。説明になる場合だけ平易なアイコン
余白mt-[13px]、ml-[7px]、h-[31px]。同じリストで行の高さが違う。グループが自分の項目より隣に近い。兄弟カードのパディング不揃い→ 4px スケールの段。1 つの高さと間隔。内側は小さく、間は大きく
コピー挨拶見出し。!!。比較対象のない変化。Search anything...。supercharge、seamless、unlock、magic。ラベルの末尾ピリオド。$123,456 や [X]→ ページ名や期間。平叙文。+12% vs last month。Search。実際にすることを書く。本物らしい数字

8 — トークン

tokens.md の値は出発点であってハウススタイルではありません。プロジェクトに良いシステムがあればその値を残し、使い方だけを直します。方向に応じて動かします。

余白とアプリのレイアウト

  • スケール: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96, 128
  • コントロール内 4〜12、関連項目間 2〜8、グループ間 12〜24、セクション間 32〜64（ランディングは 80〜128）
  • 行の高さ: 32 コンパクト、36 既定、40〜44 タッチ
  • サイドバー 240〜280、ページパディング 24〜32、上限 1440〜1600。トップバー 56〜64。主チャートは幅の 2/3 以上、高さ 280〜360

タイプスケールと角丸

  • 小ラベル 12/16、副文 13〜14/20、本文 14〜15/20〜22、ロゴ 16〜18、ヒーロー副見出し 18〜20、カード数字 28〜32、ページ題 28〜36、ヒーロー見出し 56〜72（モバイル 36〜44）
  • 16px 未満は字間 0。40px 以上で −0.02em、56px 以上で −0.03em まで
  • 角丸: キーキャップ 4〜6、行とボタン 8〜10、カード 12〜16、パネル 14〜20
  • イージングは cubic-bezier(0.22, 1, 0.36, 1) 1 本。ホバー 120〜180ms、メニュー 160〜220ms、登場 300〜500ms、スタッガー 40〜60ms で最大 6 項目

アクセントと書体

9 — ビジュアル

visuals.md は、装飾の埋め草を「この製品に属するビジュアル」へ置き換える手順です。ビジュアルのパスの前に、refs.md の完成例を見て、構図、光、抑制、瞬間の置き方といった性質を取り、題材、パレット、レイアウトは取りません。

何を見せるか決める

  1. 画面に要るか。ダッシュボード、設定、多くのアプリ画面には不要。ランディングのヒーローと空状態にはたいてい必要
  2. 画像ツールはあるか。あれば、方向の世界から情景を生成してヒーロー全体の背景にし、題材を片側、見出し用の静かな空間を反対側に置き、下端から製品を立ち上げる。これが最も強いヒーロー
  3. 製品を見せる。情景の下、またはツールが無いときのビジュアルとして、ページがすでに約束しているものをコードでプレビューする。アプリ全体ではなく見出しを証明する 1 つの瞬間（予約ツールなら予約済みの 1 週間、コードレビューならコメント付きの 1 つの差分）。既存コンポーネントか、新パレットでの丁寧な HTML と本物らしいデータで
  4. 情景を 1 文で書く。1 文で言えないなら、まだ明確ではない

うまくいく様式

  • 描かれた背景美術: 現代の日本のアニメ映画の背景のような、1 つの題材と静かな空。暖かく人間的な製品に
  • 1 つの物のシネマティック写真: 霧の中の灯台、宙に浮く紙の物。落ち着いた信頼を要する製品に
  • 柔らかい様式化 3D: マットな素材と穏やかな光の小さな情景。遊び心のある製品に
  • 製品の物のレンダリング: 決済カード、端末、荷物をスタジオ光で。物理世界に触れる製品に
  • 光と光学: 暗い場にプリズムを通る光 1 つ。技術やデータの製品に
  • 版画・印刷: 単色のインクと紙の色味に、同じ世界の書体とパレット。伝統、工芸、編集的な声を持つ製品に
  • 画像へのコード処理: グリフ、ドット、デュオトーンでページのパレットへ

失敗しがちなもの

  • フィルムグレインや紙の質感をプロンプトで頼む。モデルが細かい市松模様を焼き込む。質感はコードで足す
  • ページの残りが素のモダン UI なのに、1 枚だけ版画やリソグラフ。フィルターに見える。ブランド全体がその様式に住むときだけ成立する
  • 複数の題材や忙しいコラージュ。1 秒で伝わらなくなる
  • 紫と青の光沢のある抽象画のすべて

瞬間に置く物

  • 1 つの物をスタジオ光で、ページ色と同じ無地の背景に、柔らかい接地影で生成する。レイアウトに必要な角度を指定する
  • カードや窓の縁に重ね、少し回転させ、ランプの最も暗い色の柔らかい影で UI と同じ空間に置く
  • 背景除去は背景色に近い暗部（消えた黒い画面など）も消す。画面をコントラストのある平色で頼むか、輪郭からアルファを再構築する
  • 生成した端末に本物の UI を載せるには、正面から透視なしで生成し、画面の矩形を測って HTML を重ね、一緒に回転させる

生成の流れとプロンプトの組み立て

手持ちのツールから画像生成（fal、Replicate、OpenAI images、Higgsfield、デザインツールの MCP サーバーなど）を探します。あれば、プロンプト、モデル、サイズを見せて実行前に確認します（費用が発生するため）。1 回実行し、1 文とパレットに照らして判断してから、同じプロンプトを引き直すのではなく変えて再試行します。結果はプロジェクトのアセットに保存します。ツールが無く情景や物が要るなら、ビジュアルのパスの前にそう言い、接続を提案します。ユーザーが飛ばしたら、スロットを空のままにし、プロンプトはページではなく報告に書きます。空のスロットは正確なサイズと角丸の無地の面で、中に文字を入れず、未完成のものが誤って出荷されないようにします。

順部品内容
1Subject具体的で物理的な 1 文
2Settingどこにあるか、単純に
3Light and paletteページに合わせる。縁が溶けるようにページの背景色を名指しし、光の方向を書く
4Style性格に合う 1 つの明確な方向（cinematic photo、soft 3D render、editorial illustration、risograph print、painted background）
5Composition文字の場所が空くように題材を置く。ヒーロー全体の背景なら 16:9 以上で、製品ビューが乗る下 1/5 も静かに
6Exclusions文字、字、ロゴ、UI、透かしなし
7Formatスロットのアスペクト比で、表示サイズの 2 倍

ページに載せるときは WebP か AVIF で表示の 2 倍、内容を述べる alt、背景色の一致（合わなければ mask-image やページ色のグラデーションで縁を溶かす）、静止か題材に合う 1 つの遅い動き、高優先度の読み込みと固定寸法を守ります。

コード処理（effects.md）

画像をページ専用に見せる任意の処理で、方向の性格に合うときだけ、主ビジュアルにのみ使います。グリフは画像を文字のグリッドとして描き、明るさで文字を選びます。文字が製品の素材から来ると効きます（金融なら . : 1 7 4 0 8 $ %、開発ツールなら . : / { } < > = #、音楽なら音名と ♭ ♯）。セルは 6〜10px、書体はモノ、色は画像かランプから。effects.md には canvas の実装例が載っています。ほかにハーフトーン（明るさに応じた点の大きさ）、ディザ（ランプの 2〜3 色へ、読み込み時に 1 回）、デュオトーン（最も暗い面とアクセントか主文字色の 2 色へ）があります。

性能規則。これらは弱いノート PC で壊れた前例があるため、ピクセルの読み取りは読み込み時に 1 回だけ（ループ内で getImageData を呼ばない）、グリフのアトラスと着色済みセルを事前に用意して drawImage で描く、毎秒 8〜12 ステップで一部のセルだけ変える、画面外では止める、キャンバスは DPR に合わせつつ 2 で上限、と決められています。

10 — ストーリー動画

画面がスロップに赤いレッドラインを引かれながら、段階的に自分で直っていく短い動画です。元になったダッシュボードの動画が拡散したため、その作り方が手順化されています。数分かかるので、ユーザーが求めたときだけ作ります。

0.5s赤い選択枠とタグで、スロップに監査のビートを 1 拍（data-slop があるとき）
step 1Spacing。赤い寸法線が元の値から新しい値へ数えながら動き、直ると白になる
step 2Color and icons。紫が抜け、絵文字がクロスフェードでアイコンに
step 3Type and copy。文字がぼけて消え、新しい語が 1 文字ずつ立ち上がる
step 4Details。角の輪郭に半径が表示され、角丸が柔らかくなる
原則内容
何も差し替えず、すべてモーフする1 枚のページで、各ステップは CSS だけを変える。パディング、間隔、サイズ、色、角丸、影が古い値から新しい値へその場でトゥイーンする
波要素が左上から数十ミリ秒ずつ遅れて始まり、変化が画面を走る
文字が転がる変わるコピーはぼけて消え、新しい語が 1 文字ずつ立ち上がる
レッドラインが先スロップに赤い枠とタグ。余白ステップは赤い寸法線が直ると白に。細部ステップは角に半径の輪郭
近く、短く正方形で、最も変わる部分に寄せて切り、スマートフォンで読めるように。約 10 秒

ストーリーファイルの書き方

unslop-story/story.html に、元の画面をスタイルごと 1 ファイルで複製します。元の規則はそのまま残し、それがステップ 0 です。ステップは 3〜5 個で、見える変化があるようにパスを束ねます。新しいチャートやビジュアルは最後のステップへ。各ステップの変更は .s1、.s2 … の下に書き、クラスは積み上がるので、ステップ 3 にはステップ 1 と 2 の規則も効いています。値を変え、構造は変えないことで、ブラウザがトゥイーンできます。

<meta name="unslop-steps" content="Spacing, Color and icons, Type and copy, Details">
<meta name="unslop-frame" content="0 0 960">   <!-- x y width: どこを正方形に収めるか -->

<style>
  .s1 .card { padding: 24px; }               /* step 1: 余白 */
  .s2 body  { background-color: #141415; }   /* step 2: 色 */
  .s4 .btn  { border-radius: 23px; }         /* ピルは 9999px ではなく高さの半分 */
</style>

<!-- 変わる語だけ swap（1 本で最大 8 個） -->
<span class="swap" data-at="3">
  <span class="from">Welcome back, Damir! 👋</span>
  <span class="to">October 2026</span>
</span>
<span class="badge" data-out="2">New ✨</span>   <!-- step 2 で畳まれて消える -->
<div class="legend" data-in="4">…</div>         <!-- step 4 でフェードイン。場所は確保しておく -->

<aside data-gap="sidebar">…</aside>              <!-- 縦積みのブロックに。1 スタック 4〜6 個 -->
<button data-radius>…</button>                   <!-- 角が変わるボタンやカード 2〜4 個 -->
<h1 data-slop="Gradient text">…</h1>             <!-- 最初の 1 拍で赤枠。任意、最大 5 個 -->
トゥイーンできないもの扱い
グラデーション、グロー、放射状の色独自のレイヤーに置き、opacity を 0 へフェードさせ、下の単色を変える。グラデーション文字は .from の span にだけ掛ける（文字クリップは隠れた新しい文字も捕まえるため）
ピル半径は 9999px ではなく高さの半分（23px など）。さもないと角が最後のフレームでしか変わらない
swap の使いすぎ語が変わる場所だけ、1 本で最大 8 個。20 個が同時にぼけると 2 枚の絵の切り替えに見え、動画が最も避けたいものになる。ウェイト、サイズ、字間、色は自力でトゥイーンするので swap 不要。新しい書体はステップ内で直接切り替える
絵文字 → アイコン同じ枠に絶対配置で重ね、ステップで opacity をクロスフェード。swap ではなく、上限に数えない
消えるもの、現れるものdata-out="2" で畳む、data-in="4" でフェードイン。場所は確保して何も跳ねないように
画面だけ余計な窓、枠、影を足さず、ページ自身の背景がフレームを満たす。窓がデスクトップ比率へ育つなら左に固定して右へ広げる。ページは 1440 幅、高さ 900 以上で描画されるので 100vh でサイズを決めず、position: fixed は背景レイヤーだけ

クリーンな結果は、.s クラスやストーリー属性を含まない通常のコードとしてプロジェクトのスタックで別途出荷します。ストーリーファイルは見せるための作品です。すべての動画には、ライセンスが求める小さな unslop by @heydamir のクレジットが入ります。

11 — スクリプト

snapshot.mjs

ライブサイトを 1 枚の自己完結した HTML として保存します。Playwright（playwright か playwright-core、ローカルの Chrome があればそれ）でページを開き、フォントの準備を待ち、スタイルシートと画像を data URL へインライン化します（1 ファイル 3 MB まで）。--dark / --light は prefers-color-scheme のメディアクエリを書き換えて、ユーザーが見ているテーマに固定します。あわせて original.live.png にライブのスクリーンショットを残すので、保存したコピーを描画してライブと比べてから始められます。スクリプトで描かれるアニメーション背景は残らないため、監査ではライブページから記述します。

node <skill folder>/scripts/snapshot.mjs <url> unslop/original.html [pass label] \
  [--dark | --light] [--width=1440] [--height=810]

story.mjs

ストーリーファイルをローカル HTTP サーバーで配信し、iframe の中で描画して、unslop-steps の各ステップを時間計画に沿って発火させます。レイアウト系プロパティは 700ms のスプリング、色系は 900ms のイージングで、要素ごとの --wave 遅延付きでトゥイーンします。監査ビートがあれば 0.5 秒から約 0.9 秒表示し、全体を 1.1 秒ずらします。名前に spac を含むステップ、または detail / radius / corner を含むステップは 1.75 拍、他は 1.25 拍で、合計が 10 秒に収まるよう縮めます。1080×1080（--wide で 1920×1080）のビューポートをデバイスピクセル比 2 で撮影し、60 fps で 1 フレームずつ JPEG に保存して、ffmpeg で 2160×2160（--wide で 3840×2160）の H.264 MP4（-crf 18、+faststart）にします。--play なら出力せずブラウザ窓でループ再生します。

node <skill folder>/scripts/story.mjs unslop-story/story.html unslop-story.mp4 [--wide]
node <skill folder>/scripts/story.mjs unslop-story/story.html --play

どちらも Playwright が無ければ npm install -D playwright と npx playwright install chromium を、story.mjs は ffmpeg が無ければ brew install ffmpeg を案内して終了します。渡す前に ffmpeg で数フレーム抜いて目で確認する、と手順にあります。

12 — 禁止事項とチェック

Do not

  • 製品名を変えない（名前に AI が入っていても）。本物のロゴはそのまま。ロゴ自体がスロップ（絵文字、グラデーションタイルのキラキラ）なら平らに描き直す。光沢や グラデーションの球、グロー、グラデーションタイルは AI と一目で分かる
  • 製品が何かを変えない。機能、コンテンツ、セクションの順番を保つ。意味のないプレースホルダーだけは意味のあるものに置き換えてよい
  • 除いた装飾を新しい装飾で埋めない。ガラス、グレイン、ノイズ、ネオン、ベントグリッドのように、流行を別の流行に取り替えない
  • 機能、主張、データを発明しない
  • すべての製品で同じ見た目に落ちない。パレットの色味、書体、ビジュアルは習慣ではなく方向が決める

チェックリスト（抜粋）

  • 方向が書かれ、すべてのパスがそれに従う
  • 余白はすべて 4px スケール、同じものは同じサイズ。アイコン、ラベル、数字が各 1 列
  • 色味付きのランプ 1 本、文字 3 役、十分なコントラストのアクセント 1 色。色相グラデーション、グラデーション文字、グロー、色付き影、色の塊なし
  • インターフェイスに絵文字が残っていない。アイコンは 1 セット、1 サイズ、1 ストローク
  • 感嘆符なし、短い文字列の末尾ピリオドなし、挨拶見出しなし、未検証の主張なし。数字は 1 書式で tabular
  • 入れ子の角丸が計算に合う。ヒーローは本物のビジュアルか瞬間を持つ製品プレビューで、埋め草やラベル付きプレースホルダーではない
  • ループや弾む動きなし、イージング 1 本、レイアウトプロパティのアニメーションなし
  • テンプレート検査: 製品名を別の製品に差し替えても画面が成立するなら、コピー、ビジュアル、署名の細部で方向をさらに押し込む
