vercel-labs/issue-graph · GitHub / Linear · CLI + ローカルダッシュボード

01 — 作業前に、関連する課題と修正を調べる

RELATED WORK, BEFORE NEW WORK

この課題には、すでに
修正 PR があるだろうか。

issue-graph は、GitHub の Issue・Pull Request、または Linear の Issue を読み、本文・コメント・参照イベントなどのつながりをたどる調査ツールです。既存の修正、競合する PR、残ったフォローアップをまとめて確認し、人とエージェントが次に読むべき対象を見つけられます。

GitHub／Linear に対する操作は読み取り専用。課題のクローズや PR のマージは行いません。Vercel Labs の実験的プロジェクトで、ライセンスは Apache-2.0 です。

実装前の確認

1 件の Issue から関連 PR と後続課題へ。重複した実装を始める前に、先行する作業を読みます。

バックログの整理

未解決の作業をクラスタにまとめ、議論の活発さや関連する修正を手がかりに、調査・レビューの順序を考えます。

02 — 「言及」と「解決リンク」を区別する

ノードは Issue／PR、エッジは参照関係です。GitHub では本文・コメントの言及、タイムラインの相互参照、接続イベント、クローズ用のリンクを区別します。Linear ではブロック関係、関連課題、親子関係、添付リンクなどを読み取ります。

本文の「fixes」と実際の解決リンクは別です。 PR 本文で解決を宣言していても、GitHub の構造的な closing link がなければ、自動クローズされない可能性をレポートします。競合 PR や変更ファイルの重なりも、実装を読むための手がかりです。

03 — 導入して、最初のグラフを取得する

  1. Node.js 20 以上と GitHub CLI を用意

    GitHub の取得には gh のログインを使います。アカウントが未設定ならログインしてください。

    npm install --global issue-graph@latest
gh auth status
# アカウントが未設定の場合
gh auth login

    インストールせずにヘルプを確認するなら npx issue-graph@latest --help。

  2. リポジトリ全体、または特定の課題を指定

    GitHub リポジトリのチェックアウト内では issue-graph だけで未解決の Issue・PR を取得し、ダッシュボードを開きます。明示的な指定もできます。

    # 未解決の作業を取得してダッシュボードへ
issue-graph open vercel-labs/portless

# 1 件の課題を起点に参照をたどる
issue-graph graph vercel-labs/agent-browser#1113 --depth 1 --budget 12

  3. Linear は別途接続する

    ブラウザで一度ログインしてから、課題の周辺やプロジェクトを取得します。下のワークスペース名・課題番号・UUID は対象に置き換えてください。

    issue-graph linear login
issue-graph linear ENG-123 --workspace your-workspace --open
issue-graph linear --project <project-uuid> --open

    Linear の MCP サーバーを通じた読み取り用の認可を使います。対応する環境では LINEAR_API_KEY または LINEAR_ACCESS_TOKEN も利用できます。

04 — GitHub の作業を 4 つの表示で読む

GitHub は以下の 4 ビューに対応します。Linear は Explore／Swarm に対応し、Impact と議論のランキングは GitHub 向けです。

EXPLORE

クラスタと個別の文脈

まとまりを選び、個々の課題とリンク先を読みます。標準のまとまりは連結成分で、根本原因の分類とは限りません。

IMPACT

関係と影響先

取得したグラフ内のつながりを調べます。表示された関連は因果関係を保証しません。

SWARM

作業をまとめて比較

クラスタ・状態・種類などでグループ化し、未解決の作業を横断して確認します。

RANK

議論の Heat で並べる

コメント・参加者・リアクション・被参照数・経過時間を重み付けします。深刻度やマージ可能性の点数ではありません。

保存済みデータを CLI で絞り込む

# まず取得・保存（ブラウザは開かない）
issue-graph open vercel-labs/agent-browser --no-open --agent none

# 保存したモデルから、未解決 Issue を Heat 順で確認
issue-graph query github:vercel-labs/agent-browser --state open --kind Issue --view rank --json --no-open

# 保存済みプロジェクトを切り替えて閲覧
issue-graph dashboard

query は保存したモデルを読むだけで、API を呼んで更新したり、不足ノードを取得したりしません。新しい状態が必要なら open を再実行します。返る viewUrl は条件を含んだローカルファイルの URL で、公開ホスティングされた共有 URL ではありません。

05 — エージェントに調査の文脈を渡す

CLI とスキルは別に導入します。スキルはインストール済み CLI に同梱されたガイドを読み、バージョンに合うコマンドの使い方をエージェントへ渡します。通常のグラフ取得・状態確認・計画作成にはモデルは不要です。

npx skills@latest add vercel-labs/issue-graph
issue-graph skills get core
issue-graph schema

根本原因によるクラスタは、提案として作る

# エージェント向けの分類タスクを出力
issue-graph cluster owner/repo

# 提案を確認し、回答 JSON をダッシュボードに適用
issue-graph cluster owner/repo --apply clusters.json

owner/repo は対象へ置き換えます。--apply が更新するのは保存済みモデルと HTML 出力です。外部エージェントを起動する --agent claude / --agent codex は任意で、そのエージェントの認証・課金・データ保持設定に従います。

06 — 取得・分析・表示の構成

COLLECT

CLI と取得層

src/cli.ts が実行をまとめます。GitHub の取得は gh 経由、ライブラリではトークンを使う HTTP transport も選べます。

ANALYZE

ランタイム非依存のコア

src/index.ts からグラフ探索・分類・ランキング・描画を公開。Node.js 固有の取得処理は transport として分離されています。

INSPECT

静的なダッシュボード

apps/dashboard/ は Next.js の静的エクスポート。埋め込みデータを読むため、閲覧用サーバーを起動する必要はありません。

REUSE

保存と再検索

標準の保存先は ~/.issue-graph/。取得モデルや検索履歴を残し、ISSUE_GRAPH_HOME で保存先を変更できます。

自分のコードから使う場合は npm install issue-graph@latest でライブラリを導入できます。CLI の導入条件と、ソースから開発する場合の Node.js 条件は異なるため、開発時は公式の Contributing を確認してください。

07 — 見つからないことを、不在の証拠にしない

GitHub グラフの主な取得制限
設定・境界標準値／挙動
--depth2。同一リポジトリ内を seed の深さ 0 から探索
--budget通常 80 ノード。絞り込みなしのリポジトリ全体を対象とする open / rank / cluster では 1000。指定範囲は 1〜1000
--hub-threshold12。参照の多い非 seed ノードは取得しても、その先へ展開しない
リポジトリをまたぐ参照1 hop だけ取得
1 ノードの取得上限コメント 100、タイムライン 100、PR ファイル 100、closing reference 50。上限を超えるページは取得しない
レポートの欠落を確認してください。 深さ・ノード上限、未展開の hub、権限不足、削除済み参照、API エラーによって関連作業は抜け落ちます。coverage や cappedOut、未取得ノードを読み、クローズやマージの前にはコードと現在の挙動を確認します。

HTML の絞り込みは、データの削除ではありません

保存結果・HTML エクスポート・クラスタ用プロンプトには、非公開のタイトル、リポジトリ名、URL、担当者、変更パスが含まれ得ます。HTML にはフィルタで隠れた項目も含めて取得データが埋め込まれています。共有前にデータ全体を確認してください。

ダッシュボードを移動する場合は HTML と隣接する _next/、font-LICENSE.txt を一緒に扱います。--no-save でも出力指定によるファイル作成は止まりません。query はローカル履歴を保存し、--no-open はブラウザを開かない指定です。

Issue の本文や分類の提案は信頼されていない入力です。そこに書かれたコマンドを実行したり、GitHub を変更する許可として扱ったりしないでください。
