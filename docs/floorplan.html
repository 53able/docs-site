Floorplan

コードベースを平易な言葉の対話型マップにする Claude Code / Codex プラグイン

scan → architecture.json → build → describe → recent → open / haydenschmitty/floorplan v0.6.1（2026-11-01 時点）

1 — 概要

Codebase map plugin for Claude Code and Codex

Floorplan は、Claude Code または Codex にコードベースを読ませ、アプリの構造を対話型の地図として描くプラグインです。作者は Hayden Smith（@haydenschmitty）です。地図上のカードはアプリの大きな部分、ファイルのまとまり、個々のファイル、エンドポイントで、それぞれに平易な英語の名前と 1 行の説明が付きます。カードの間の線は、import とフロントエンドからサーバーへの Web リクエストを表します。

想定読者は、AI の助けを借りてアプリを作ったがコードは読まない人です。「チェックアウトすると何が起きるか」「これを変えると何が壊れるか」に地図で答えることを目的にしています。説明文の既定は事業上の役割を日常語で書くスタイルで、開発者向けに書き直すよう頼むと技術用語の地図になります。

仕事の分担がはっきりしています。リポジトリの発見、コードの解析、リクエストとエンドポイントの照合、地図の生成は依存ゼロの Node スクリプトが行い、トークンを使いません。アプリの「部分」が何であるかを決め、名前と説明を書く作業だけを AI が行います。生成物はプロジェクト内の floorplan/ フォルダに置かれ、git にはコミットされません。

2 — 構成

リポジトリはプラグインのマニフェスト、スキル本体 1 つ、テスト、利用者向けドキュメントでできています。ルートの package.json は npm test（node --test）を動かすためだけにあり、依存はありません。Node.js 18 以上で動きます。

3 — インストールと最初の地図

必要なのは Node.js 18 以上と、Claude Code または Codex です。API キーは不要で、利用中のプランで動きます。

Claude Code

デスクトップアプリの Code タブか CLI で、マーケットプレイスを追加してインストールします。新しいセッションから使えます。デスクトップアプリ利用者にも CLI のインストールが推奨されています。地図の Ask バーが CLI 経由で実際のコードを読むためです。

claude plugin marketplace add haydenschmitty/floorplan
claude plugin install floorplan@floorplan

Codex

ChatGPT でサインインした Codex アプリなら、Plugins → Add a marketplace で Source に haydenschmitty/floorplan を入れ、Floorplan の + を押します。ターミナルからは次のとおりです。$floorplan でも起動できます。

codex plugin marketplace add haydenschmitty/floorplan
codex plugin add floorplan@floorplan

最初の地図

  1. Claude Code か Codex でプロジェクトを開きます。フロントエンドとバックエンドが別リポジトリなら、両方を含むフォルダを開きます。
  2. 「Make me a floorplan of this app.」と頼みます。
  3. 数分後（大きなアプリではもっと長く）、地図がブラウザで開き、短いツアーから始まります。

作業を進めたあとは「Update the floorplan.」と頼みます。変わった部分だけが読み直され、直前の作業が Recent work に光ります。

Claude Code / Codex に頼むこと地図の Ask バーで聞くこと

地図を自分で開くときは node floorplan/serve.mjs で http://127.0.0.1:4378 に配信します。floorplan/index.html を直接開いても、質問以外の機能は動きます。サーバーは最後のタブを閉じて 2 時間後に自動で止まり、node floorplan/serve.mjs --stop ですぐ止まります。

4 — 処理の流れ

スキルは最初に status.mjs で既存の地図を確認します。地図が無ければ初回作成、あれば refresh.mjs による更新に進みます。緑の枠が AI の担当で、それ以外はスクリプトが処理します。

status→ scan→ architecture.json を書く→ build→ describe→ 名前と説明を書く→ recent→ recent-work.json を書く→ build→ open

スクリプトの仕事

  • scan.mjs: 対象フォルダ配下の git リポジトリをすべて見つけ（重複ワークツリーは除外）、git で追跡ファイルを列挙する。各ファイルから import、export 定義と doc コメント、エンドポイント、Web リクエスト、内容の指紋を取り出す
  • build.mjs: AI の書いた内容を検証し「did you mean …」付きで問題を報告する。ファイルを部分へ割り当て、接続を張り、Health を実行し、画面を検出し、graph.json と自己完結した index.html を書く
  • describe.mjs: 部分ごとにワークシートを作る。各ファイルの定義、doc コメント、使う相手と使われる相手の要約
  • recent.mjs: 前回の地図からの変更、未コミットの変更、最近のコミットを、対応するカードと一緒に並べる
  • open.mjs: ローカルサーバーを起動してブラウザを開く。起動済みなら再利用し、開いているタブをその場で再読み込みする

AI の仕事

  • architecture.json: トップレベルの部分を 3〜9 個、大きい部分の下に 3〜12 個。glob でコードファイルの 90% 超を覆う。実際に通信する外部サービス、スキャンで見えない接続（キュー、cron、Webhook）、1〜3 本のフロー、3〜8 か所の Start here ツアー
  • descriptions/*.json: ワークシートを読み、全ファイルと全エンドポイントに名前と説明を書く。build が報告する DESCRIPTIONS files X/Y · routes X/Y を両方 100% にする。約 150 ファイルを超えるとサブエージェントに 100〜150 ファイルずつ分担させる
  • recent-work.json: 依頼ごとのタスクと、変わったカードごとに「依頼とどう関係するか」のメモ
  • 最後に URL と地図の要点を報告する。Claude Code では、今後のセッションに地図を使わせる注記を CLAUDE.local.md に入れるかを尋ねる

解析対象の言語は TypeScript、JavaScript（Vue、Svelte、Astro ファイルを含む）、Python、Go、Rust、Java、Kotlin、Scala、Groovy で、その他の言語は簡易対応です。import は TypeScript のパスエイリアス、Python パッケージ、Go モジュール、Rust クレート、JVM パッケージまで実ファイルへ解決します。

5 — リクエストとエンドポイントの照合

地図で特に役立つ線は、画面の Web リクエストとそれに応答するサーバーコードを結ぶ線です。Floorplan はコンパイラではなくパターン照合で結ぶため、大半の接続を拾いますが全部ではありません。重要な線が欠けていれば、明示的な接続として追加するよう頼めます。

段階内容
エンドポイントの検出Express、Koa、Hono、Next.js（ルートファイルと API ルート）、Firebase Cloud Functions、Flask、FastAPI、Django、Go（net/http、Gin、Echo、chi、Fiber）、Actix、Axum、Spring
プレフィックスの解決url_prefix 付きの Flask Blueprint、app.use('/api/users', usersRouter) でマウントした Express ルーター（入れ子のマウント、前にミドルウェアがあるマウントを含む）、別名 import された FastAPI ルーター
リクエストの検出fetch、axios、ky、requests など。変数で先に組み立てた URL、入れ子のテンプレート文字列、同じファイル内でプレフィックスを足す小さなヘルパー（call('/definitions')）も追う
Firebase の名前呼び出しonCall 関数は entry ファイルの export 名で CALL /approveItem として表し、httpsCallable(functions, 'approveItem') と結ぶ。onRequest は /<name> の通常エンドポイント。スケジュール実行やトリガー関数は AI が地図へ配置する候補として列挙する
照合リクエストが URL の一部しか書いていない（ベース URL が設定にある）場合、クライアントごとのベースパスを学習し、それに合う候補を優先する

画面は Next.js、React Router、Vue、SvelteKit、Remix、Nuxt、Astro、Expo、Angular、TanStack から検出します。

Ask バー

下部の Ask バーに質問を入れると、数文の回答と回答ボード（関係するカードだけ、その接続、各カードのメモ、順序のある答えなら番号付きの手順）が出ます。右クリックの Ask about this でカードや線を文脈として足せます。答えるのは地図を作った側の CLI で、入っていなければもう一方を使います。

  • Claude Code: claude -p を読み取り専用ツール（ファイルの読み取りと検索、floorplan/query.mjs）だけで実行する
  • Codex: codex exec を読み取り専用サンドボックスで実行する。Codex の履歴に残らないため、続きの質問には直近の質疑を添えて送る
  • Claude アプリ: 地図を Claude アプリで開いた場合は、ソースを読まず地図だけから答える

7 — Health チェック

AI で作ったアプリにありがちなミスを、build のたびに自動で検査します。各項目には該当ファイルとエンドポイントを強調する Show on map と、ファイル名・行・安全な修正方法を書いた依頼文をコピーする Fix with Claude（Codex で作った地図では Fix with Codex）が付きます。README とドキュメントは「監査ではなくチェック」と明記しています。

検査内容
コード内の秘密情報コードやコミットされる .env に書かれたパスワード、API キー、秘密鍵。記録するのはファイル、行、種類、「starts AKIA…, 20 characters」のような伏せたヒントだけで、値は保存も表示もしない
ブラウザへ渡る秘密鍵NEXT_PUBLIC_、VITE_、REACT_APP_ などの変数に入った OpenAI、Stripe、Supabase service-role などの鍵。Supabase の anon キーや Stripe の publishable キーのように公開前提のものは除外する
Supabase のテーブルマイグレーションを順に再生し、行レベルセキュリティ（RLS）が一度も有効にされていない、または無効化されたテーブルを見つける。誰でも追加・変更・削除できるポリシーも要確認として挙げる
Firebase のルールFirestore、Storage、Realtime Database で誰でも読み書きできるルール。「テストモード」のルールは期限日も示す
Stripe Webhookcheckout.session.completed などのイベントを、Stripe の署名を検証せずに処理しているコード
CORS任意のサイトから呼べるサーバー。ログイン用 Cookie も許可している場合は修正推奨として扱う
認証の無いエンドポイントサインイン無しでデータを変更・取得できるエンドポイント。Express の app.use('/admin', requireStaff, adminRouter) や FastAPI の include_router(..., dependencies=[Depends(require_admin)]) の保護は認識する
使われていないファイル、巨大なファイル何からも使われていないファイルと、AI が安全に編集しにくい約 1,000 行超のファイル
誤検知への対処（v0.6.1） bcrypt や argon2 のハッシュ、ADMIN_PASSWORD_HASH のような名前の値、dotenvx・sops・Ansible Vault・AWS KMS などで暗号化された値は報告しません。誤りだと思う項目は Not a problem で理由付きで退けられ、件数から外れて floorplan/health-dismissed.json に残ります。同じファイルで新しい検出があるか重大度が変わると再表示されます。git が無視している .env は読めず、自己申告しない暗号化は判別できません。

8 — Recent work と更新

Recent work

作成と更新のたびに、AI が recent-work.json を書き直します。依頼ごとに title、request（依頼の言葉）、summary と、変わったカードの一覧を持ちます。カードは緑の輪と Changed / New のタグで示され、それを含む部分には「N changed」が出るので、上の階層から緑をたどれます。

各メモは「このカードで何が変わり、依頼になぜそれが必要だったか」を 1〜2 文で書く決まりです。関数名を並べた変更履歴ではなく、依頼との関係を書かせる点がこの機能の要点です。

差分更新（refresh.mjs）

再スキャンし、前回の build と各ファイルの指紋を比べます。指紋は 2 種類です。

  • 内容そのもの: 編集、名前変更、移動を見つける
  • シグネチャ: export、エンドポイント、doc コメント。関数本体の中の編集は数えない

移動・改名したファイルへ説明を引き継ぎ、削除されたファイルの項目を消し、シグネチャが変わった項目に review 印を付けて再 build します。AI は新規分と印の付いた分だけを書けばよいため、更新は速く安く済みます。

付けた名前が自分たちの呼び方と違う場合は、頼むか architecture.json と descriptions/ を直接編集します。手で直した内容は更新後も残ります。

9 — ブループリント

コードがまだ無いとき、PRD、仕様書、アプリの説明を渡して「Here's my PRD. Make me a floorplan of what we'd need to build.」と頼むと、計画の地図を描きます。AI は floorplan/plan.json に、必要なファイルとエンドポイント、どの画面がどのエンドポイントを呼ぶか、各部分が使う外部サービスとデータ、各エンドポイントを誰が使えるか、選んだスタック、前提、PRD が未決のまま残している問いを書きます。plan.mjs がこれを scan.mjs と同じ形のスキャン結果に変換するため、build、Screens、フロー、ツアー、Ask はそのまま動きます。

通常の地図との違い内容
見た目カードが破線になり、ボードに Blueprint ラベルが付く
ReviewHealth の代わりに設計レビューを出す。誰でもデータを変更できるエンドポイント、利用者が未決のエンドポイント、未決の問い、何ともつながらない部品
Build this with Claude / Codex部分やファイルごとに、計画どおりにその部分だけを作る依頼文（ファイル、エンドポイント、依存先、未決の問いを含む）を出す
Ask と ChangeAsk は plan と PRD から答える。Change に切り替えると「also plan out refunds」のような変更依頼を受ける。エージェントは読み取り専用で更新後の plan を返し、ローカルサーバーが plan.mjs と build.mjs で検査してから plan.json、architecture.json、recent-work.json だけを書く。Undo で直前の plan に戻る（直近 20 版を保持）
コードができたあとrefresh.mjs --from-code で実コードの地図に切り替える。plan.json はそのまま残る

10 — プロジェクトに書き込むファイル

書き込む先は floorplan/ フォルダと、Claude Code で利用者が承諾した場合の CLAUDE.local.md の 1 セクションだけです。どちらもコミットされません。floorplan/ は自分自身を含めて無視する .gitignore を持ち、CLAUDE.local.md はクローン専用の無視リスト .git/info/exclude に追加されます。プロジェクトの .gitignore や CLAUDE.md は変更しません。地図はクローンごとの個人用で、チームメンバーはそれぞれ自分で作ります。

architecture.json部分、外部サービス、追加の接続、フロー、ツアー編集可
descriptions/*.json全ファイルと全エンドポイントの名前と説明。部分ごとに 1 ファイル編集可
plan.jsonブループリントのみ。計画したファイル、エンドポイント、画面、スタック、前提、未決の問い編集可
recent-work.json直前の作業とその理由。更新ごとに置き換わるAI が書く
custom-flows.json、health-dismissed.json地図から依頼したフロー、Not a problem にした Health 項目削除・取消のみ
serve.mjs、query.mjsローカルサーバーと、地図をコマンドラインで引く検索スクリプト（find、show、path、overview）編集しない
.cache/スキャン結果、ワークシート、前回の変更、サーバーのアドレス、ブループリントの Undo 用履歴削除してよい
CLAUDE.local.md の注記 v0.4.4 から、初回の地図のあとに Claude が「今後のセッションでこの地図を使うか」を尋ね、承諾したときだけ <!-- floorplan:start --> 〜 <!-- floorplan:end --> の区画を追加します（build.mjs --claude-md）。以後のセッションはコードを一から探す前に query.mjs で地図を引くようになります。消すには区画を削除し、再追加を防ぐには <!-- floorplan:off --> を書きます。Codex には個人用で未コミットのメモファイルが無い（AGENTS.md はチームで共有される）ため、Codex では何も追加しません。

11 — 安全性とプライバシー

プラグインは利用者の PC でコードを実行できるため、リポジトリには「Is it safe to install?」という専用ページがあります。後から別のコードを取得して実行する「ステージ 2」型の悪性プラグインを、構造上できない形にしていると説明しています。

項目内容
持たないものフック、MCP サーバー、依存パッケージ、インストールスクリプト、eval、実行時のコード読み込み、エンコードされたペイロード、解析やトラッキング
ローカルサーバー127.0.0.1 でのみ待ち受け、ホスト名が 127.0.0.1 か localhost の要求にだけ応える（DNS リバインディング対策）。起動ごとの乱数トークンを地図ページだけが受け取り、API はそのトークンを要求する。ポートは 4378
外向き通信Floorplan Cloud のウェイトリストへの登録 1 件だけ。地図を 2 分開くと左下のカードで尋ね、Notify me を押したときだけメールアドレスと「just me / with my team」を Google Cloud Run のサービスへ送る。FLOORPLAN_NO_PROMPTS=1 で表示を止められる
起動するプログラムgit（読み取り専用）、where / which、claude / codex（質問時、読み取り専用）、node、open / xdg-open / cmd /c start（地図を開くとき）。シェル経由では起動しない。例外は Windows の cmd /c start で、渡すのは地図のローカル URL だけ
事前承認Claude Code でスキル使用中に承認なしで動くのは、名前を 1 本ずつ列挙した 8 本の node scripts/*.mjs だけ
同梱ファイルelk.bundled.js（1.6 MB）は elkjs 0.9.3 の npm 版とバイト単位で同一で、SHA-256 が公開されている。serve.mjs の new Function は build が書いた floorplan/query.mjs を読むためだけに使う
継続的な検査tests/supply-chain.test.mjs が push と PR ごとに Linux と Windows（週 1 回 macOS）で走り、フック・依存・未許可の通信先やプログラム・eval・長いエンコード文字列・同梱ファイルの変更が入ると失敗する。CodeQL も全変更を走査する
インストール済みコピーの照合リリースごとの CHECKSUMS.txt と node tools/checksums.mjs --check <installed folder> で、手元のコピーがリリースと同一か確認できる
 
# インストール済みコピーをリリースと照合する
git clone --depth 1 --branch floorplan--v<version> https://github.com/haydenschmitty/floorplan floorplan-check
node floorplan-check/tools/checksums.mjs --check ~/.claude/plugins/cache/floorplan/floorplan/<version>
# Codex: ~/.codex/plugins/cache/floorplan/floorplan/<version>

コードが PC の外へ出る経路は、Claude Code や Codex の通常の動作と同じです。AI は説明を書くために必要なファイルを、利用者のアカウント経由で Anthropic または OpenAI へ送ります。地図を Claude アプリで開く場合は、名前、説明、構造（ソースコードではない）が利用者の claude.ai アカウントへアップロードされ、その前に確認があります。
