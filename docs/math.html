数学原稿と Lean 形式化

内部 OpenAI モデルが生成した数学原稿と、それを支える証明資料のコレクション。研究テーマから原稿を探し、対応する形式化の命題と検証設定まで辿るための構成を整理します。

01 — 概要と検証段階

原稿をファミリー単位で読む

ファミリーは主結果、補助的な議論、帰結、別証明などの関連原稿をまとめた単位です。分野別に分類され、カタログの番号は順位を表しません。

722数学原稿
372ファミリー
10推論要約の対象

既存の数学評価が飽和した後、モデル開発の一環として未解決の研究課題へ評価を広げたと README は説明しています。約 4,000 問の出力を整理し、重要性の基準を満たした結果がこの資料集に収録されています。

結果ごとに検証段階が異なります。すべての原稿に Lean 形式化が付いているわけではありません。README は未形式化の結果に問題があり得ると明記し、形式化カタログの review.status は unchecked です。本ページは資料の案内であり、数学的な正しさを独立に認定するものではありません。

出典: README · 形式化カタログ

02 — 資料を読む順序

STEP 01 / FAMILY

研究テーマを選ぶ

overview.pdf で分野別の概要を確認。数論、幾何、解析、計算機科学などから関心のあるファミリーを選びます。

STEP 02 / MANUSCRIPT

関連原稿を辿る

CONTENTS.md で個々の原稿と関連資料を探し、preprints/ の PDF と原稿別 README を開きます。

STEP 03 / STATEMENT

形式化の対応を調べる

formalization.yaml と lean/docs/ で命題の範囲を確認し、対応する Comparator 設定に進みます。

推論要約を併読する

reasoning_traces/ には、π の無理数度、乗法的関数の相関、自由群因子の同型など 10 ファミリーの短縮された推論要約があります。対象の一覧は README にあり、原稿・形式証明と併せて読む補助資料です。

04 — 形式化がカバーする命題

EXAMPLE / FAMILY 017

π の無理数度を題材に範囲を確認する

形式化範囲の説明は、π の無理数度が 2 である命題を対象にしています。ν > 2 に対し、十分大きい正の分母 q では、すべての整数 p について次の不等式を満たすと記載されています。

|π − p/q| ≥ q−ν

選択された命題

無理数度が 2 であることと、無限個の有理近似を用いた上限の特徴付け。照合用の命題は PiExponent.lean にあります。

この命題の範囲外

原稿が述べる Flint–Hills 級数の収束という帰結は、この選択された形式化命題の対象外です。

参照版では π の説明文書と Comparator 設定は存在しますが、formalization.yaml の main_results に PiExponent の項目はありません。カタログだけでなく個別の文書と設定も確認してください。

原稿の主張と Lean の宣言を対応させてください。原稿のタイトルだけで範囲を判断せず、対象命題、仮定、定義、許可する公理を読みます。形式化済みの部分から原稿全体の検証済み状態を推定しないことが大切です。

05 — Lean と Comparator の確認手順

Comparator README は comparator、landrun、lean4export をインストールして PATH に置くよう指定しています。対応する Lean 環境を用意し、取得したプロジェクトの lean/ 内から実行します。

公式 README の例 · lean/ 内で実行
lake update
lake exe cache get
lake env comparator ComparatorChallenges/QuasiRiemannHypothesis.json

対象の設定を選ぶ

上の例は QuasiRiemannHypothesis 用です。π の例なら ComparatorChallenges/PiExponent.json の設定を選びます。

その設定は OAI.PiExponent.main を指定し、許可する公理を propext、Quot.sound、Classical.choice に限定しています。enable_nanoda は false です。

小さい単位で確認する

Lean README はライブラリ全体を一度にコンパイルせず、小さい部分ごとにビルドすることを推奨しています。全体ビルドでは Linux の vm.max_map_count が不足すると失敗する場合があります。

回避策として Lean の CMake オプション -DMMAP=OFF、必要に応じた環境変数の設定を案内しています。

Lean README にある mmap 回避用環境変数
GLIBC_TUNABLES=glibc.malloc.mmap_max=0:glibc.malloc.arena_max=1

このページの作成では Lean 証明や Comparator を実行していません。上記はソースに記載された検証手順の案内です。
