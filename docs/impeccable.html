Impeccable

skill v4.8.0 · 24 commands · 62 detector rules — by Paul Bakaus

1 — 概要
What is Impeccable?

Impeccable は、コーディングエージェントにデザインの語彙を与えるスキル。polish や bolder で方向を指示し、critique と audit でレビューさせ、AI が作りがちな凡庸な UI（AI スロップ）を出荷前に検出する。Anthropic の frontend-design スキルを出発点にしている。

スキル本体に加えて、LLM を使わない決定的な検出器（62 ルール）、エージェントの編集ごとに検出器を走らせるデザインフック、ブラウザ上で代替案を試すライブモード、Chrome 拡張機能を持つ。どの機能も Rust で書かれた 1 つのエンジンバイナリで動く。

提供するもの内容
指示の語彙「目立たせて」のような曖昧な依頼の代わりに /impeccable bolder the pricing cards と書く。コマンドごとに専用の手順書（playbook）があり、1 つの対象に適用される。
レビューcritique はユーザビリティのヒューリスティクスで採点し、直す順を付ける。audit はアクセシビリティ、パフォーマンス、テーマ、レスポンシブを P0（ブロッカー）〜 P3（仕上げ）で報告する。
スロップ検出器62 の決定的ルール。上記の傾向に加え、詰まった padding や見出しレベルの飛ばしなど品質の問題も拾う。LLM も API キーも使わない。
得意な場面: README によると、Impeccable が最も効くのは既存のインターフェイス。ページやコンポーネントを指定して繰り返し改善する。新規ページも作れるが、より難しいモードとして別ガイド（Build something new）がある。最初は /impeccable critique the pricing cards のように 1 コンポーネントから始める。
2 — 使い方の流れ
init → document → コマンド + 対象

プロジェクトごとに 1 回 /impeccable init を実行する。コードを読み、推測できないこと（誰のためのプロダクトか、何をするか、制約）だけを質問して PRODUCT.md を書く。続けて /impeccable document で既存のビジュアルシステムを DESIGN.md に記録しておくと、以後の変更がブランドから外れにくい。後続のコマンドはすべてこの 2 ファイルを読む。

3 — スキル構成
SKILL.md の Setup

スキル本体（skill/SKILL.src.md）は短く、作業前に次の 3 手順を課す。

  1. セッションごとに 1 回 impeccable context を実行する。PRODUCT.md、DESIGN.md、対象画面のサーフェスブリーフ、必要ならネイティブ（iOS / Android）向けガイドを読み込み、指示を返す。
  2. 依頼に対応する手順書を読む。コマンド指定があればそのリファレンス、新しい画面やビジュアルの作り直しなら reference/new-work.md。編集前に既存の見た目を確認する。
  3. UI を編集する直前に reference/craft-floor.md を読む。品質の下限、禁止事項、検出器が拾えない癖をまとめたファイル。計画だけの作業では読まない。

ランチャーが動かない場合は、その旨をユーザーに伝えてから PRODUCT.md と DESIGN.md を直接読み、手順 2〜3 を続ける。

4 つのモード

モードは「その画面で訪問者が何を達成すれば成功か」で決める。プロダクト単位ではなく画面単位で選ぶ。ツールのランディングページは Persuade、ファッションブランドのドキュメントは Read になる。

モード訪問者の成功例方針
Persuade判断して行動するランディング、キャンペーン、料金注目と行動を勝ち取る。必要なら実画像を使う
Operateタスクを終えるアプリ UI、ダッシュボード、設定一覧性、一貫性、慣れた操作を表現より優先する
Read理解するドキュメント、記事、ヘルプ理解のための構造を先に作り、読み続けたくなる体験にする
Experience作品の中に入るポートフォリオ、ギャラリー最初の画面から作品を主役にし、UI は引く
デザインの原則（抜粋）
  • ブリーフが優先: 指定された時代感、素材、フォント、配色は、よくあるパターンへの警告と衝突しても守る。
  • 改善は保ち、作り直しは置き換える: 改善では既存のアイデンティティ、挙動、コピーを残す。作り直しでは古い見た目を参考資料として扱い、新しい世界観を選んで DESIGN.md を書き換える。中途半端に旧デザインを磨くことはしない。
  • DESIGN.md がないことは白紙を意味しない: コードに一貫したアイデンティティがあれば、それを記録して引き継ぐ。
  • ずれの修復を勝手にしない: 古くなった文脈ファイル（CONTEXT_STALE）は報告するだけで、ユーザーが頼まない限りデザイン作業のついでに直さない。

5 — 検出器
3 つの実行場所
場所動き対応
エージェント内（デザインフック）エージェントが UI ファイルを編集するたびに検出器を走らせ、完了報告の前に指摘を返す。README はここで大半のスロップが捕まると書く。インストーラーが設定するClaude Code、Cursor、Codex、GitHub Copilot、Grok Build、Hermes Agent
CI・ターミナルnpx impeccable detect。エージェント不要任意
ブラウザChrome 拡張機能が、自分や他人の公開ページに同じ指摘を重ねて表示するChrome
フックの 2 段構成

対象拡張子は .tsx .jsx .html .vue .svelte .astro .css .scss .sass .less .ts .js。ルールは 2 段に分かれる。

  • 編集ごと（即時）: 壊れた画像、はみ出し、コントラスト不足、グラデーション文字、グロー影、デザインシステムからのずれなど、機械的で曖昧さのない問題だけを返す。
  • Stop 時（まとめて）: セッションで触った UI ファイル全体に全ルールを走らせ、残りの指摘（コピーのリズム、配色や書体の好み、レイアウトのリズム）を重複を除いて 1 回だけ返す。Claude Code、Codex、Grok Build、Hermes Agent が対象。Cursor と GitHub Copilot は Stop で文脈を返せないため、編集ごとに全ルールを走らせる。

指摘は 3 つに仕分ける。本当の問題なら直す。根拠を示せる誤検知や合意済みの例外なら、最も狭い範囲で ignore を登録し、--reason に「誰が決めたか: 根拠」を書く。判断できなければ 1 行でユーザーに聞く。修正を避けるために ignore を使ってはいけない。

CLI 
npx impeccable detect src/                   # ディレクトリを走査
npx impeccable detect https://example.com    # 描画済みページを走査（手元の Chrome / Edge を使う）
npx impeccable detect --json .               # 機械可読な出力
npx impeccable detect --github src/          # GitHub Actions の注釈形式
npx impeccable detect --list-rules           # 全ルールの id と説明

JSX や TSX などのソースファイルにはパターン系のルールだけが効く。低コントラストや小さすぎる文字など、描画結果が必要なルールは URL を走査したときに動く。開発サーバー（例: npx impeccable detect http://localhost:5173）にも向ける。

終了コード意味
2指摘あり
1対象を走査できなかった
例外の登録 
# ブランドフォントをプロジェクト全体で許可する
npx impeccable ignores add-value overused-font Inter --reason "Brand font"

<!-- 1 ファイルだけルールを止める -->

共有する例外は .impeccable/config.json の detector に入り、個人の例外は Git 管理外の .impeccable/config.local.json に入る。Blade、Twig、ERB、Handlebars のテンプレートは detector.extensions に拡張子を宣言すると走査対象になる。

6 — ライブモード
ブラウザで代替案を試す

/impeccable live は起動中の開発サーバーにオーバーレイを重ねる。要素を選んで方向を選ぶと、Impeccable が代替案をその場で差し替える。採用した案はソースに書き戻される。generate は要素を名前で指定して代替案を作る版。

  1. ブラウザで要素を選ぶ（スクリーンショットがあれば読む）。
  2. 要素のアイデンティティを抽出し、既定の方向か大きく外す方向かを決める。
  3. 3 つの代替案を作り、パラメーターで細かく調整できるようにする。
  4. 採用（accept）した案をソースへ反映する。破棄（discard）や追加の指示（steer）もできる。

対応: Vite、Next、SvelteKit、Astro、Nuxt、プレーン HTML。要素の削除を編集として積む Remove バッジもある。

安全上の注意: ライブモードはローカルのチェックアウトだけを編集する。デプロイ済みサイトに注入したり、動かすために本番の CSP を緩めたりしない。コピー修正を反映するとき、package.json の任意スクリプト impeccable:manual-edit-validate が自分の権限で実行される。見知らぬリポジトリで使う前に中身を確認する。
7 — エンジン
1 つの Rust バイナリ

スキルが実行するコマンドはすべて impeccable <verb>。スキル横のランチャーがプラットフォーム別の静的バイナリを探すか、初回に ~/.impeccable/bin/ へ一度だけダウンロードして実行する。実行時に Node は不要。npm の impeccable も同じバイナリを動かす薄いシムで、検出器専用の別バイナリはない。

liveライブモードのサーバー、差し替え、accept、手動編集、Svelte / Vue 対応
skillsinstall / update / check / link
detectimpeccable detect。ファイル走査、設定、ignore、出力

core / foundationルールの本体と、ルール登録・色・指摘などの共通型
wasm同じルールを拡張機能、ライブオーバーレイ、サイト向けに WebAssembly 化する
comp / comp-verbsカンプ（完成見本画像）と実装の一致度を測る
1 つのソースから各ツール向けに生成

スキルのソースは skill/ に 1 つだけある。bun run build:release が各ツール用のフォルダ（.claude/、.cursor/、.agents/ など）と plugin/ を生成する。これらは生成物だが、GitHub から直接、npx skills、サブモジュールで入れる利用者のためにリポジトリに含めている。

8 — インストール
推奨: インストーラー 
npx impeccable install   # プロジェクトルートで実行
npx impeccable update    # 既存のインストールを更新

インストーラーは使っているツールを検出し、プロジェクト単位かグローバルかを聞き、対応ツールではデザインフックを提案する。README はフックを受け入れるよう勧めている。終わったらツールを再読み込みし、/impeccable init（Codex では $impeccable init）を実行する。スクリプトからは --providers=claude,codex,cursor と --scope=project|global を渡す。

追加の許可が必要なツール: Codex は /hooks でプロジェクトのフックを承認する（フックが変わる更新の後も再承認）。Grok Build は /hooks-trust を実行するか --trust で起動する。Hermes Agent はフックがプラグインなので hermes plugins enable impeccable-design-hook を一度実行する。

ビルドパス

新しいランディングページやショーケースでは、先に完成度の高いカンプ画像を生成してそれに合わせて作るか（より大胆、より遅い）、直接コードで作るか（より軽い、より速い）を選べる。アプリ画面とドキュメントは常にコードで作る。init が一度だけ聞き、.impeccable/config.json の buildPath に保存する。選択肢は、使っているツールが画像を生成できる場合にだけ出る。

フックはモデルの承認と無関係に動く: Claude Code では、モデルのコマンドを拒否してもインストール済みのコマンドフックは実行される。最初の編集でエンジンがダウンロードされることがある。無人で動かす前にフックを確認するか、--settings '{"disableAllHooks": true}' でその実行だけフックを止める。
テレメトリー: 新しいデザインを始めるとき、スキルは impeccable.style のカタログからビジュアルの方向性候補を取得する。テレメトリーを切ってもこの取得は止まらない。止まるのは「どの候補が表示され、どれを選んだか」の匿名記録。プロジェクト名、ファイル、コード、PRODUCT.md は送られない。無効化は npx impeccable telemetry off、DO_NOT_TRACK=1、または .impeccable/config.json に "telemetry": false。
壊れたとき: /impeccable doctor が古い文脈ファイル、使われていない設定、壊れたフックを見つける。
