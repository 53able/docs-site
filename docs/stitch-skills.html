01 — Google Stitch をエージェントから操作するスキル集

CODE ⇄ STITCH

既存のコードを Stitch に取り込み、
Stitch のデザインをコードに戻す。

stitch-skills は、Google のデザイン生成ツール Stitch をコーディングエージェントから使うためのスキル集です。Agent Skills の形式（SKILL.md + scripts/ / resources/ / examples/）で書かれ、Codex、Antigravity、Gemini CLI、Claude Code、Cursor、OpenCode（手動導入）で使えます。

ほぼすべてのスキルが Stitch MCP サーバーのツール（generate_screen_from_text、get_screen、create_design_system_from_design_md など）を呼び出します。README には「Google の公式サポート製品ではない」と明記されています。

02 — コードと Stitch の往復

スキルは単体でも使えますが、いくつかは他のスキルを順に呼び出す前提で書かれています。代表的な 2 方向の流れは次の通りです。

コード → Stitch（stitch::code-to-design）

extract-static-html→ extract-design-md→ manage-design-system→ upload-to-stitch

起動中の開発サーバー（または index.html を含むビルド成果物）から 1 ファイルの静的 HTML を取り出し、ソースコードから .stitch/DESIGN.md を抽出します。DESIGN.md をアップロードして Stitch のデザインシステムを作成し、最後に HTML を画面としてアップロードします。

Stitch → コード（stitch::react-components など）

get_screen（全画面）→ HTML / PNG 取得→ tailwind.config からトークン抽出→ コンポーネント分割→ validate.js

Stitch の HTML は Tailwind ベースです。<head> 内の tailwind.config から色・フォント・角丸を style-guide.json に同期し、それを使ってコンポーネントを書きます。同じスキルで「Stitch 側の更新に既存アプリを追従させる」同期にも使えます。

DESIGN.md が両方向をつなぎます。 コードから抽出した DESIGN.md は Stitch のデザインシステムになり、Stitch から作った DESIGN.md は次の画面生成プロンプトや React 化のトークンに使われます。

03 — 導入

  1. Stitch MCP を設定する

    全スキル共通の前提です。Stitch MCP Setup に従ってサーバーを登録し、認証情報を設定します。

  2. プラグインを入れる（推奨）

    # Claude Code（現在のプロジェクトへ）
npx plugins add google-labs-code/stitch-skills --scope project --target claude-code

# Cursor（現在のワークスペースへ）
npx plugins add google-labs-code/stitch-skills --scope workspace --target cursor

# Codex（マーケットプレイスを登録し、必要なプラグインを入れる）
codex plugin marketplace add google-labs-code/stitch-skills --ref main \
  --sparse .agents/plugins \
  --sparse plugins/stitch-design \
  --sparse plugins/stitch-build \
  --sparse plugins/stitch-utilities

    Codex の --sparse は取得範囲を絞るための任意指定です。マーケットプレイス定義は .agents/plugins/marketplace.json にあり、3 プラグインとも認証は ON_INSTALL です。

  3. スキル単位で入れる

    npx skills add google-labs-code/stitch-skills

    スキル間に依存があります。たとえば code-to-design は 4 つのスキルを順に呼ぶため、個別に入れる場合は依存先もまとめて入れてください。

  4. OpenCode は手動で配置する

    スキルのフォルダを .opencode/skills/（または .claude/skills/、.agents/skills/）にコピーし、opencode.json に Stitch MCP を remote として追加します。OpenCode はスキル名が小文字のケバブケースでディレクトリ名と一致する必要があるため、stitch::… という名前のスキルは name とフォルダ名を変更しないと読み込まれません。

04 — stitch-design：生成と取り込み

stitch-design プラグインのスキル
スキル内容
stitch::generate-designテキストから新規画面、画像・モックアップから画面、既存画面の編集、バリエーション生成の 4 フロー。生成前にプロンプトを補強し、deviceType（MOBILE / DESKTOP / TABLET）とデザインシステム ID を渡す
stitch::code-to-designフロントエンドのコードを Stitch デザインへ変換する統括スキル。上記 4 スキルを順に呼ぶ
stitch::extract-static-html動いているアプリから自己完結の HTML を作る。戦略 A は Puppeteer スナップショット、戦略 B はブラウザ操作サブエージェント
stitch::extract-design-mdReact / Vue / Svelte / Angular / 素の CSS のソースから DESIGN.md を逆算。フレームワーク別の参照資料を持つ
stitch::manage-design-systemDESIGN.md をアップロードして create_design_system_from_design_md を呼び、画面へテーマを適用する
stitch::upload-to-stitch画像（png / jpg / webp）、HTML、Markdown を Python スクリプトで HTTP 直送する

静的 HTML 抽出（戦略 A）

npx tsx <SKILL_DIR>/scripts/snapshot.ts \
  --url http://localhost:5173/dashboard \
  --output .stitch/dashboard.html \
  --wait 2000 --html-class dark --title /dashboard

ヘッドレス Chrome で描画済み DOM を取得し、CSSOM のルール、スタイルシート、画像（srcset を含む）、同一オリジンのアイコンフォントを base64 で埋め込みます。<script> や Vite の HMR 用ブロックは削除されます。認証が必要な画面は --auth-script、グラフの <canvas> は --inline-canvas で画像化します。

なぜアップロードにスクリプトを使うのか。 小さなファイルでも base64 にするとモデルの出力トークン上限（約 16K）を超えるため、MCP ツール経由ではアップロードできません。upload_to_stitch.py がファイルを読み、Stitch API へ直接送ります。

05 — stitch-build：デザインからコードへ

stitch-build プラグインのスキル
スキル内容
stitch::react-componentsStitch の画面を Vite + React のコンポーネント群に変換、または既存コンポーネントを最新デザインに同期。AST ベースの validate.js で検査
stitch::react-nativeStitch の HTML を StyleSheet を使う React Native コンポーネントに変換・同期
react-vite-dashboardReact + Vite のダッシュボード。TanStack Query、DESIGN.md 由来のトークン、ethers / viem による Web3 の読み取りパターン
remotionStitch プロジェクトの画面を Remotion で遷移・ズーム付きの紹介動画にする
shadcn-uishadcn/ui の導入・カスタマイズ・移行の手引き。Stitch には依存せず、shadcn の MCP を使う

react-components が強制する構成

分割

カード・バッジ・ページネーションなど再利用する UI は src/components/ へ。1 ファイルに全部入れたページは禁止。ロジックは src/hooks/ のカスタムフックへ。

データと型

文言・画像 URL・リストは src/data/mockData.ts に集約。すべてのコンポーネントに Readonly の [Name]Props を定義し、無いと検証が失敗する。

スタイル

style-guide.json に同期したテーマ付き Tailwind クラスだけを使い、16 進カラーの直書きは禁止。すべての色に dark: を付ける。

ナビゲーション

Stitch の画面は href="#" の仮リンクを持つ単独ページ。React Router の <Link> に置き換え、ロゴを / へのリンクにする。

CI（.github/workflows/validate-skills.yml）は React と React Native の両スキルで、同梱の examples/gold-standard-card.tsx を validate.js にかけます。

06 — stitch-utilities：仕様書とビルドループ

stitch-utilities プラグインのスキル
スキル内容
design-mdStitch プロジェクトの画面を読み、雰囲気・配色と役割・タイポグラフィ・コンポーネント・レイアウトを自然言語で記述した DESIGN.md を作る
taste-design「ありがちな AI デザイン」を避ける DESIGN.md を作る。密度・非対称性・動きを 1〜10 で調整し（既定値は Creativity 9 / Variance 8 / Motion 6 / Density 5）、禁止パターンを列挙する
enhance-prompt「設定ページを作って」のような曖昧な依頼を、UI/UX の語彙とデザインシステムを含む Stitch 向けプロンプトに書き換える
site-md要件の説明から .stitch/SITE.md（サイトの憲章）を作る。README の一覧には未掲載で、2026-08 に追加
stitch-loopバトン方式で 1 ページずつ生成・統合を繰り返し、複数ページのサイトを作る

stitch-loop の 1 周

  1. バトンを読む

    .stitch/next-prompt.md の frontmatter page が出力ファイル名、本文が生成プロンプトです。プロンプトには DESIGN.md のデザインシステムの記述を必ず含めます。

  2. 文脈を確認して生成する

    SITE.md のサイトマップで既存ページを確認し、generate_screen_from_text で画面を作って HTML と PNG を .stitch/designs/ に保存します。

  3. サイトへ統合する

    site/public/ に移し、アセットのパスと href="#" のナビゲーションを修正します。Chrome DevTools MCP があれば、スクリーンショットで Stitch の画像と見比べます。

  4. 次のバトンを書く

    SITE.md のサイトマップとロードマップを更新し、次のページの指示を next-prompt.md に書きます。これを書かないとループが止まります。

07 — プロジェクトに作られる .stitch/

スキル同士は、プロジェクト直下の .stitch/ を介して情報を受け渡します。

project/
├── .stitch/
│   ├── metadata.json   # Stitch のプロジェクト ID と画面ごとのメタデータ
│   ├── DESIGN.md       # デザインシステム（design-md / extract-design-md / taste-design）
│   ├── SITE.md         # サイトの目的・サイトマップ・ロードマップ（site-md）
│   ├── next-prompt.md  # stitch-loop のバトン
│   └── designs/        # Stitch から取得した {page}.html / {page}.png
└── site/public/        # stitch-loop が統合したページ

metadata.json は生成・編集・バリエーションのたびに get_project の結果で更新され、後の編集で同じ画面を指定するために使われます。

08 — 使う前に確認すること

運用上の注意
項目内容
API キーの扱いupload-to-stitch はエージェントの MCP 設定（Claude Code なら ~/.claude.json）から X-Goog-Api-Key を読み取り、スクリプトのコマンドライン引数で渡します。シェル履歴やプロセス一覧に残る点に注意してください
確認の停止点静的 HTML の抽出戦略の選択、開発サーバー起動後のスナップショット実行、アップロードの実行前に、ユーザーの承認を待つよう指示されています。React 化の検証スクリプトや開発サーバー起動も事前に確認を取ります
外部への送信アップロードした HTML は画像を base64 で埋め込んだ完全な画面です。認証付き画面を抽出した場合、表示されていた個人情報や社内データもそのまま Stitch に送られます
証明書エラーmacOS の Python で CERTIFICATE_VERIFY_FAILED が出る場合、スクリプトは certifi を試します。無ければ pip install certifi または SSL_CERT_FILE を指定
ツール名の差スキル本文は web_fetch / run_command などのツール名を前提にしています。OpenCode では webfetch / bash に読み替えます
サポートGoogle の公式サポート製品ではなく、Google OSS 脆弱性報奨プログラムの対象外です
