eve

vercel/eve — ファイルシステムを契約に durable なバックエンド AI エージェントへコンパイルする Vercel 製フレームワーク（eve 1.0.2 / main 2026-11-18 時点）

1 — 概要
何か

eve は、エージェントの能力を agent/ 配下の通常ファイル（Markdown・TypeScript）として記述し、モデルループ・セッション永続化・HTTP / 各種プラットフォーム配信までをフレームワークが担うfilesystem-first な durable エージェント基盤。npm パッケージ名・CLI バイナリ名はいずれも eve。2026-11-15 に 1.0.0 がリリースされ、安定 API はセマンティックバージョニングの対象になった。

1.0.2最新リリース（2026-11-17）
Node 24+実行要件（新規は 26.x 固定）
Workflow 5.xdurable 実行基盤
3runtime 依存（nitro / rolldown / undici）

設定オブジェクトを 1 か所に集約するのではなく、instructions・tools・skills・channels・memory など責務ごとにファイルの場所が決まっている。ファイルを置けば eve が発見し、名前はパスから導出される（agent/tools/get_weather.ts → get_weather）。別レジストリとの同期は不要。

設計上の分離: チャネル（ingress / delivery）、ハーネス（モデルループ）、ワークフロー実行は runtime 上で分離される。同じツールは Web Chat・ターミナル・Slack・A2A のどこから呼ばれても同じ挙動になる。
2 — 1.0 での主な変更
0.x から 1.0 へ

前回このページを書いた 2026-06 時点から約 2,500 コミットが入り、0.x 系を経て 1.0.0（2026-11-15）、1.0.1、1.0.2 が出ている。アップグレードは node_modules/eve/CHANGELOG.md と公式の Upgrade ガイド（agent files / channels / clients / saved history / session events）を版ごとに確認する。

安定性ポリシー

  • 安定 API の非互換変更はメジャーリリースのみ。deprecated な API は次のメジャーまで動く
  • eve/experimental/*・eve/internal/*、および defineAgent({ experimental }) などの experimental フィールドは互換保証なし
  • イベント union・出力値はマイナーで値が増え得るため、switch には default 分岐を残す
  • eve/channels/chat-sdk・linq・photon は Chat SDK v4 の型を契約に含む。chat の破壊的メジャーは eve のメジャーを伴う可能性がある

1.0.0 の破壊的変更（抜粋）

変更影響
agentWithModel → agent({ models })（eve/tools/agent）root-copy タスクが使えるモデルを列挙する形に置換
全エージェントに既定の edit_file ツールcode 拡張の code__apply_patch・code__grep・code__worker は削除。bash の結果形式と system prompt は pi に合わせた
同名の dynamic tool は static tool を上書きしないstatic 側が名前を保持し、eve はエラーを記録する
新規セッションは開始時にアドレスを claim同じチャネルアドレスへの競合した初回メッセージは 1 セッションに集約される

主な追加機能

  • A2A チャネル（eve/channels/a2a）: A2A v1.0 サーバーとして公開し、Agent Card から発見・JSON-RPC でタスク委譲
  • エージェント全体の承認ポリシー: agent.ts の approval で tool・connection・subagent の全呼び出しをゲート
  • ctx.conversation.space: Slack チャネル等「会話の場所」を表す ID。tool・承認・memory スコープで共有できる
  • eveVite()（eve/vite）: 任意の Vite アプリと並走（dev / preview / Vercel）
  • Vercel 上のスケジュールは Vercel Cron Jobs から Vercel Schedules に移行。固定スケジュールは IANA タイムゾーン指定可
  • 実験的: ユーザーが自分用・チャネル共有のスキルを保存できる custom-skills 拡張、実行時に作成する dynamic schedules
  • 起動・初回応答の高速化、AI Gateway 上の Anthropic モデルで system prompt を 1 時間キャッシュ、新規プロジェクトは Node.js 26 を対象
3 — プロジェクト構造
agent/ が契約

必須は instructions.md だけ。agent.ts を省くと openai/gpt-6-luna-fast（reasoning high）で動く。必要に応じて下位ディレクトリを増やす。

my-agent/
├── package.json
├── evals/                 # *.eval.ts（eve eval）
└── agent/
    ├── agent.ts           # 任意: モデル・承認・compaction 等（defineAgent）
    ├── instructions.md    # 必須: 常時オンな system prompt
    ├── tools/             # モデルが呼ぶ typed 関数
    ├── skills/            # 必要時だけ読み込む手順
    ├── channels/          # HTTP / Slack / A2A / MCP 等
    ├── connections/       # 外部 MCP / OpenAPI
    ├── memory/            # セッションをまたぐ記憶スロット
    ├── extensions/        # npm / workspace 拡張のマウント
    ├── hooks/             # ライフサイクル・ストリーム購読
    ├── sandbox/           # サンドボックス環境の定義
    ├── subagents/         # 委譲先（ローカル / リモート）
    ├── schedules/         # cron 等の定期実行
    └── lib/               # エージェント専用の共有コード

規模に応じた構成

必要なもの構成
エージェント 1 つ（ブラウザアプリの有無を問わず）アプリコードの横に agent/
委譲先の専門エージェントagent/subagents/<name>/（独自の prompt・tool・sandbox、チャネルなし）
個別にアドレスできる複数エージェント（同一パッケージ・同一デプロイ）エージェントワークスペース agents/<name>/agent/
依存・バージョン・リリースを分けたい別パッケージ / 別プロジェクト（共有は拡張、委譲は remote agent）

ワークスペースは npx eve@latest init operations --agents support,research で作り、eve dev --agent support のように対象を選ぶ。ルートに agent/ が残っていると単一エージェント扱いになる点に注意。

4 — 実行モデル
session / turn / step
  • session: 会話・タスク全体。日〜週単位でリクエストをまたぎ、再起動・再デプロイ後も継続
  • turn: 1 つのユーザーメッセージと、それが引き起こす model / tool 呼び出し全体
  • step: turn 内の保存チェックポイント。既定は model 呼び出し 1 回とそれに続く inline tool 呼び出し

各セッションは Workflow SDK 上の 1 ワークフローとして動く（Vercel では Vercel Workflow、ローカルと eve start は .eve/.workflow-data の local world）。

flowchart LR
  In["プラットフォーム入力
HTTP / TUI / Slack / A2A …"]
  Norm["チャネル
正規化 · session 対応付け"]
  Ctx["コンテキスト組立
instructions · skills · tools · memory · history"]
  Loop["モデルループ
tool / subagent / task"]
  Persist["step チェックポイント
stream events"]
  Out["配信
プラットフォーム形式"]

  In --> Norm --> Ctx --> Loop --> Persist --> Out
  Loop -.->|"承認 / 質問 / サインイン待ち"| Persist

長期セッションを支える仕組み

仕組み挙動
HITL 待機承認・質問で turn は turn.paused のまま停止。待機は再起動を越えて数日続けられ、回答到着で再開
デプロイ間の移動Vercel の production が変わると、アイドルなセッションは次の配信で新デプロイへ移る。実行中 turn・未回答の承認・稼働中タスクがある間は移らない
Compaction会話がコンテキスト窓の compaction.threshold（既定 0.9）に達すると古い turn を要約。その後セッションを新しいワークフロー run へ移し、run 履歴を有界に保つ
タスクagent 呼び出しや workflow tool はレシートを即返し、結果は後で task.result として届く。タスク稼働中は turn が終わらない
stranded セッション新しい eve が読めない古いセッションは 409 session_stranded。記録の読み出しは可能で、end() 後に新セッションを作る

動的設定

model・tools・skills・connections・subagents・instructions は defineDynamic でセッションごとに切り替えられる。動的関数は毎回のモデル呼び出し前に実行されるため、ネットワーク・DB・サンドボックス読み出しは ctx.memo の中に入れる。

memory provider

同梱の fileMemory()（Vercel Blob 版あり）のほか、Supermemory・Upstash AgentKit・Kybernesis Arcana・memco・claude-mem、独自 provider を選べる。scope は byPrincipal などで「誰と共有するか」を決める。

バンドル docs: eve パッケージに公式ドキュメント全文が同梱される（node_modules/eve/docs/）。インストール版と一致するため、コーディングエージェントはこちらを正とする。
6 — ツールと承認
既定ツールと HITL
区分ツール
既定（import 不要）bash・read_file・write_file・edit_file・web_fetch・web_search・agent、カタログ用 eve__search / eve__tool / eve__skill、タスク用 eve__task_wait / eve__task_cancel
オプトインask_question・glob・grep・no_reply・sleep

既定ツールは同名ファイル（例: agent/tools/bash.ts）で置き換え、defaultTools: false で一括無効化できる。bash は既定 60 秒、モデル指定の timeout で最大 120 秒待ち、それ以上はバックグラウンドで実行を続けて /tmp/.eve/jobs/ に出力を残す。

承認ポリシー

import { defineAgent } from "eve";

export default defineAgent({
  model: "anthropic/claude-opus-5.5",
  approval: ({ toolName, toolAnnotations }) => {
    if (toolName.startsWith("billing__")) return "user-approval";
    if (toolAnnotations?.destructiveHint === true) return "user-approval";
    return undefined; // ツール側の判断に任せる
  },
});
  • エージェント全体のポリシーとツール個別の approval は厳しい方が採用される（deny > user-approval > approve）。全体ポリシーはゲートを追加できるが外せない
  • eve/tools/approval の always()・once()・never()・auto() を使う。auto() は decision model（既定 typesafe-ai/jev）が clear / caution を判定し、caution なら人間に回す
  • 承認後の実行は依頼者の identity・認証情報で走り、承認者の権限は使わない
注意: approval を省略したツールは never() 扱いで、承認なしに実行される。課金・送信・破壊的操作など副作用のあるツールは明示的にゲートを付け、非冪等な処理には別途冪等キーを持たせる（承認は「ちょうど 1 回実行」を保証しない）。
7 — クイックスタート
新規 scaffold
Step 1
scaffold
npx eve@latest init my-agent で依存関係・Git・対話 TUI を起動。既存 repo なら npx eve@latest init .。--model / --reasoning で初期モデルを指定できる。
Step 2
認証
ChatGPT サブスクリプション、Vercel アカウント、AI Gateway / OpenAI / Anthropic の API キーのいずれか。未設定なら TUI が /login を開く。Vercel プロジェクトは不要。
Step 3
instructions と tool
agent/instructions.md に system prompt、agent/tools/*.ts に defineTool + Zod（または任意の Standard Schema / JSON Schema）。
Step 4
起動・追加・デプロイ
npx eve dev で TUI。/model でモデル切替、/add でチャネル追加、/deploy で Vercel へ。
import { defineTool } from "eve/tools";
import { z } from "zod";

export default defineTool({
  description: "Return mock weather data for a city.",
  inputSchema: z.object({ city: z.string().min(1) }),
  async execute({ city }) {
    return { city, condition: "Sunny", temperatureF: 72 };
  },
});

モデル ID 文字列は Vercel AI Gateway 経由になる。直接接続は eve/models/openai の openai() / chatgpt()、eve/models/anthropic の anthropic()（既定 claude-sonnet-5）を使う。静的なモデル変更は eve set model <id> でも可能。

Web Chat を足す

npx eve link
npx eve add channel/web   # Next.js か TanStack Start を apps/web に生成
npx eve deploy

ホスティングは「Vercel services（推奨、Web Chat とエージェントを別サービス化）」か「フレームワークがエージェントをホスト」を選ぶ。Sign in with Vercel でチームメンバー向け認証が付く。既存アプリには useEveAgent（React / Vue / Svelte）と Next.js・Nuxt・SvelteKit・TanStack Start・Vite の統合を使う。

8 — チャネル・プロトコル
入口アダプタ

チャネルはプラットフォーム入力をエージェント入力に変換し、会話を eve セッションへ対応付け、返信の配信方法を決める。ファイルは agent/channels/<id>.ts。eve add channel/<name> で導入できる。

用途チャネル
Web UI / curl / TypeScript clienteve HTTP（既定で有効）、Web Chat
チャットSlack・Discord・Microsoft Teams・Telegram・Chat SDK アダプタ
SMS / iMessage / 音声Twilio・Linq・Photon
開発ツールGitHub（@mention / PR）・Linear（delegation）
エージェント間A2A（A2A v1.0 サーバー）・MCP（agent_start 等 4 ツールで長時間タスクを委譲、tool / skill の公開も可）
ビデオ会議Recall.ai（実験的。Zoom / Meet / Teams に bot 参加）
独自 Webhook 等custom channel
  • サインイン: 接続の認可リンクは資格情報として扱われ、グループでは本人だけに見える経路（Slack のエフェメラル等）で送る。送れないプラットフォームでは DM への移動を促す
  • audience（public / private / unknown）はトレースに何を残すかを制御する。誰が呼べるかはルート認証で決める

プロトコル

プロトコルeve での扱い
ACP（Agent Client Protocol）eve acp がエディタ等から stdio で起動される。--url でデプロイ済みエージェントへ接続
UCP（Universal Commerce Protocol）/.well-known/ucp のプロファイルをチャネルから配信し、コマースエンドポイントを追加

9 — セキュリティと運用
信頼境界
App runtimeSandbox
process.env / シークレットありなし
自分の Node.js コード（tools 等）実行される実行されない
ネットワーク制限なしポリシーで制御
ファイルシステムアプリ自身隔離された /workspace

ツールは app runtime で動き、bash などモデルが操るコマンドは sandbox で動く。サンドボックス provider は Default（Vercel 上は Vercel Sandbox、Docker があれば Docker、開発時は just-bash）・Vercel・Docker・just-bash（プロセス隔離なし）から選ぶ。アイドル時は自動停止し、使わない turn では起こさない。

同梱拡張

  • eve/extensions/code: コーディングエージェント化（1.0 で prompt を約 1/3 に縮小）
  • eve/extensions/git: gh 付きサンドボックスと GitHub App のスコープ付きトークン
  • eve/extensions/computer-use、self-modification（local / remote）、eve add extension/agent-browser など
