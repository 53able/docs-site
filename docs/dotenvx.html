SOURCE GUIDE / DOTENVX

dotenvx

.env の値を読み込み、必要なら復号して、コマンドや Node.js のプロセスへ渡す。暗号化した .env は Git に入れ、秘密鍵だけを別に持つ。

1 — 何を担うか

ENV FILE → PROCESS ENV

dotenvx は、.env の変数をアプリに渡す CLI と Node.js ライブラリ。dotenv の作者が開発している。README は「Encrypt → Commit → Ship」の 3 段階で使い方を示す。値を暗号化した .env はコードと一緒にコミットし、復号用の秘密鍵は実行環境に別途置く。

2 — run の実行フロー

01 / SELECT

.env を選ぶ

-f、--convention、または既定の .env を解決する。

02 / DECRYPT

値を読む

ファイルを解析し、encrypted: の値を保管先から見つけた秘密鍵で復号する。

03 / CHECK

規則で検証

カレントに Dotenvxfile があれば、最終的な値を規則と照合する。

04 / EXECUTE

子コマンドを実行

-- より後のコマンドに変数を渡す。伏せ字対象の値は出力から隠す。

echo 'HELLO=World' > .env
dotenvx run -- node index.js
# ⟐ injected env (1) from .env
エラーの扱い: 読み込み・検証のエラーは既定ではログに出して実行を続ける。--strict を付けるか、Dotenvxfile で strict true とした規則に違反した場合は、子コマンドを起動せずに終了する。

根拠: README.md「Run Anywhere」、src/cli/actions/run.js、src/lib/resolvers/envs.js

3 — 複数環境の読み込み順

-f でファイルを指定する。複数ファイルはカンマ区切りで並べる。既定では、先に読んだファイルと既存の環境変数が優先される。--overload を付けると、後から読んだ値で上書きする。

指定読み込み結果用途
-f .env.production指定したファイルを読む環境を明示する
-f .env.local,.env先の .env.local が優先ローカル設定を共通設定に重ねる
-f .env.local,.env --overload後の .env が上書き上書き順を切り替える
-f ../..ディレクトリ内の .env を読む。--convention の基準ディレクトリにもなるモノレポでルートの .env を共有する
--convention=nextjs / flowNext.js または dotenv-flow の順序で .env.<環境>.local などを探すフレームワークの慣習に合わせる

秘密鍵の変数名からも読み込むファイルが決まる。DOTENV_PRIVATE_KEY_PRODUCTION があれば .env.production、DOTENV_PRIVATE_KEY があれば .env を読む。

根拠: README.md「Multiple Environments」「Encryption」、src/lib/helpers/envResolution/determine.js

4 — 暗号化と鍵の保管先

REPOSITORY

暗号化した .env

dotenvx encrypt は値ごとに encrypted: 付きの暗号文へ変換し、公開鍵 DOTENV_PUBLIC_KEY* をファイルに書く。この状態でコミットする。

RUNTIME

復号用の秘密鍵

秘密鍵は下表のいずれかに保管する。CI などでは環境変数 DOTENV_PRIVATE_KEY* で渡す。run は実行時に復号する。

暗号方式は secp256k1 の ECIES。値ごとに使い捨ての AES-256 鍵で暗号化し、その鍵を公開鍵で包む。同じ値を暗号化しても毎回異なる暗号文になる。

保管先内容
File（.env.keys）リポジトリ内のファイルに書く。CI や非対話端末ではこれが既定
OS のシークレットストアmacOS Keychain / Windows Credential Manager / Linux Secret Service。同じマシンの別ワークスペースからも見つかる
1Password / Bitwarden各 CLI（op / bw）が必要。DOTENVX_NO_1PASSWORD などで無効化できる
Dotenvx Armordotenvx のマネージドサービス。ログインが必要。秘密鍵をリモート側に置いたままにする Enclaved 鍵もある
 
dotenvx encrypt -f .env.production
DOTENV_PRIVATE_KEY_PRODUCTION="<private key>" dotenvx run -- node index.js

# 別の場所で作った公開鍵で暗号化する（秘密鍵は生成も保存もしない）
dotenvx encrypt -f .env.production --with <public-key>

対話端末では、encrypt で新しい鍵を作るときに保管先を選ぶ。保管先は後から dotenvx transfer未リリース で移せる（対話端末のみ）。

鍵の扱い: 既定の .env.keys は暗号化した .env と同じディレクトリにできる。コミットすると暗号化の意味がなくなるので、次節の protect か .gitignore で除外する。v2.34.0 でパスワード付きの lock 系コマンドは削除された。

根拠: README.md「Usage」「Encryption」「FAQ」、src/lib/helpers/selectKeyStorage.js、src/lib/custodians/index.js、src/cli/actions/transfer.js

5 — Dotenvxfile で検証・保存形式・伏せ字を決める 未リリース

カレントディレクトリの Dotenvxfile に、変数ごとの規則を書く。同じファイルから 2 種類のポリシーが作られる。実行時の最終値に対する検証・伏せ字（policy）と、ファイルに保存された文字列に対する保存形式の検証（storagepolicy）。

# Dotenvxfile
strict true
redacted true
storage "encrypted"
env "PORT", storage: "plaintext", redacted: false
env "DATABASE_URL", required: true
規則効果効く場面
required: true最終値にキーがなければ INVALID_ENVrun、config() の読み込み時
strict true違反をエラー終了にする（既定は警告）同上
redacted対象の値を出力で [REDACTED] に置き換える。ルートに書くと宣言していないキーにも効くrun の子コマンド出力、config() 後の stdout / stderr
storage "encrypted" / "plaintext"保存された文字列が暗号文か平文かを検査し、違反は INVALID_STORAGEencrypt、set、protect

上の例では PORT だけ平文での保存を許し、表示もそのまま。それ以外のキーは暗号化必須で、出力では伏せ字になる。DATABASE_URL がなければ run は子コマンドを起動しない。

echo 'redacted true' > Dotenvxfile
dotenvx run -- claude -p 'Run `dotenvx get HELLO` and echo back just Hello VALUE'
# Hello [REDACTED]
伏せ字の限界: 伏せ字は値の文字列一致で置き換える。base64 化や一部だけの切り出しなど、元の値と一致しない形に加工された出力は隠れない。README は Claude Code、Codex、Cursor などのエージェントに本物の値を渡しつつ出力を伏せる例を載せているが、エージェント自身は値を読める。ログやトランスクリプトに残る前提で扱う。

根拠: CHANGELOG.md「Unreleased」、README.md「Run Anywhere」、src/lib/resolvers/envs.js、src/lib/helpers/readStoragePolicy.js、@dotenvx/primitives README（policy / storagepolicy）

6 — protect で平文と鍵のコミットを止める

dotenvx protect は Git の clean フィルターを登録し、ステージ時に .env* を検査する。平文の値が残っていれば PLAINTEXT_ENV、.env.keys* をステージしようとすれば PRIVATE_KEY_FILE で失敗する。Dotenvxfile の storage "plaintext" で許可したキーは平文でも通る。.env.example と .env.vault は対象外。

dotenvx protect
# ⛉ protection: full (.env*, .env.keys*)

git add .env
# [PLAINTEXT_ENV] ".env" contains plaintext secrets. fix: run [dotenvx encrypt -f .env]

dotenvx protect --docker   # .env が保存ポリシーを満たすか .dockerignore 済みかを検査
影響範囲: フィルターは git config --global（core.attributesFile と filter.dotenvx.*）に書かれ、そのマシンの全リポジトリに効く。filter.dotenvx.required=true なので、登録したパスの dotenvx を削除・移動すると .env* を扱う Git 操作が失敗する。旧 precommit フックは自動で外される。

根拠: src/cli/actions/protect.js、src/cli/actions/protectStdin.js、src/lib/helpers/installProtectFilter.js

7 — CLI と Node.js から使う

CLI

run は言語を問わず子プロセスへ変数を渡す。get / set / del で個別の値を読み書きし、set は既定で暗号化して書く。encrypt / decrypt でファイル全体を変換する。

Node.js API

require('@dotenvx/dotenvx').config() でプロセス環境へ読み込む。ESM では import '@dotenvx/dotenvx/config' または import { config } from '@dotenvx/dotenvx'。v2.38.0 で getSync が追加された。

// Node.js のエントリポイント
require('@dotenvx/dotenvx').config()
console.log(process.env.HELLO)

インストールは npm のほか、curl、Homebrew、Docker、GitHub Releases、winget に対応する。グローバルに入れると Node.js 以外のプロジェクトでも run を使える。

根拠: README.md「Quickstart」「Advanced」、src/cli/dotenvx.js、src/lib/main.js

8 — v2.30.0 以降の主な変更

バージョン変更
未リリース（main）Envfile を Dotenvxfile に置き換え。--profile、spec、単独の check を削除し、検証は読み込み時に自動実行。protect をメインコマンド化し、gitignore / precommit / prebuild を削除。--mask と run --redact を削除（伏せ字は Dotenvxfile で設定）。transfer を追加
2.38.0getSync を追加。非対話モードの鍵保管先の既定を File に変更
2.35.0 – 2.37.0encrypt --with、armor invite、Armor の Enclaved 鍵を追加
2.34.0lock 系コマンドとパスワードによる鍵のロック解除を削除
2.31.0 – 2.33.0validate を check に改名し .env.example 対応を廃止。define を削除。ファイル名が Envfile → Envspec → Dotenvspec → Envfile と変遷
移行時の注意: 2.31.0 以降はマイナーバージョンでも破壊的変更が入っている。^2.x で依存を固定していると CLI の挙動が変わる。設定ファイル名も短期間に何度も変わったので、バージョンを固定して CHANGELOG を確認してから上げる。
