Kaku

tw93/Kaku — A modern Mac terminal that looks good, runs fast, and works with AI out of the box.
V0.30.0（2026-11-16）時点の内容。

1 — 概要
何か

Kaku は、WezTerm をベースにした macOS 向けターミナル。設定済みのフォント・テーマ・Mac ショートカット、AI アシスタントとチャット、コーディングエージェントの状態表示、ブラウザからのリモートアクセス、zsh/fish のシェル環境を、WezTerm の Lua 設定互換を保ったままひとまとめにしている。

名前の由来は日本語の「書く」。考えをコードとして形にする場所、という意味づけで、同じ作者の Waza / Kami と並ぶツール群の一部として位置づけられている。

初日に効くところ macOS only WezTerm compatible Lua config AI assistant Agent status Remote access zsh / fish

Kaku は「設定を作り込む前から気持ちよく動く」ことを重視している。JetBrains Mono、Kaku Dark / Light テーマ、選択時コピー、Mac 標準に近いショートカット、右クリックメニュー、タブとペインの復元が最初から入っている。インストールは DMG か brew install --cask kaku。

2 — 設計ポジション
Zero Config

フォント、テーマ、選択色、タブ/ペイン操作、コピー挙動など、AI コーディング時に邪魔になりやすい細部を初期値で整える。

AI coding

失敗コマンドの修復提案、自然言語からのコマンド生成、ツールを使える AI チャットを内蔵。Claude Code や Codex の作業状態をタブ・通知・kaku cli に流す。危険なコマンドは自動実行しない。

Compatibility

WezTerm の Lua config と API 互換を維持する。既存設定を活かしながら、Kaku 側のバンドル初期値に自分の上書きを重ねる設計。

Shell suite

z、zsh-completions、fast-syntax-highlighting、autosuggestions、Smart Tab、Starship、Delta、Lazygit、Yazi などを Kaku セッション内で自然に使えるようにする。

macOS polish

Cmd + Opt + Ctrl + K で上から降りるドロワー端末、閉じたウィンドウのレイアウト復元（Cmd + Option + Shift + T）、Option+Click のカーソル移動、読み取り専用の AppleScript 辞書などを macOS 前提で磨く。

Lightweight core

Rust ワークスペースの release profile は strip = true、lto = "fat"、codegen-units = 1、panic = "abort" でサイズと実行速度を優先する。

3 — AI ワークフロー
二つの入口

設定

kaku ai（Cmd + Shift + A）で設定パネルを開く。Auth Type は api_key（OpenAI 互換 Base URL と API key を直接指定）か codex（Codex のユーザー設定に追従）。AI サービスは Kaku が提供・中継するのではなく、自分で用意する。

失敗検知

コマンドが非ゼロ終了したとき、コマンド、終了コード、作業ディレクトリ、git ブランチを LLM に渡す。

修復提案

提案はインライン表示され、Cmd + Shift + E でプロンプトへ貼り付けられる。自動実行はしない。

自然言語

# <description> を入力すると、シェル実行前に捕捉され、コマンド候補へ変換される。

レビュー

危険な操作は「実行」ではなく「貼り付け」に留める。人間が読んでから Enter を押す設計になっている。

# Natural language to command examples
# list all files modified in the last 7 days
# find and kill the process on port 3000
# compress the src folder excluding node_modules
安全側の境界: Ctrl+C、help flags、裸の package manager 呼び出し、git pull conflicts、非シェル foreground process では Assistant を起動しない。rm -rf や git reset --hard などの危険なコマンドは貼り付けまでで、自動実行はしない。

AI チャットとモデル構成

Chat panel

Cmd + L で開くチャットパネル。Markdown をストリーミング表示し、ターミナルの内容を文脈として添付できる。プロジェクトのファイル、シェルコマンド、Web 検索、メモリといったツールは、対象と引数を確認して許可したものだけ実行する。

シェルからは k "..." または kaku chat で同じ会話ストアを使う。CLI 版は /new /resume /clear /status /memory /exit に絞った簡易版。

Simple / Deep model
  • Simple Model（model）: # によるコマンド生成、修復提案、軽いチャット。
  • Deep Model（chat_model）: Cmd + L / k の主チャットとツール利用。パネル内で Shift + Tab 切り替え。
  • API Mode: chat_completions（既定）か responses。responses では native_web_search でプロバイダ側の Web 検索を使える。
  • 保存先: ~/.config/kaku/assistant.toml。端末設定の kaku.lua とは分けている。
4 — エージェント連携
OSC 7501 で状態を受け取る

Claude Code（2.1.295 以降）と Codex（0.163 以降）は、自分の状態を OSC 7501 エスケープシーケンスで Kaku に通知する。状態は working / blocked（ユーザー待ち）/ done / error / idle の 5 種類。Kaku はこれを画面表示とスクリプト用 CLI の両方に使う。

Agent title

アクティブペインで Claude Code・Codex・Kimi が動いていると、ウィンドウ右上にエージェントのマークと現在のトピックを出す。入力欄の枠に同じトピックがあればマークだけ残す。config.show_agent_title = false で無効化。

Tab の注意マーク

ユーザー待ち・完了・失敗、BEL、OSC 9;4 のエラーや一時停止を、タブ末尾の琥珀色の点で示す。Claude Code が入力を待つと通知も出る。

kaku cli wait / events

kaku cli list --format json は状態を program_status として返す。wait は特定ペインの状態変化まで待ち、events は全ペインの遷移を 1 行ずつ流す。

# 隣のペインで別エージェントを動かし、終わるかユーザー待ちになるまで待つ
pane=$(kaku cli split-pane --right -- claude)
kaku cli send-text --pane-id "$pane" --no-paste $'review the changes in src/auth\r'
kaku cli wait --pane-id "$pane" --for done,blocked,error --next --timeout 20m
kaku cli get-text --pane-id "$pane" --start-line -100
# 全ペインを監視し、最初にユーザー待ちになったところで止める
kaku cli events --for blocked --once
wait の終了コード: 待っていた状態になれば 0、--timeout 超過で 2、Kaku に接続できないかペインが無ければ 1。--next を付けると前のターンに残った done では終わらない。状態を報告しないプログラム（素のシェルやビルド）は --for exit でしか待てない。これらの使い方は docs/agent-skill.md にエージェント向けスキルとしてまとめられており、~/.claude/skills/kaku/SKILL.md に置けば Claude Code から使える。
5 — リモートアクセス
kaku remote のペアリング

有効化

既定はオフ。kaku remote を実行すると、有効化してよいか確認したうえでペアリング用リンクを表示する。

リンクを開く

別のコンピュータのデスクトップブラウザで開く。リンクは 1 回限り、有効期限 10 分。

6 桁コード照合

ブラウザと端末に同じ 6 桁コードが出ていることを確認し、端末で Enter を押すと許可、Ctrl+C で拒否。リンクだけ盗まれてもペアリングできない。

ブックマーク

ブラウザが自分の鍵を保持するので、以後はブックマークから新しいリンク無しで戻れる。

管理

devices で一覧、revoke <id> で解除、off で停止、--reset で ID を作り直して全ブラウザを解除。

経路と暗号化
  • Relay: Mac 側が kaku-relay に外向き接続し、Mac だけが持つ秘密の SHA-256 から作った ID を所有していることを証明する。
  • E2E: ブラウザと Mac の間のメッセージは、リンクのフラグメントで渡した鍵で封をする。relay は読めないバイト列を転送するだけ。
  • Direct path: 接続後、WebRTC データチャネル（STUN で NAT 越え、DTLS）を張れれば、対話的な応答と画面はそちらを通る。ファイルは relay 経由のまま。切れたら relay に戻る。
ブラウザでできること
  • タブとペイン分割、コピー＆ペースト。
  • ファイルをドロップして Mac へアップロード、パスを Cmd + Click でダウンロード。
  • ペアリング済みブラウザがしばらくぶりに戻ると Mac に通知が出る。relay 接続状態は kaku doctor で確認できる。
  • Mac がスリープしているか Kaku が終了していると使えない。ノート型は電源接続とスリープ抑止の設定が必要。
6 — シェル連携
Bundled shell suite
  • z: よく使うディレクトリを学習する smarter cd。
  • zsh-completions: common CLI tools の補完を拡張。
  • fast-syntax-highlighting: 入力中にコマンドを色分けし、エラーも強調。zsh-syntax-highlighting より色が豊富で起動が速い。
  • zsh-autosuggestions: fish 風の履歴ベース補完。
  • Smart Tab: zsh の Tab を上書き。既定の suggestion_first は候補があれば受け入れ、無ければ補完。completion_first / off も選べる。

fish は kaku init --shell fish で ~/.config/kaku/fish/kaku.fish を用意する。

Optional tools
  • Starship: git と環境情報を含む高速プロンプト。
  • Delta: git diff / grep を読みやすくする pager。
  • Lazygit: Cmd + Shift + G で current pane に起動。Codex や vim が動いているペインでは新しいタブで開く。
  • Yazi: Cmd + Shift + Y または y で起動し、終了時に cwd を同期。テーマは Kaku Dark / Light に自動で合わせる。
Remote files

SSH セッション中に Cmd + Shift + R を押すと、現在の SSH target を検出して sshfs でローカルに mount し、Yazi で開ける。AI エージェントが遠隔サーバー上のファイルを触る場面でも、ターミナルの流れを切らずにファイル操作へ移れる。

7 — 設定と CLI
コマンド役割代表的な使いどころ
kaku aiAI 設定パネルを開くKaku Assistant と、Claude Code・Codex・Gemini CLI・Copilot CLI・Kimi Code などの設定
kaku chat単体の AI チャット（k の別名）別のシェルから Cmd + L と同じ会話・メモリを使う
kaku config設定 TUI を開く（Cmd + , と同じ）よく使う設定の変更。kaku.lua が無ければ作成
kaku doctor環境診断アプリ、PATH、zsh / fish 連携、relay 接続の確認。匿名化した診断 zip を書き出す
kaku remoteブラウザからのリモートアクセスペアリング、端末一覧、解除、停止
kaku update最新版確認と更新release を追従
kaku initzsh / fish integration を生成初回セットアップ、Starship・Delta・Lazygit・Yazi の導入
kaku resetKaku 管理の統合と状態を削除shell / tmux 連携、管理ブロック、AI メモリを消す。手書きの Lua は残る
kaku climultiplexer を外部から操作ペイン分割、send-text / get-text、wait / events
 
-- ~/.config/kaku/kaku.lua
-- 生成されたファイルはバンドル済みの既定値を読み込み、その後に上書きを適用する。

-- User overrides:
config.font_size = 16
config.window_background_opacity = 0.95
config.color_scheme = "Auto"          -- 新規インストールの既定は "Kaku Dark"
config.smart_tab_mode = "completion_first"
config.show_agent_title = false
config.macos_global_hotkey = { key = 'j', mods = 'CMD|OPT|CTRL' }
設定ファイルの分担: 端末の挙動・見た目・キーバインドは WezTerm 互換の kaku.lua、AI のモデル・認証・ツール設定は kaku ai が書き込む assistant.toml。更新はバックグラウンドで確認・ダウンロードされるが、全ウィンドウを閉じるため適用前に必ず確認を求める。
8 — 内部構成
Rust workspace map

Kaku は WezTerm 由来の crate 群を抱えた Rust workspace と、macOS アプリ本体、GUI、mux、terminal rendering 周辺のサブシステムで構成される。外側は「すぐ使えるターミナル」だが、中身は GUI・PTY・SSH・mux・surface・font・escape parser を分けた大きめのターミナル実装だ。

App layer

kaku / kaku-gui がアプリ起動、設定、macOS 統合、GUI の入口を担う。

Terminal core

term / termwiz / escape parser / font / surface が描画と端末プロトコルの土台。

Mux and remote

mux、SSH、UDS、remote crates がペイン、セッション、リモート操作の境界を担当。

Kaku 固有の crate役割
kakuCLI 本体。ai / chat / config TUI / doctor / init / reset / update などのサブコマンド。
kaku-guiGUI、タブとペイン、AI チャットパネル、エージェント状態表示、macOS 統合。
crates/kaku-ai-utilsAI 関連バイナリの共通処理（Codex 設定ディレクトリ CODEX_HOME の解決など）。
crates/kaku-remoteリモートアクセスの Mac 側。ペアリング、Web ページ配信、ファイル共有、WebRTC の direct path（str0m、純 Rust 暗号）、接続中の App Nap 抑止。
crates/kaku-relayMac とブラウザを中継するサーバー（axum + WebSocket）。暗号化済みバイト列の転送のみ。
旧版との差分: 以前の README にあった WezTerm 比の性能表（実行ファイル約 40 MB、シェル起動約 100 ms など）は現行 README から削除されているため、このページでも掲載をやめた。設定スキーマは config_version（現在 47）でリリースごとに番号を上げ、既存キーの変更にはマイグレーションを伴わせる運用になっている。
