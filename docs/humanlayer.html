HumanLayer

コーディングエージェントのタスク実行と共同レビュー

実行はホストで、進行管理はアプリで

自分のマシンで動くコーディングエージェントを、デスクトップと Web から操作する。調査・設計・実装の会話をタスクにまとめ、計画や成果物にチームでコメントできる。

02 — タスク・セッション・成果物

Task / 仕事を束ねる

一件の仕事に、複数の会話・共有ファイル・コメント・履歴をまとめる。担当者やマシンが変わっても、同じタスクで作業を続けられる。

Session / エージェントと話す

一つのエージェントとの会話。モデル設定、作業ディレクトリ、メッセージ、実行状態を持つ。調査と実装を別セッションに分けられる。

Artifact / 判断を残す

調査文書・設計・実装アウトラインなどをタスクファイルとして共有する。レビューのコメントを、後続セッションが参照できる。

Workspace / 作業場所を選ぶ

作業対象のリポジトリと worktree を定義する。複数リポジトリも扱え、primary repository がセッション開始場所になる。

タスクファイルの同期範囲: .humanlayer/tasks/<task-slug>/ 内の成果物を扱う。リポジトリ全体のバックアップではなく、対応するエージェントのファイルツール操作を契機に同期する。別プログラムが置いたファイルは、それだけではアップロードされない。

出典: Task の概念と同期 / Workspace モデル

03 — UI・クラウド・ホストの役割

01 / INTERFACE

デスクトップ / Web

タスクの作成、セッションへの返信、成果物のレビューを行う。共通 UI は apps/riptide-ui。macOS シェルは Electron / Tauri。

02 / CLOUD

API と同期基盤

作業要求とイベントを仲介する Hono + oRPC API。Postgres のクライアント同期には Electric と認証プロキシを使う。

03 / HOST

デーモンとコーディングエージェント

接続したホストでセッションを実行する。コード、開発ツール、資格情報、ネットワークへのアクセスは、そのホストと実行ユーザーに依存する。

作業要求: UI → API → 接続したデーモン。セッションイベント: デーモン → API → 各 UI。デスクトップは同じマシンのデーモンを起動でき、Web はリモートホストの作業を操作できる。

既存 CLI セッションのミラーリング: Claude Code / OpenCode のプラグイン、Pi の拡張から、手元で開始したセッションを HumanLayer に表示する経路もある。この経路のホスト表示は、Web から新規セッションを起動できることを意味しない。

出典: モノレポ構成 / デーモンの動作 / Pi 拡張 / Claude Code プラグイン / OpenCode プラグイン

04 — 最初のタスクを実行する

ローカルの macOS アプリ

公式チュートリアルは Apple silicon Mac、HumanLayer アカウント、認証済み Claude Code、Git を前提にしている。

  1. 公式アプリを入れてサインインする。
  2. 変更を保持する必要のない、クリーンなテスト用ブランチを選ぶ。
  3. Create Task で対象 Directory と小さな作業内容を指定する。
  4. ONESHOT / Worktree NEVER / Claude Code を選ぶ。
  5. 完了後にファイルと差分を確認する。

リモートホストの CLI

実行ホストで CLI を導入・認証し、デーモンを起動する。接続後は Web アプリから操作する。

npm install -g @humanlayer/cli@latest
humanlayer --help
humanlayer login
humanlayer daemon launch

エージェントが必要とするコード・ツール・認証も、そのホストで準備する。daemon launch は常駐サービスを自動登録しない。

Codex を使う場合: CLI の humanlayer agents auth codex login で認証し、新規セッションで Codex を選ぶ。HumanLayer へのログインとエージェントの認証は、それぞれ必要になる。

出典: 最初のタスク / リモート導入 / Codex 設定

05 — 変更の規模に合うワークフロー

設計の確認点に合わせて選ぶ
選択肢適した作業主な段階
Oneshot結果が明確な小さな修正実装 → PR
RPI調査と設計議論が必要質問 → 調査 → 設計議論 → 構造アウトライン → 実装 → PR
PRD-Oriented製品設計と技術設計を分けたい質問 → 調査 → PRD → TDD → 構造アウトライン → 実装 → PR
Freeform固定の段階を設けず進めたい固定フェーズなし

成果物を確認して次へ進む

段階ごとに成果物へフィードバックし、決定事項を文書に残す。設計やアウトラインの主要な引き継ぎは人の確認を待つ。通常の実装も、検証後に段階ごとのレビューを挟む。

Worktree を作る時点を選ぶ

Now: 最初のセッション前。Later: 実装前。Never: 現在の checkout を使用する。Oneshot の Later は Never と同じ扱いになる。

出典: ワークフローの選択 / 正確な段階・確認点・Worktree 設定

06 — 利用上の制約とソース開発

接続・権限・同期

  • デーモンは実行ユーザーのファイル・ネットワーク権限で動く。
  • Web とネイティブアプリは機能が同一ではない。workspace 管理や埋め込み terminal などは個別に確認する。
  • テキスト成果物は Markdown / text / JSON 系に対応し、各ファイルの上限は 10 MB。画像・PDF・HTML などはオブジェクトストレージを使う。

ソースから開発する場合

Bun と Turborepo のモノレポ。Bun と Docker が必要で、Tauri 版 riptide-native のビルドには Rust も必要になる。

# 開発用スタックの起動方法を確認
bun --bun run devstack help

環境設定とチェックは CONTRIBUTING.md を参照する。セルフホスト手順は README 時点で準備中。

再起動時の認証: humanlayer login は資格情報をホストに保存する。launch token を使う経路では、交換した資格情報はそのプロセス限り。サービス再起動時の認証方法を事前に決める。

出典: ホストと認証の制約 / 成果物の同期 / 開発環境とセルフホスト
