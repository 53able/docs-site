01 — Jane Street が公開したスキル集

SOCRATIC-TUTOR

答えを教えず、質問で理解させる。
レベルは実演できたときだけ上げる。

agent_skills は、Jane Street が AI エージェントとチャットボット向けに公開したスキル集です。各スキルは SKILL.md を 1 つ持つディレクトリで、2026-11-03 の初回公開時点で収録されているのは socratic-tutor の 1 本だけです。

socratic-tutor は、LLM を「厳しい個人チューター」にする指示書です。指定したトピックについて、診断、0〜5 段階のスキルマップ、1 問ずつの質問、間隔を空けた復習、最終試験の順に進めます。説明するのではなく、予測・理由づけ・誤りの指摘をユーザーにさせる問いで教えます。

02 — 起動条件と、始める前の確認

frontmatter の description は、起動のきっかけになる言い回しと、起動しない場合の両方を書いています。

description に書かれた起動条件
区分内容
起動する教わる・クイズを出される・習熟まで鍛えられることを明示的に頼んだとき。例: teach me、tutor me、quiz me、drill me、help me master
起動しない単発の explain X や what is X といった質問

本文の最初の節「Guard」でも同じ区別を繰り返します。単発の質問なら普通に答え、教える流れには入りません。どちらか判断できないときは、診断を始める前に 1 問だけ確認します。

Want a quick answer, or should I actually teach you this properly?
確認を挟む理由。 SKILL.md は「誤って始めるとユーザーは望まないクイズを受けることになるが、確認なら 1 語で済む」と書いています。

03 — 診断から最終試験までの流れ

  1. トピックを分解する

    トピックを 4〜10 の具体的なサブスキルに分けます。狭いトピックなら少なめにします。広いトピックは 2 段の木にして、最初に取り組む枝を選びます。

  2. 診断する

    「最初にいくつか質問して、今わかっていることを確かめる」と伝え、易しいものから難しいものまで 3〜5 問を 1 問ずつ出します。診断が終わるまでは何も教えません。

  3. スキルマップを見せる

    診断結果から各サブスキルの開始レベルを決め、マップを表示して開始地点を提案します。ユーザーは別の地点を選べます。

  4. サブスキルごとに教えるループを回す

    質問を中心に進め、レベルが変わるたびにマップを描き直します。途中で前のサブスキルを予告なしに再テストします（05・06）。

  5. 最終試験

    全サブスキルが目標レベル（既定 4/5、ユーザーが完全な習熟を求めたら 5/5）に達したら、全範囲の混合試験を行います。各サブスキル 1 問以上と、複数の内容を組み合わせる統合問題を 1 問以上含めます。合格なら最終マップと弱点のまとめを示し、不合格ならループに戻ります。

04 — 0〜5 のスキルマップ

各サブスキルの習熟度を 6 段階で記録します。既定の合格ラインは 4 です。

  1. 0知らない
  2. 1聞いたことがある
  3. 2説明について行ける
  4. 3手助けがあればできる
  5. 4一人でできる（既定の目標）
  6. 5人に教えられる・例外にも対応できる

マップはレベルが変わるたび、およびユーザーが進捗を求めたときに ASCII で表示します。SKILL.md の書式例は次の通りで、実際の表示ではバーに U+2588（█）と U+2591（░）を使うよう指示されています。

Topic: <topic>                          overall: ######.... 58%
-----------------------------------------------------------------
subskill A            [########..]  4/5  * independent
subskill B            [######....]  3/5  <- current focus
subskill C            [##........]  1/5
-----------------------------------------------------------------

05 — 教えるループでの質問の仕方

1 回に 1 問

質問を書いたらそこでメッセージを終え、答えを待ちます。質問の後にヒント、解答例、解説を付け足しません。

考えさせる問い

結果を予測させる、理由を説明させる、もっともらしい誤った主張の欠陥を見つけさせる、新しい場面に当てはめさせる、2 つの考えを結びつけさせる問いを優先します。

間違えたとき

答えは言わず、推論の矛盾が見える範囲の狭い問いを出します。直接説明するのは 2〜3 回続けて失敗した後だけで、説明したらすぐ別の角度から同じ内容を再テストします。

正解したとき

ときどきあえて反論します（「本当に？ X の場合は？」）。正しい答えを追及されても守れる状態を求めます。

説明は短く

ユーザーが自力で導けない新しい内容を導入するときだけ、数文の説明をします。説明の後は質問に戻ります。

実際にやらせる

ツールが使える環境では「〜するクエリを書いて」「このコードの出力を予測して」のような演習を出し、ユーザーの説明ではなく実際の出力を確認します。

06 — 評価基準（厳しめに設定）

Evaluation rules の要点
ルール内容
レベルは実演で上げる独立した 2 回以上の確認で正しく答えられたときだけ上げる。そのうち 1 回以上は、答えを教えられた直後ではない状態で自分から思い出せたこと
曖昧な答えは不正解扱い部分的に正しい答えは正解にしない。理解しているか判断できるまで掘り下げる。ユーザーが口にしていない洞察を、ユーザーのものとして扱わない
間隔を空けた復習前のサブスキルを予告なしに再テストする。失敗したらレベルを下げて学び直す
レベル 5 の条件例外的なケースや意地の悪い問いに対応でき、かつ「この人になら教えさせてよい」と思えるほど明確に説明できること
お世辞を言わない「Great try!」ではなく「Not quite — why would X happen if Y were true?」と返す

07 — セッション中に使えるコマンド

ユーザーがいつでも使える指示
入力動作
show progressスキルマップを表示する
harder / easier難易度を上げる / 下げる
just tell me今の 1 問に限ってソクラテス式をやめ、答えを教える
save stateトピック、レベル付きのスキルマップ、誤解のメモ、学習済みの範囲をまとめた短いブロックを出力する。新しいセッションに貼れば再開できる
resume from:続けて貼った保存ブロックから状態を復元し、中断したところから続ける
状態はチャットの中にしかありません。 スキルはファイルへの保存を行わないため、長い学習を複数セッションに分けるときは save state の出力をユーザー自身が保管しておく必要があります。

08 — 導入

  1. リポジトリを取得する

    git clone https://github.com/janestreet/agent_skills.git

  2. コーディングエージェントで使う

    socratic-tutor ディレクトリを、使っているエージェントのスキル用フォルダにコピーします。フォルダの場所はエージェントごとに異なります。以下は Claude Code の個人用スキルフォルダに置く場合の例です。

    mkdir -p ~/.claude/skills
cp -R agent_skills/socratic-tutor ~/.claude/skills/

    配置後に「teach me <トピック>」と頼みます。

  3. 普通のチャットボットで使う

    socratic-tutor/SKILL.md の本文（--- で囲まれた frontmatter より後ろ）をチャットか、カスタム指示・システムプロンプトに貼り、続けて学びたい内容を書きます。

09 — 使う前に確認すること

運用上の注意
項目内容
収録数「collection」と名乗っていますが、確認時点のスキルは socratic-tutor の 1 本だけです。スクリプトや参照資料はなく、102 行の SKILL.md のみで動きます
判定するのはモデル自身レベルの上げ下げは LLM の判断です。採点用のスクリプトや外部の正解データはありません。モデルが詳しくない分野では、問いや判定そのものが誤っている可能性があります
コンテキストの消費1 問ずつ往復し、レベルが変わるたびにマップを再描画するため、長い学習では会話が長くなります。区切りで save state を取り、新しいセッションで resume from: するのが手堅い運用です
文字の表示バーに使うブロック文字（█ ░）は、等幅でないフォントや一部の環境では揃って見えないことがあります
起動の取りこぼしdescription は明示的な依頼だけを起動条件にしています。「X を理解したい」のような曖昧な頼み方では自動で起動しない場合があるため、スキル名を指定するか「teach me」と書きます
貢献のルールプルリクエストには DCO（Developer Certificate of Origin）の署名が必要です。コミットに実名の Signed-off-by: 行を付けます（git commit -s）。偽名や匿名は受け付けていません
同梱ファイル.gitignore と .ocamlformat は Jane Street の OCaml リポジトリ共通のもので、スキルの動作には関係しません。コミットのメッセージ（v0.18~preview…）も社内の公開ツールによる自動のものです
