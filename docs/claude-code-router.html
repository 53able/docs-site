1 — 何を一元化するか
役割

Claude Code Router（CCR）は、Claude Code、Claude Design、Codex、Grok CLI、Kimi CLI、Kilo Code、OpenCode、Pi、ZCode、互換 API クライアントと、実際に推論を行うプロバイダーの間に入ります。クライアント側の接続先を固定したまま、CCR 側でモデルやアカウントを差し替えられます。

設定は Agent Profiles、Providers、Models、Routing、API Keys、Extensions などの画面に分かれ、処理結果は Logs で解決済みプロバイダー、モデル、認証情報、レイテンシ、トークン、推定コストまで追跡できます。

2 — リクエストが通る経路
Request lifecycle
Clients コーディングエージェント

プロファイルが接続先、環境変数、モデル既定値を適用します。

→
CCR :3456 認証 → ルール評価 → 変換

プロファイル固有ルールを先に評価し、続いてグローバルルール、書き換え、認証情報選択、リトライ、順序付きフォールバックを適用します。

→
Upstream 選択済みモデル

OpenAI、Anthropic、Gemini 系などのプロトコルへ適合し、応答と利用情報を CCR に戻します。

先勝ちのルール: カスタムルートは一覧順で評価され、最初に一致した有効ルールがリクエストを書き換えます。プロファイル固有ルールは、そのプロファイルの API キーで認証されたリクエストにだけ適用され、グローバル一覧より先に評価されます。
3 — モノレポの責務
@claude-code-router/core

ゲートウェイの中核

ルーティング、プロバイダー、認証情報、ストレージ、MCP、観測、プロファイル起動を担います。CLI とデスクトップの両方がこの中核を利用します。

@musistudio/claude-code-router

CLI 配布物

ccr コマンド、ブラウザ管理 UI、ローカルゲートウェイ、プロファイル起動を Electron なしで提供します。

@claude-code-router/ui

管理画面

React ベースの Web UI。プロバイダー、モデル、ルート、ログ、利用量、エージェント設定を操作します。

@claude-code-router/electron

デスクトップシェル

トレイ、通知、自動更新、OS 統合、デスクトップ専用ブラウザー機能を Web UI と中核サービスに加えます。

4 — 主要機能

Agents

クライアント別プロファイル、モデル上書き、スコープ、環境設定、CLI / App 起動を管理します。

Providers

プリセットと互換エンドポイント、プロトコル検査、モデル探索、接続確認、認証情報プールを扱います。

Routing

ヘッダー・本文条件、プレフィックス、パラメーター書き換え、リトライ、順序付きフォールバックを組み合わせます。

Tools

Fusion モデル、ToolHub、MCP、ブラウザー自動化、プラグイン、ローカルルート、仮想モデルを追加します。

Access

CCR クライアントキーごとに有効期限とリクエスト、トークン、画像のローカル上限を設定します。

Observability

要求・応答、解決済み経路、状態、遅延、トークン、推定コスト、ツール呼び出し、エージェントトレースを記録します。

5 — 最短の導入手順
CLI · Node.js 22+
npm install -g @musistudio/claude-code-router
ccr ui
プロバイダーを追加

Providers でプリセットまたはカスタム接続先を選び、API キー、プロトコル、モデルを保存します。

クライアントキーを作成

API Keys で、エージェントからゲートウェイへ送る要求を認証するキーを用意します。

ゲートウェイを開始

Server で起動し、既定の http://127.0.0.1:3456 が利用可能になったことを確認します。

Agent Profile を適用

対象エージェントとモデルを選び、起動後に Logs で解決済み経路と結果を確認します。

Desktop / CLI / Docker: デスクトップ版は OS 統合を含む推奨経路、CLI は開発マシンやヘッドレス環境向け、Docker は管理 UI とゲートウェイを既定で 127.0.0.1:3458 に公開します。
6 — 認証と運用境界
境界守るもの運用上の要点
管理トークンブラウザ UI と RPC APIccr_web_token を含む管理 URL はパスワードとして扱い、ログやチケットへ貼らない。
CCR クライアントキーモデルゲートウェイへの要求管理トークンとは別物。ゲートウェイを外部へ公開する前に必ず作成する。
プロバイダー認証情報上流 API とアカウントCCR のローカルデータディレクトリとバックアップを保護する。
リスナー管理画面とゲートウェイ意図的なリモート利用でなければ 127.0.0.1 にバインドする。外部公開時はファイアウォール、プライベートネットワーク、TLS を併用する。
SQLite設定・利用量・ログなど稼働中の DB を直接コピー・編集せず、UI の export を使うか CCR を停止してからバックアップする。
