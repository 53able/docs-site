Hyper

Electron のデスクトップアプリに、シェルプロセス、xterm.js の描画、React の UI、プラグイン API を組み合わせた拡張可能なターミナルです。

4.0.0-canary.5 macOS / Windows / Linux MIT

概要

01 / PROFILE

Hyper は Web 技術を使ってデスクトップ端末を構成します。Electron main process がシェルを起動し、renderer process が React の状態管理と xterm.js の表示を担います。プラグインは両側のライフサイクルや UI を拡張できます。

ElectronDESKTOP RUNTIME
React + ReduxRENDERER UI
xterm.jsTERMINAL VIEW
読み方: 端末出力は main process から renderer へ流れ、キー入力は同じ RPC/IPC 経路を逆向きに進みます。プラグイン API はこの実行境界をまたいでフックを提供します。

プロセス構成

02 / RUNTIME

ウィンドウごとの RPC チャネルで Electron main と renderer を接続します。シェルの起動・管理は main 側、画面と端末描画は renderer 側に分かれています。

Electron main process
app/index.ts Electron 起動、BrowserWindow、メニュー、プラグイン初期化
app/session.ts node-pty でシェルを起動し、出力をまとめて通知
app/rpc.ts ウィンドウごとの RPC Server を生成し、IPC を管理
↔ RPC / IPC window channel
Electron renderer process
lib/index.tsx Redux store と RPC listener を初期化し、通知を action に変換
HyperContainer / React タブ、ペイン、ヘッダー、通知などのアプリ UI を描画
lib/components/term.tsx xterm.js と検索・フィット・リンク等の addon を接続

入力方向: xterm.js のキー入力 → renderer action → RPC/IPC → Session.write() → node-pty → シェル。

端末データの往復

03 / DATA FLOW

出力は小さな IPC 呼び出しが続かないようにバッチ化し、renderer で session action に分けて xterm.js に渡します。

STEP 01

シェル起動

Session が設定に基づいて shell、引数、作業ディレクトリ、環境変数を渡し、node-pty を生成。

STEP 02

出力を集約

PTY の文字列を DataBatcher が最大約 16 ms ごと、または上限到達時に flush。

STEP 03

チャネルで送信

RPC Server が対象ウィンドウの WebContents に session data を送信。

STEP 04

状態を更新

renderer の RPC listener が UID とデータを取り出し、Redux action を dispatch。

STEP 05

端末へ描画

Term component が xterm.js に書き込み、Canvas などの addon と設定を適用。

流量制御の値

BATCH_DURATION_MS = 16 を目安にまとめ、BATCH_MAX_SIZE = 200 KiB で大きなバッファを flush します。コメント上、1 チャンク分（最大約 4 KiB）の超過はあり得ます。

プラグイン API

04 / EXTENSIONS

Hyper は拡張ポイント名を app/plugins/extensions.ts で列挙します。インストール済み・ローカルのプラグインを読み込み、フックに応じてアプリの設定や UI に合成します。

設定と CLI

05 / INTERFACE
hyper.json

設定のまとまり

  • config: shell、shellArgs、env、workingDirectory、フォント、色、scrollback、描画設定
  • profiles: プロファイルごとの設定。defaultProfile が初期選択を指定
  • plugins / localPlugins: npm から導入する拡張とローカル開発用拡張
  • keymaps: コマンドとショートカットの対応
CLI commands

拡張を管理する

hyper install <name>プラグインをインストール
hyper uninstall <name>プラグインを削除
hyper listインストール済みプラグインを表示
hyper search <query>Hyper 用プラグインを検索
hyper list-remote公開プラグイン一覧を表示

アプリ本体の起動時に任意の引数でファイルやディレクトリを渡すと、その場所を開きます。設定ファイルの場所とバージョンは hyper --help / hyper --version で確認できます。

開発と参照

06 / DEVELOPMENT
Local development

起動・検証

README の開発手順では pnpm を使います。watcher と Electron アプリは別ターミナルで起動します。

pnpm install
pnpm run dev
# 別ターミナル
pnpm run app

# lint + unit tests
pnpm test
pnpm run build
Project shape

リポジトリの入口

app/ は Electron main process、lib/ は renderer の React/Redux 実装、cli/ は hyper コマンドです。

ルート package.json から Webpack、TypeScript、Babel の build と AVA の unit test を実行します。ネイティブ依存のため、初回インストールには OS ごとのビルド要件があります。

  • vercel/hyper ソースコード・README・リリース
  • PLUGINS.md ローカル開発と拡張レシピ
  • extensions.ts 利用可能な拡張ポイント
  • hyper.is 製品情報と配布先
