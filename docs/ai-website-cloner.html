AI Website Cloner Template

URL を渡すと、AI エージェントが既存サイトを編集可能な Next.js ページとして再構築する — v0.6.1（2026-10-05）

1 — 概要
何か

AI Website Cloner Template は、既存のウェブページを AI コーディングエージェントに再現させるための Next.js テンプレート。Next.js + shadcn/ui + Tailwind CSS v4 の土台が用意されており、 エージェントに /clone-website <url1> [<url2> ...] を実行させると、 ソースの実テキスト・実アセット・レスポンシブ挙動・インタラクションを観察してページを組み立てる。

成果物は 動作する編集可能なコード。スクリーンショット、iframe、ダウンロードした本番バンドルは参照資料として扱い、 実装そのものには使わない。

2 — クイックスタート
1. プロジェクトを用意する

方法は 2 つ。README が推奨するのは、エージェントにセットアップを任せる方法。

A. エージェントに頼む（推奨）

Codex、Claude Code などのエージェントに次の文面を貼り付ける。保存先を尋ねられたら答える。

Set up https://github.com/JCodesMore/ai-website-cloner-template
as a standalone project in a new folder on my computer.
Ask me where to put it. Clone the repository, remove its origin remote,
install dependencies, and run npm run check. Leave it ready for me
to clone a website.

エージェントはリポジトリを clone し、origin リモートを外し、依存関係を入れて npm run check を通す。

B. 自分の GitHub リポジトリを作る

GitHub の Use this template から名前を付けて Create repository を押す。作成したリポジトリの URL をエージェントに渡し、 手元への clone、依存関係のインストール、npm run check の実行を依頼する。

2. サイトを再現する

ブラウザを使える状態でエージェントにプロジェクトを開かせ、Claude Code または Cursor で次を実行する。

/clone-website https://example.com

URL は空白区切りで複数渡せる。完成後は、追加の変更をそのままエージェントに依頼する。

よく使うコマンド 
npm run dev        # 開発サーバー起動
npm run build      # プロダクションビルド
npm run lint       # ESLint チェック
npm run typecheck  # TypeScript 型チェック
npm run check      # lint + typecheck + build をまとめて実行

# Docker を使う場合
docker compose up app --build   # ビルドして起動
docker compose up dev --build   # 開発モード（ポート 3001）
3 — /clone-website の 4 ステップ
Map → Observe → Build → Compare

各ステップの終了条件
ステップ主な作業終了条件
1. Map プロジェクト指示・スクリプト・既存ルートを読み、ソース URL をローカルルートへ対応付ける。サイトごとに src/components/sites/<site>/ などの置き場所を分ける。 すべての URL に行き先があり、ファイルの持ち主が明確
2. Observe ページ全体をスクロールして遅延読み込みを発火させ、メニュー・タブ・カルーセル・ホバーを操作する。スクリーンショットに幅・スクロール位置・状態を記録し、ページブリーフにまとめる。 全セクションと意味のある状態について、作るのに足りる証拠がある
3. Build フォント・ページ幅・色・アセット・ルート・共通部品を先に確定し、実コンテンツでセクションを作る。独立したページやセクションは、スクリーンショットと寸法、保存先を添えて他のエージェントへ渡せる。 すべてのルートが実アセットで描画され、主要な操作が動く
4. Compare ソースとローカルを同じ条件で並べ、形・欠けたレイヤー・文字組み・切り抜き・余白・動きの順に直す。ナビゲーション、モバイルメニュー、横スクロールの発生、アセット欠落も確かめる。 本番ビルドの成功 かつ 描画比較。未確認の結果をピクセル完全と呼ばない
複数 URL と既存クローン: 同じオリジンの複数ページはパス名を保つ。クエリやフラグメントの違いは同じルートの状態として再現する。 オリジンが異なる場合は、指示がない限り別アプリに分ける。既存ページは保持し、要求のないルート衝突は置き換え前に解消する。
4 — 観察と動きの扱い
観察は「規則」のサンプルとして扱う

v0.6.1 で追加された考え方。1 回の描画結果から値を推測せず、次のようにして変化の原因を突き止める。

  • computed style、CSS 変数、ライブラリの実行時オプションなど、宣言された値を読む
  • ビューポートの幅（デザイン幅より広い幅を含む）、高さ、入力、状態を変えて、何が変化を起こすかを確かめる
  • ホイール・タッチ・キーボード・ポインタなど、訪問者と同じ入力で操作する。スクリプトでのスクロールはスムーススクロールなど入力に紐づく挙動を素通りする
  • ソースが実際に読み込むフォント・画像・SVG・動画を使う。同名の代替品はメトリクスや形が違う
  • URL の拡張子を信用しない。.png の URL が AVIF を返すことがあるため、Content-Type と寸法を確認する
動きの駆動源を見分ける

スクロールで動くセクションをクリックで真似すると別物になる。references/framer-and-motion.md は駆動源ごとに確認すべき証拠と実装手段を挙げている。

Framer サイトの注意点
  • デスクトップとモバイルの両バリアントが DOM にあり、片方をクラスで隠していることがある。各幅で見えている要素のスタイルを読む
  • data-framer-name はセクションの手がかりになるが、生成クラス名はコンポーネント設計ではない
  • 静的な Medium ウェイトのファイルを可変フォントとして宣言すると、本文が太くなる。@font-face の前に実ファイルのウェイトを確かめる
  • Framer のスムーススクロールは Lenis。html の lenis クラスか window.lenis からオプションを読む
  • デプロイ用スクリプトや minify 済みラッパーは証拠であり、新しいアプリに貼り付けるコードではない

6 — プロジェクト構成
ディレクトリツリー

v0.4.0 以降、クローン対象ごとに <site> ディレクトリを分け、後から別サイトを追加しても既存ページを壊さない。

src/
  app/                # Next.js ルート (App Router)
  components/
    ui/               # shadcn/ui プリミティブ
    sites/<site>/     # サイト固有のコンポーネントと抽出 SVG
  lib/utils.ts        # cn() ユーティリティ
  types/              # TypeScript インターフェース
  hooks/              # カスタム React hooks
public/
  sites/<site>/       # サイト固有の画像・フォント・動画など
docs/
  research/<site>/    # ページブリーフ、アセット対応表、検査の証拠
  design-references/  # スクリーンショット
scripts/              # アセットのダウンロードスクリプト置き場（AGENTS.md の記載。テンプレートでは空）
.agents/skills/
  clone-website/      # 正のスキルと検査リファレンス
.claude/commands/
  clone-website.md    # Claude Code 用の薄いブリッジ
AGENTS.md             # エージェント指示（唯一の正）
CLAUDE.md             # Claude Code 設定（AGENTS.md を読み込む）
コードスタイルと設計原則（AGENTS.md）
  • TypeScript strict モード、any 禁止
  • Named exports、PascalCase のコンポーネント、camelCase のユーティリティ
  • Tailwind ユーティリティかスコープ付き CSS を使う。インラインスタイルは動的な値が必要なときだけ
  • インデント 2 スペース、モバイルファースト
  • 再現中は個人の好みでデザインを変えない。まず 1:1 で合わせ、カスタマイズは後で行う
  • プレースホルダーではなく、ソースの実テキストと実アセットを使う
7 — 用途と禁止事項
README が挙げる用途
  • プラットフォーム移行 — 自分が所有するサイトを WordPress / Webflow / Squarespace から Next.js へ作り直す
  • ソースコードの喪失 — サイトは公開中だがリポジトリが無い、開発者が去った、スタックが古い場合に、現代的な形でコードを取り戻す
  • 学習 — 本番サイトのレイアウト、アニメーション、レスポンシブ挙動の作り方を、実際のコードで分解する
想定外の用途: フィッシングやなりすまし、違法行為への利用は禁止。ロゴ、ブランド資産、オリジナルの文章は所有者のものであり、 他人のデザインを自分のものとして出さない。スクレイピングや複製を利用規約で禁じているサイトもあるため、事前に確認する。
