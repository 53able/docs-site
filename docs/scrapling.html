Scrapling

HTTP 取得、ステルスブラウザ、パース、クロールを 1 つにまとめた Python スクレイピングフレームワーク

Fetcher / StealthyFetcher → Selector → Spider → export / D4Vinci/Scrapling v0.5（main 95cf901、2026-11-01 時点）

1 — 概要

Web scraping framework for Python

Scrapling は、ページの取得、HTML の解析、サイト全体のクロールを 1 つのライブラリで扱う Python のスクレイピングフレームワークです。作者は Karim Shoair（@D4Vinci）で、ライセンスは BSD-3-Clause です。

静的ページは TLS 指紋を偽装した HTTP リクエストで取り、JavaScript で描画されるページや Cloudflare Turnstile のあるページは Patchright ベースのステルスブラウザで取ります。返ってきた Response は CSS、XPath、BeautifulSoup 風の検索、テキスト検索、正規表現でそのまま解析でき、Scrapy に似た Spider で並行クロール、一時停止と再開、JSON / CSV などへの書き出しまで進められます。

Python から使うほか、コードを書かずにターミナルから抽出する scrapling extract、IPython ベースの対話シェル、AI エージェント向けの MCP サーバーと Agent Skill を備えています。

4 — Fetcher の選び方

v0.5 で Fetcher は 2 系統になりました。HTTP だけで足りるなら Fetcher、JavaScript の描画やボット対策の突破が必要なら StealthyFetcher を使います。どちらも戻り値は同じ Response（Selector にステータス、ヘッダー、Cookie などを足したもの）なので、解析のコードは変わりません。

Fetcher / AsyncFetcherStealthyFetcher
エンジンcurl_cffiPatchright（Playwright の改変版）上の Chromium または Google Chrome
JavaScript実行しない実行する
速度・メモリ速い・軽い遅い・重い
偽装impersonate='chrome' でブラウザの TLS 指紋と一致するヘッダーを送る。stealthy_headers、HTTP/3指紋の偽装、hide_canvas、block_webrtc、solve_cloudflare=True で Turnstile / Interstitial を突破
主なオプションproxy、retries、follow_redirects、verifyheadless、network_idle、wait_selector、page_action、block_ads、blocked_domains、dns_over_https、cdp_url、executable_path、pierce_shadow
向く用途HTTP だけで取れるページ、API動的なサイト、小規模な自動操作、保護されたページ

1 回だけ取るならクラスメソッドを呼び、続けて取るならセッションクラスを使います。セッションはブラウザや接続を開いたままにし、Cookie と状態を引き継ぎます。FetcherSession は同期と非同期の両方で使え、ブラウザ側は StealthySession と AsyncStealthySession（max_pages でタブを並列化）に分かれています。

HTTP セッション

from scrapling.fetchers import FetcherSession

with FetcherSession(impersonate='chrome') as session:
    page = session.get('https://quotes.toscrape.com/',
                       stealthy_headers=True)
    quotes = page.css('.quote .text::text').getall()

ステルスブラウザ

from scrapling.fetchers import StealthySession

with StealthySession(headless=True, solve_cloudflare=True) as session:
    page = session.fetch('https://nopecha.com/demo/cloudflare',
                         google_search=False)
    data = page.css('#padded_content a').getall()

そのほか、全セッション共通の ProxyRotator（巡回または独自の戦略、リクエスト単位の上書き）、ローカルでブラウザを起動せず CDP で既存ブラウザへつなぐ cdp_url、プロキシ利用時の DNS 漏れを防ぐ Cloudflare DoH 経由の名前解決があります。Response.markdown() はスクリプト、スタイル、隠し要素を除いた Markdown を返します。

5 — パースと adaptive

解析は Selector が担います。Fetcher を使わず、手元の HTML 文字列から Selector("<html>...</html>") で作っても同じ API で使えます。Scrapy / Parsel と同じ ::text、::attr(href) 疑似要素に対応しています。

方法例
CSSpage.css('.quote .text::text').getall()
XPathpage.xpath('//div[@class="quote"]')
BeautifulSoup 風page.find_all('div', class_='quote')
テキスト・正規表現page.find_by_text('Albert Einstein', first_match=False)
DOM の移動.parent、.next、.below_elements、チェーンした .css()
類似要素first_quote.find_similar() で同じ形の要素を集める
セレクタ生成任意の要素から頑健な CSS / XPath セレクタを作る

adaptive: サイトが変わっても要素を見つけ直す

サイトの構造が変わると、#p1 のようなセレクタは何も返さなくなります。adaptive を有効にしておくと、Scrapling は要素の特徴を保存しておき、セレクタが外れたときにページ上の全要素と比べて最も似ている要素を返します。AI は使いません。

adaptive=True で有効化→ css(..., auto_save=True)→ ドメイン + 識別子で SQLite に保存→ サイト変更でセレクタが空に→ css(..., adaptive=True)→ 類似度が最も高い要素を返す 
from scrapling.fetchers import Fetcher

Fetcher.adaptive = True              # 既定は無効
page = Fetcher.get('https://example.com')
element = page.css('#p1', auto_save=True)
if not element:                      # サイトが変わったら
    element = page.css('#p1', adaptive=True)

比べる特徴は、要素のタグ名・テキスト・属性（名前と値）・兄弟のタグ名・パス（タグ名のみ）と、親のタグ名・属性・テキストです。完全一致ではなく類似度で採点し、クラス名の並び順まで考慮します。保存データはドメインごとに分かれるため、URL ごと変わったサイトでは adaptive_domain で同じサイトだと指定します。保存先は既定で SQLite で、storage 引数で独自のストレージに差し替えられます。

6 — Spider

Spider は Scrapy に似た非同期のクロールフレームワークです。start_urls と async の parse を書き、parse から辞書（アイテム）か Request（次のリクエスト）を yield します。

Spider.start_requests→ Scheduler（優先度キュー + 重複除去）→ Crawler Engine（並行数・遅延・robots.txt）→ Session Manager（sid で振り分け）→ セッションが取得→ ブロック判定と再試行→ コールバック → item / Request

リクエストの指紋は URL、メソッド、本文、セッション ID から作ります。crawldir を指定すると、Engine が保留中のリクエストと既出 URL の指紋を定期的に pickle で保存し（一時ファイルから rename する原子的な書き込み）、Ctrl+C の停止時にも保存します。同じ crawldir で再実行すると続きから始まり、正常に終わればチェックポイントは削除されます。アイテムは別途保存する必要があります。

from scrapling.spiders import Spider, Request, Response
from scrapling.fetchers import FetcherSession, AsyncStealthySession

class MultiSessionSpider(Spider):
    name = "multi"
    start_urls = ["https://example.com/"]
    concurrent_requests = 10

    def configure_sessions(self, manager):
        manager.add("fast", FetcherSession(impersonate="chrome"))
        manager.add("stealth", AsyncStealthySession(headless=True), lazy=True)

    async def parse(self, response: Response):
        for link in response.css('a::attr(href)').getall():
            if "protected" in link:
                yield Request(link, sid="stealth")   # 保護されたページだけブラウザで
            else:
                yield Request(link, sid="fast", callback=self.parse)

result = MultiSessionSpider(crawldir="./crawl_data").start()
result.items.to_json("items.json")

7 — ネットワーク履歴と状態保存

v0.5 で追加された、ブラウザセッション向けの機能です。どちらもセッションクラス（StealthySession / AsyncStealthySession）で使います。

ネットワーク履歴（record_requests）

セッション作成時に record_requests=True を渡すと、ページ読み込み、操作、タブをまたいで完了したリクエストを記録します。ページの裏で呼ばれた API の応答を、リクエストを送り直さずに読めます。

with StealthySession(record_requests=True) as session:
    session.fetch("https://example.com", network_idle=True)
    for r in session.network.search(url_pattern=r"/api/", limit=None):
        print(r.url, r.status, r.body)
  • URL、メソッド、リソース種別、ステータスで絞り込める。search() の既定の上限は 100 件
  • 保持は既定で 1,000 リクエスト（max_recorded_requests）。本文はテキスト系の Content-Type だけで、1 応答 1 MiB、合計 20 MiB まで
  • 完了したリクエストだけが残る。読み取りやセッション終了は保留中の記録を待たない

ログイン状態（save_state / load_state）

Cookie、localStorage、IndexedDB を Playwright 互換の JSON に保存し、別の実行で読み込みます。1 度ログインした状態を次回以降に使い回すための機能です。

  • 同期・非同期どちらのブラウザセッションでも使える
  • ページの取得や再読み込みの前に読み込む
  • 開始済みの共有ブラウザコンテキストが必要で、proxy_rotator とは併用できない
  • タブ、ブラウザ設定、sessionStorage は保存しない

同じく v0.5 で、pierce_shadow=True により開いた Shadow DOM の中身を通常の CSS / XPath で取れるようになりました。閉じた Shadow DOM と iframe の文書は HTML 取得に含まれません。

8 — CLI と対話シェル

scrapling コマンドのサブコマンドは install、shell、extract、mcp の 4 つです。extract はコードを書かずにページをファイルへ保存します。出力形式は拡張子で決まり、.txt はテキスト、.md は Markdown、.html は HTML です。

pip install "scrapling[shell]"

# HTTP で取得（get / post / put / delete）
scrapling extract get 'https://quotes.toscrape.com/' quotes.md
scrapling extract get 'https://quotes.toscrape.com/' quotes.txt --css-selector '.quote' --impersonate 'chrome'

# ブラウザで取得（fetch）
scrapling extract fetch 'https://quotes.toscrape.com/js/' quotes.md --css-selector '.quote' --wait-selector '.quote' --no-headless
scrapling extract fetch 'https://nopecha.com/demo/cloudflare' captchas.html --css-selector '#padded_content a' --solve-cloudflare

# 対話シェル（IPython ベース）
scrapling shell

--css-selector で範囲を絞り、--ai-targeted を付けると body の中身だけを選んで隠し要素を除去します。対話シェルには、curl コマンドを Scrapling のリクエストに変換する機能や、取得結果をブラウザで表示する機能があります。

9 — MCP サーバーと Agent Skill

AI 向けの入口は 2 つあり、役割が違います。MCP サーバーは Claude や Cursor などのチャットやエージェントにスクレイピングを代行させるツール群です。Agent Skill はコーディングエージェントにScrapling の現行 API を教え、古い学習データから推測したコードを書かせないための資料です。

MCP サーバーの 16 ツール

分類ツール内容

ブラウザ系ツールは既定で広告・トラッカーのドメインを遮断し、AI に渡す内容から隠し要素、aria-hidden、ゼロ幅文字、HTML コメント、template タグを除去します。プロンプトインジェクションの埋め込みを減らすための処理です。

stdio で登録する（Claude Code）

pip install "scrapling[ai]"
scrapling install
claude mcp add ScraplingServer "$(which scrapling-mcp)"

Claude Desktop では設定ファイルの mcpServers に "command": "scrapling-mcp" を書きます。Docker なら docker run -i --rm pyd4vinci/scrapling mcp を起動コマンドにします。

Streamable HTTP で公開する

# トークンはシェル履歴に残らない環境変数で渡す
export SCRAPLING_MCP_AUTH_TOKEN="$(openssl rand -hex 32)"
scrapling-mcp --http --allowed-host 'your-server.example.com:8000'

HTTP モードではポートに届く誰もが全ツールを呼べ、サーバーのマシンから任意の URL を取得できてしまいます。そのため --http はトークン無しでは起動せず、クライアントは Authorization: Bearer ヘッダーでトークンを送ります。--allowed-host は DNS リバインディング対策です。トークンは平文で流れるため、公開時は TLS を終端するリバースプロキシの後ろに置きます。認証を外す --no-auth もありますが、起動時に警告が出ます。

10 — v0.5 への移行

v0.5（2026-10-17）は破壊的変更を多く含みます。v0.4.15 から上げる場合は、公式の移行ガイドに沿って次の点を確認します。

使っているもの変更
DynamicFetcher、DynamicSession、AsyncDynamicSession削除 素の Playwright バックエンドが無くなった。StealthyFetcher / StealthySession / AsyncStealthySession に置き換える。ブラウザ型の import も playwright から patchright へ
capture_xhr、response.captured_xhr削除 record_requests=True のセッションと session.network.search() へ移す
keep_cdata削除 Selector と Fetcher の設定から外す
scrapling extract stealthy-fetch、シェルの stealthy_fetch()fetch に統一
MCP のツールツール名、スクリーンショットの呼び方、セッション作成の戻り値が変わった
POST やクエリ付きリクエストの後の response.follow()メソッド、クエリ、本文を引き継がなくなった。必要なら渡し直す
保存済みのチェックポイント、レスポンスキャッシュリクエスト指紋の入力が変わったため、新しくクロールし直す
robots_txt_obey=Truerobots.txt の取得失敗がそのドメインのクロールを止めるようになった
extra_flags組み込みのステルス用フラグを置き換えず、追加する形になった
Patchright の分離コンテキスト Patchright は既定で JavaScript を分離されたコンテキストで評価します。コールバックからページ自身の JavaScript 変数を読む場合は page.evaluate(..., isolated_context=False) を指定します。Cloudflare の突破は今も solve_cloudflare=True を明示したときだけ動きます。

11 — ベンチマーク

README には、5,000 個の入れ子要素からテキストを取り出す速度の比較があります（100 回以上の平均、benchmarks.py）。作者による計測で、条件によって差は変わります。下のバーは差が 3 桁に及ぶため対数目盛です。

Scrapling1.99 ms
Parsel / Scrapy2.06 ms
Raw lxml2.56 ms
PyQuery23.98 ms
Selectolax197.02 ms
MechanicalSoup1545.15 ms
BS4 + lxml1562.1 ms
BS4 + html5lib3412.73 ms

Scrapling、Parsel、素の lxml はいずれも lxml 上で動くため、上位 3 つの差は小さく、Scrapling は素の lxml より遅くはないという読み方が妥当です。類似要素の探索とテキスト検索の比較では、Scrapling 2.3 ms に対し AutoScraper 12.58 ms（約 5.5 倍）です。
