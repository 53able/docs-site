interfere-inc/landmines · npm @interfere/landmines 0.1.0 · Oxlint 1.81 以上 · Node 22.18 以上 · MIT

01 — CI を通すための近道を、lint で失敗させる

MOCK · SLEEP · RETRY · TIMEOUT · COMMENT → LINT ERROR

テスト対象をモックする、sleep で競合をやり過ごす、落ちたテストをリトライする。こうした「通るが正しくない」書き方を Oxlint のエラーにする。

landmines は、AI が書いたコードを対象にした Oxlint の JS プラグインです。README は動機を次のように説明しています。コーディングエージェントは CI を緑にすることを優先しやすく、放っておくとテスト対象をモックし、競合が大抵うまくいくまで sleep し、フレーキーなテストをリトライし、タイムアウトを延ばし、差分の説明をコメントに書く。どれも CI は通るが、どれも事実を表していない。

各ルールのエラーメッセージには「代わりに何をするか」が書かれています。エージェントが lint で失敗したとき、同じループの中でそのメッセージを読んで書き直せるようにする設計です。Interfere 社が自社の本番開発で使っているものを公開したと README にあります。

02 — どの近道を、どのルールが塞ぐか

README の冒頭に挙がっている近道と、それを検出するルールの対応です。左が近道、右がメッセージで示される代わりの書き方です。

03 — 4 プラグイン・10 ルールの一覧

ルールはプラグイン単位で分かれていて、パッケージのエントリーポイントも @interfere/landmines/testing のようにプラグインごとです。configs/recommended.json は 4 つのプラグインを登録し、10 ルールすべてを error にします。

04 — no-test-doubles：差し替えは禁止、観察は許可

実装は約 2,400 行あり、10 ルールの中で最も大きいルールです。方針は「依存先の振る舞いを置き換えたら報告、呼ばれたかどうかを見るだけなら許可」です。ネットワークについては、実際の実装と MSW を使うよう求めます。

REPORTED

報告される例

vi.mock("client");
vi.fn(() => 1);
vi.spyOn(client, "send").mockResolvedValue({});
vi.stubGlobal("fetch", replacement);
globalThis.fetch = replacement;
Object.defineProperty(navigator, "clipboard", { value });
AbortController.prototype.abort = abort;
ALLOWED

許可される例

const received = vi.fn();
vi.spyOn(client, "send");
vi.spyOn(AbortSignal, "timeout");
vi.mock("client", { spy: true });

実装を渡さない vi.fn()、mock* を続けない spyOn、Vitest の { spy: true } 付きのモジュールモック（元の実装を保ったまま呼び出しを記録する）は観察とみなされます。

検出の範囲

  • Vitest / Jest の API：mockImplementation、mockReturnValue、mockResolvedValue などの置き換え系メソッド、vi.mock・doMock・stubGlobal・jest.setMock・replaceProperty・enableAutomock など。
  • 書き方の言い換え：vi.mock.call(vi, …)、Reflect.apply(vi.fn, …)、bind した関数、分割代入や別名、計算プロパティ（vi[method]）経由の呼び出しも、同じファイル内で追える範囲で検出します。テストファイルにはこうした言い換えの例が多数並んでいます。
  • ブラウザ・ランタイムのグローバル：fetch、Date、crypto、localStorage、navigator、matchMedia、ResizeObserver など 41 のグローバルへの代入と、Date.now、Math.random、navigator.clipboard.readText などのメンバーの書き換え・削除。
  • 特定のフレームワーク：Cloudflare Workers の env バインディングに関数を入れること（withEnv、runInDurableObject 内のインスタンス書き換えを含む）、Tauri の mockIPC 系、Playwright の route.fulfill に固定レスポンスを渡すこと、Hono の app.request への手書きバインディング、Knock クライアントへの偽の fetch、vitest.config の outboundService と serviceBindings。
  • 保存して戻すパターン：const original = obj.method; obj.method = () => …; obj.method = original; のように、元の値を保存して差し替え、後で戻すコードも報告します。

グローバルの書き換えなどは「テストコード」と判定したファイルでだけ調べます。判定条件は、パスに tests/・__tests__/・test-utils/ などを含むか、ファイル名が .test・.spec・.fixture・.mock・setup などで終わるか、vitest・@jest/globals・node:test を import しているかです。

05 — 待ち方と MSW のルール

no-fixed-sleep

test・it・beforeEach などのコールバックの中で、次のような固定時間の待機を await すると報告します。

  • new Promise((resolve) => setTimeout(resolve, 250)) の形
  • node:timers/promises から import した setTimeout
  • scheduler.wait、Bun.sleep

同じファイルのどこかで vi.useFakeTimers() を呼んでいると、そのファイルでは報告しません。時間を進めたい場合は偽のタイマーで進めるよう、メッセージも案内しています。

no-unsignaled-poll

expect.poll や vi.waitFor のコールバックが、.mock を含むパス、記録用の配列の length・size、toHaveBeenCalled 系の matcher を見ている場合に報告します。期限付きでカウンタをポーリングすると CPU 負荷が高いときに落ち、タイムアウトを延ばしても隠れるだけ、というのがメッセージの説明です。代わりに、記録する側のハンドラで Promise.withResolvers() の promise を resolve し、テスト側はそれを await します。current を含むパス（React の ref などを想定したものと見られます）は対象外です。

strict-msw

msw/node の setupServer().listen() と msw/browser の setupWorker().start() について、引数に onUnhandledRequest: "error"（または関数）がなければ報告します。ハンドラのないリクエストが実際のネットワークに出ていくのを防ぐためです。ローカルの自前のオリジンは passthrough() で通すよう案内されます。

no-flake-masking

テストやスイートのオプション、vi.setConfig、設定ファイルの test オブジェクトにある retry を報告します。タイムアウトについては、test("x", fn, 10_000) の第 3 引数、オプションの timeout、vi.setConfig の testTimeout・hookTimeout が対象です。遅い共通の準備は beforeAll に移すよう案内されます。

06 — 許可リストで段階的に導入する

既存のコードベースにいきなり入れると違反が大量に出るため、一部のルールはファイルごとに「この件数までは許す」という許可リストを受け付けます。件数は正確に一致させる必要があります。

{
  "landmines-testing/no-flake-masking": [
    "error",
    { "allow": { "src/legacy/slow.test.ts": 2 } }
  ]
}

違反を直して件数が減ると、そのまま放置はできず、許可数を下げるよう lint が求めます。許可リストは減る方向にしか動きません（README の表現では「ratchet down」）。パスの照合は完全一致か、/パス での後方一致です。

07 — no-comments：残してよいコメントは 3 種類だけ

説明のためのコメントはすべて報告します。メッセージは「意味はコードで表し、理由は PR に書く」です。残せるのは次の 3 種類です。

DIRECTIVE

機能を持つディレクティブ

oxlint-disable・eslint-disable、@ts-expect-error、prettier-ignore、istanbul ignore、/* @__PURE__ */、webpackChunkName:、@jsx、/// <reference>、sourceMappingURL、SPDX-License-Identifier: など。

WARNING

1 行の // WARNING:

繰り返し踏まれる危険な落とし穴のためのもの。行コメントで、1 行に収まり、WARNING: の後に本文があるものだけが対象です。

TSDOC

公開 API の TSDoc

export された宣言の直前の /** … */。export された型から参照される interface・type やそのメンバーも含みます。@internal・@private を含むものは対象外です。

オプション publicApi（ファイルパスに対する正規表現の配列）を渡すと、TSDoc を残せるのはそれに一致するファイルだけになります。渡さなければ全ファイルで TSDoc を許可します。

{
  "landmines-style/no-comments": ["error", { "publicApi": ["/packages/sdk/"] }]
}

08 — 構造と型のルール

colocated-tests

.test.ts などのテストファイルが import している実装から「持ち主」のディレクトリを推定し、テストがその隣か、持ち主の直下の test/・tests/・__tests__/ にない場合に報告します。推定には oxc-resolver で import を解決し、.fixture.・.test-utils. などの付随ファイルが import しているものも Babel でたどります。持ち主が一意に決まらない場合は報告しません。

test-file-names

src/rules/test-file-names.ts より
種類報告される名前求められる名前
テスト.spec.ts、.specs.ts、.tests.ts<subject>.test.ts（必要なら .browser.test.tsx のような実行環境の中置）
テストデータfixtures.ts、user-fixture.ts など<subject>.fixture.ts
補助コード.helpers.ts、.mocks.ts、.stubs.ts、.harness.ts、.test-util.ts など<subject>.test-utils.ts
ディレクトリパッケージ内の tests/・__tests__/ 配下にあるファイル単数形の test/ に置く（テストでは test/recovery/admission.test.ts を許可、src/tests/… と src/__tests__/… を拒否）

package-exports

ファイルの属するパッケージの package.json を読み、exports の値に *、src/*、src/*.ts のような無制限のパターンがあれば報告します。明示したエントリーポイントか、名前を付けた公開名前空間を宣言するよう求めます。landmines 自身の package.json も、./testing などのプラグインごとのエントリーポイントだけを公開しています。

no-explicit-return-types

本体のある関数・アロー関数の戻り値の型注釈を報告します。型は推論させ、契約を固定したい場所では型付きの変数か satisfies を使うよう求めます。型述語（x is Foo）と never は対象外です。オーバーロードのシグネチャなど本体のない宣言も対象外です。

09 — 導入

  1. インストール

    bun add -d oxlint @interfere/landmines

    Oxlint 1.81 以上（peerDependency）、Node 22.18 以上が必要です。npm や pnpm でも -D で入れられます。

  2. recommended をまとめて有効にする

    {
  "extends": ["./node_modules/@interfere/landmines/configs/recommended.json"]
}

    .oxlintrc.json に書きます。10 ルールすべてが error になります。

  3. または、必要なプラグインとルールだけを登録する

    {
  "jsPlugins": [
    { "name": "landmines-testing", "specifier": "@interfere/landmines/testing" }
  ],
  "rules": {
    "landmines-testing/no-test-doubles": "error"
  }
}

    既存のコードに入れる場合は、testing プラグインから始め、違反の多いファイルを許可リストに入れて段階的に減らす使い方が README の想定です。

README は、型レベルの問題（連鎖した型アサーション、安全でない辞書型、unknown の受け渡し）を扱う anti-slop との併用を勧めています。

10 — 注意点

  • 初版：npm のバージョンは 0.1.0（CHANGELOG は初回リリースの 1 件のみ）、リポジトリのコミットは 4 件です。ルールの追加や判定の変更が今後入る前提で、バージョンを固定して使うのが無難です。
  • 方針の強いルールを含む：no-comments と no-explicit-return-types は、一般的な TypeScript の慣習（理由を書くコメント、公開関数の戻り値の明示）と衝突します。recommended を使うと両方が error になるため、チームの方針と合わなければ個別に無効にする必要があります。
  • モックを使わない前提のテスト設計が必要：no-test-doubles は、実装をそのまま使い、外部通信は MSW で受けるテスト構成を前提にしています。外部 SDK を直接モックしてきたコードベースでは、テストの書き直しが必要になります。このルールには許可リストがありません。
  • 静的な判定の限界：どのルールも型情報を使わず、同じファイル内の AST と変数のスコープで判断します。別ファイルで定義したヘルパー経由の差し替えや sleep は検出されない場合があります。逆に、vi.useFakeTimers() がファイルのどこかにあれば、そのファイルの固定 sleep はすべて見逃されます。
  • テスト用ディレクトリ名の食い違い：colocated-tests と README は持ち主の tests/ ディレクトリを置き場所として認めていますが、test-file-names は tests/ と __tests__/ を拒否します。recommended で両方を有効にすると、実際に使えるのは単数形の test/ か、実装の隣だけです。
  • ファイルシステムを読むルール：colocated-tests、test-file-names、package-exports は package.json の位置を探したり import を解決したりするため、ファイルを読みます。エディタ上の未保存のバッファでは結果が変わる可能性があります。
  • Oxlint の JS プラグイン機能に依存：ESLint では使えません。@oxlint/plugins のバージョンは 1.81.0 に固定されています。
