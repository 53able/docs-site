1 — 概要

Pixel art VFX / Claude Code skill

pixelfx は、ピクセルアートのエフェクトとアニメーションを 画像ではなく JavaScript のコードとして持つライブラリです。炎、爆発、魔法、天候、UI、ピックアップ、小動物など 244 本のエフェクトが、1 本につき 1 ファイルで収録されています。ブラウザ上でそのまま再生でき、パレットの差し替え、左右反転、シード変更ができ、任意のゲームエンジン向けにスプライトシートとして書き出せます。

キャラクターが関わるエフェクトは、灰色のダミーキャラクターが演技します。振りかぶり、放ち、着弾で止まり、構えに戻る。的（わら人形）が殴られて揺れる。12 本の「ムーブ」はこれらのエフェクトをつないだ、振りかぶりから回復までの一連の攻撃です。

同梱の Claude Code スキルは、既存エフェクトの検索・利用・書き出しに加え、「下書きを描き、レンダリングし、目で見て、直す」という手順で新しいエフェクトを作らせます。方法論は Sprite Fusion の Hugo Duprez による記事「How to make (good) pixel art effects with Claude」に基づき、コアの粒子シミュレーションは同氏の MIT ライセンスのコードを改変したものです。

2 — 構成

リポジトリは、エフェクトを描くための小さなコア、エフェクト本体、確認と書き出しのためのツール、スキル、ギャラリーで構成されます。実行時依存はなく、開発依存も esbuild のみです。Node 18 以上で動き、GIF と MP4 のプレビューにだけ ffmpeg を使います。

1 フレームの描画経路

effect modulemeta と、draw(p, t, o) または create(o) をエクスポートする 1 ファイル
Painterローカル座標の描画命令を受け取り、配置・反転・回転してフレームへ書く。ディザ、半透明、シェーダー、加算光を持つ
frame { color, light }色のバッファと加算光のバッファ。Sprite Fusion の VFX と同じ形なので、両ライブラリが 1 枚のフレームに描ける
composite()背景色（または透過）の上に色を置き、光を加算して RGBA バイト列にする。putImageData で canvas へ
effect →(local px)→ Painter →(place / flip / angle)→ frame.color + frame.light →(composite)→ ImageData → canvas（image-rendering: pixelated で拡大）

3 — 仕組み

純粋エフェクト（pure）

draw(p, t, o) をエクスポートし、時刻 t だけからそのフレームを描きます。状態を持たないので継ぎ目のないループに向きます。ループ、オーラ、ポータル、滝、ビーム、小動物など。繰り返す粒子は cycle、動きは fly、ノイズは loopNoise と tileFbm で作ります。

シミュレーションエフェクト（simulated）

create(o) が { update(dt), draw(p), drawBack?(p) } を返し、粒子、破片、光源を 120 Hz 以上の固定ステップで進めます。火花が跳ね、煙が巻く挙動がフレームレートに依存しません。衝撃、爆発、呪文など多くのワンショットがこちらです。

原則内容
2 枚のバッファcolor は不透明・ディザ・真の半透明のピクセル。light は加算される発光。熱いものが熱く見えるのは light バッファの寄与
すべてシード付き乱数はエフェクトの seed からのみ取る。Math.random と Date は禁止。同じ 40 フレーム目は毎回同じ絵になる
ローカル空間(0, 0) がアンカー（足元、着弾点、松明の根元、銃口）。x 右、y 下、1 単位 = 1 px。方向のあるエフェクトは右向きに描き、配置・反転・回転は Painter が行う
スケールダミーキャラクターは 24 × 38 px。すべてのエフェクトはこの縮尺で、1 px 単位の細部まで描く。キャンバスは 96〜320 px 幅が多く、トランジションは 320 × 180
レイヤーdrawBack はキャラクターの後ろや床のリングの奥半分、draw はそれ以外。fx.draw(frame, "back") と "front" の間に自前のキャラクターを描ける
本物のスケルトンダミーは骨の長さが固定の 3D スケルトン。ねじり、屈伸、振り向きができ、奥行きで前後関係が決まる。Dead Cells のように少数のフラットな階調と 1 本の線で描画される。ポーズは 12 fps 刻み、粒子はフルレート
同じフレーム形状{ w, h, ox, oy, color, light } は Sprite Fusion の VFX と同じ。両者を 1 枚のフレームに重ねられる

エフェクトファイルの形

import { Particles, Lights, P, Rng, fit, sparkle } from "../../core/index.js";

export const meta = {
  name: "Spark pop", desc: "...", tags: ["impact"],
  size: [96, 72], origin: [48, 56],      // キャンバスと、その中のアンカー位置
  duration: 1.2, loop: false, fps: 30, bg: "ground",
  options: { palette: [/* 暗→明 */], seed: 1 },
};

export function create(o) {
  const C = fit(o.palette, 7), R = new Rng(o.seed);     // どんな長さのパレットでも 7 段に揃える
  const ps = new Particles({ rng: R, ground: () => 0 }), lights = new Lights();
  lights.add(0, -12, 40, C[4], 0.7, 0.4);
  for (let i = 0; i < 40; i++) {
    const a = R.range(0, Math.PI * 2), sp = R.range(80, 260);
    ps.spawn(P.SPARK, 0, -12, Math.cos(a) * sp, Math.sin(a) * sp - 60, R.range(0.2, 0.6));
  }
  let t = 0;
  return {
    update(dt) { t += dt; ps.update(dt); lights.update(dt); },
    draw(p) { if (t < 0.12) sparkle(p, 0, -12, 9 * (1 - t / 0.12), C[5], C[3]); ps.draw(p); lights.draw(p); },
  };
}

粒子の種類（P.SPARK、MOTE、VAPOUR、SMOKE、FIRE、BRAND、GRIT、EMBER など）、剛体の破片 Bits、燃え広がる Blazes、光源 Lights、そして sparkle、flare、band、crystal といった定型描画は src/core/sim.js にまとまっています。重力は 950 px/s² で、Hugo Duprez のコードがワールド単位（1 px = 2 単位）なので、移植時は速度と距離を半分にします。

5 — ゲームで使う

ブラウザゲーム: コードをそのまま使う

npm には公開されていません。npm i github:patch-gg/pixelfx で GitHub から入れるか、src/core と必要なエフェクトのファイルをコピーします。package.json の exports は pixelfx（コア）、pixelfx/fx/*、pixelfx/core/* を公開しています。

import { createFrame, clearFrame, createFx, composite } from "pixelfx";
import * as frostNova from "pixelfx/fx/ice/frost-nova";

const frame = createFrame(320, 180);                   // ゲームのピクセル解像度。ox, oy でカメラに合わせてスクロール
const img = new ImageData(320, 180);
const fx = createFx(frostNova, { x: 160, y: 140 });   // flip, angle, seed, palette, light ... も指定できる

function tick(dt) {
  fx.update(dt);
  clearFrame(frame);
  fx.draw(frame, "back");                              // キャラクターの後ろに来るもの
  drawCharacters();                                    // 自前のスプライト（frame.color に直接描いてもよい）
  fx.draw(frame, "front");
  composite(frame, img.data, backgroundColor);         // 色を置き、その上に光を加算。null で透過
  ctx.putImageData(img, 0, 0);                         // canvas は image-rendering: pixelated で拡大する
  if (fx.done()) removeIt();                           // ワンショットは自分で終わる。fx.stop() でループをフェードアウト
}

複数のエフェクトは 1 枚のフレームを共有できます。WebGL エンジンでは合成後の RGBA を毎フレームテクスチャに転送するか、一度スプライトシートに書き出して通常のアニメーションとして再生します。

オプション意味
x、yフレーム内の配置位置（アンカーが来る場所）
flip左右反転。方向のあるエフェクトは右向きが既定
angle回転
seed別の乱数列。同等だが違う 1 本になる
palette暗→明の hex 配列。src/core/color.js の PAL には fire、ember、lava、smoke、ice、water、electric、poison、holy、arcane、shadow、blood、gold、neon、cyber、matrix、candy、night など 27 本の既製ランプがある。他のカラーランプ系オプションも同様に再サンプリングされる
light発光の強さ（0..1 以上）
エフェクト固有各ファイルの meta.options（size、count、radius、text、height など）

他エンジン: スプライトシートを書き出す

node tools/render.mjs ice/frost-nova --sheet     # records/ice/frost-nova/frost-nova.png + frost-nova.json
node tools/render.mjs fire --sheet               # カテゴリ全体
node tools/sheets.mjs                            # 全ライブラリを sheets/ へ（sheets/index.json 付き）
node tools/sheets.mjs fire ice                   # 一部のカテゴリだけ

# コードを触らずにリカラーして GIF を確認
node tools/render.mjs fire/torch --gif --opts '{"palette": ["#102","#215","#43a","#8cf","#cff","#fff"]}'

PNG は透過の全フレームをグリッドに並べたもの、JSON は Aseprite 形式（フレーム矩形と表示時間）です。meta.pixelfx に fps、loop、フレームサイズ、列数、ピボット、アクトのタイミングが入ります。Phaser のアトラスローダー、Godot と Unity の Aseprite インポーターがそのまま読みます。

取り込み時の設定。 ピボットは meta.pixelfx.pivot（足元などエフェクトの原点）に合わせ、最近傍フィルタ・圧縮なしで読み込み、meta.pixelfx.fps で再生します。発光はアルファ付きの色としてシートに焼き込まれるため、暗い背景では加算光のように見えますが、明るい背景ではリカラー版を作るか暗いレイヤーに置きます。

6 — アクト（演技）

エフェクト単体では「シール」のように見えます。殴った感じを作るのは周囲の身体の動きです。0.3.0 では、キャラクターが関わる 61 本のエフェクトと 12 本のムーブが、export const act で「身体が何をいつするか」を持つようになりました。初回リリースへの反応にあった「予備動作と硬直がない」という指摘への回答です。

t < 0構え、振りかぶり。負の時刻はエフェクト開始前の予備動作
t = 0エフェクトの最初のフレーム。放つポーズに "snap" で切り替え
hit.t着弾。stop 秒だけ全体が止まり、shake 秒揺れる。的が push で押され、skin で色が変わる
followフォロースルー。行き過ぎてから戻る
recovery構えに戻る。ワンショットのアクトは最後のキーまで続く
export const act = {
  target: { x: 58 },                 // 的の位置。targets: [...] で複数
  poses: [
    [-0.55, GUARD],                  // エフェクトより先に始まる
    [-0.3, WIND_UP],
    [0, CUT, "snap"],                // "snap": 直前のポーズを保持し、このキーで一気に切り替え
    [0.06, FOLLOW_THROUGH, "snap"],
    [0.86, GUARD],
  ],
  hits: [{ t: 0.06, stop: 0.14, shake: 0.18, amp: 2, push: 2.8, straw: 18 }],   // 着弾で 0.14 秒停止
};
要素内容
poses[時刻, ポーズ, 補間] の配列。ポーズは立ち姿との差分だけを書く（crouch、lean、近い手 fx, fy、遠い手 bx, by、足 ffx, fbx、turn、yaw、weapon と角度 sa、two、ghost など）。手足の位置を与えると肘・膝・背骨はスケルトンが解く。補間は "snap"、"out"、"in"、"line"
hitst で stop 秒の停止（ヒットストップ）、shake 秒 × amp px の揺れ、的への push（負なら術者側へ）、straw、flash、skin（char、ice、shock、holy、shadow、red、poison）、shiver。複数の的は at で選ぶ
dust踏み込みの土煙。t、x、n、dir
onBody: trueエフェクトが o.actor（キャラクターのマスクとピクセル）を読む場合。立ち姿に対して描けば、各ポーズのピクセルが元の立ち姿のどのピクセルかを知っているので、霜や毒やスキャンラインが身体に追従する
武器sword greatsword dagger spear hammer scythe claw bow pistol launcher handle。腕は肩から約 15 px しか届かず骨は伸びないので、無理をさせず身体を一歩踏み込ませる。振りでは刃が手に遅れて鞭のようにしなる

ダミーキャラクターごと再生する

import { createFrame, clearFrame, createAct, composite } from "pixelfx";
import * as slash from "pixelfx/fx/melee/sword-slash";

const act = createAct(slash, { x: 80, y: 140 });

function tick(dt) {
  act.update(dt);                                  // ヒットストップ中は自分で止まる
  clearFrame(frame);
  act.draw(frame);                                 // { body: false } や { target: false } で省略できる
  composite(frame, img.data, backgroundColor);
  const [sx, sy] = act.shake;                      // 画面をこれだけずらす
  ctx.putImageData(img, sx, sy);
}

自前のキャラクターに合わせる

エフェクトの id は変わっておらず、スプライトシートはエフェクト単体のままなので、既存のゲームはそのまま動きます。タイミングは slash.act、またはシートの JSON の meta.pixelfx.act（windup、recovery、hits の t と freeze、poses）として読めます。自前の攻撃アニメーションを windup 秒前に始め、各ヒットでエフェクトもキャラクターも freeze 秒止めます。ホスト側のヒットストップは、アクトの有無によらず任意のエフェクトに使えます。

身体そのものも使えます。skeleton(pose) はポーズの全関節を 3D で返し、posedParts(pose) は各パーツを個別に描画したものを返します。node tools/act.mjs <id> --sheet はキャラクター込みのアクト全体をスプライトシートに焼きます。

身体の上に描くエフェクトはダミーキャラクターを塗ります。 frozen や poisoned のように o.actor を読むエフェクトのスプライトシートには、灰色のダミーの色が焼き込まれています。自前のキャラクターで出荷する場合は、自分のゲーム側で再生成するか、コードで再生してください。

7 — Claude Code スキル

skills/pixelfx/SKILL.md は、Claude Code にエフェクトの検索・利用・書き出し・制作を教えます。プラグインとして入れるか、skills/pixelfx を ~/.claude/skills/ にコピーします。

/plugin marketplace add patch-gg/pixelfx
/plugin install pixelfx@pixelfx

スキルは最初に pixelfx のチェックアウトを要求します。作業ディレクトリに tools/render.mjs がなければ git clone https://github.com/patch-gg/pixelfx し、node tools/render.mjs fire/torch が records/fire/torch/contact.png を書き出すことを確認します。以後、このコンタクトシートを画像として読むのがエフェクトを「見る」手段になります。

1. 既存を探す

node tools/list.mjs <words> で id、名前、タグ、説明を検索し、候補をレンダリングして見てから選ぶ。多くの依頼は既存エフェクト + オプション変更で済む

2. ゲームに入れる

JS/TS の canvas・WebGL ゲームにはコードを、他エンジンにはスプライトシートを。ムーブの依頼は src/fx/moves/ から始める

3. 新しく作る

docs/AUTHORING.md を読み、1 行で言い切り、参照を探し、下書きし、見て直し、アクトを付け、検査する。詳細は次節

4. ネイティブに移植

JS を実行できず、シートでも足りない場合（追尾や実行時の色変更）はエフェクトを移植する。2 バッファ、4×4 Bayer のディザ、ランプ参照を保ち、JS 原版と並べて確認する

想定している依頼の例

  • 「魔法使いの必殺技にフロストノヴァを付けて」
  • 「コイン取得のきらめきを 5 案作って、良い 2 つを見せて」
  • 「fire と explosions カテゴリを Godot 用のスプライトシートで書き出して」
  • 「このヒットエフェクトが軽い。もっと手応えを出して」
  • 「この呪文に振りかぶりを付けて、敵がリアクションするようにして」
制約。 方向のあるエフェクトは右向き、地面のエフェクトは y = 0 に立ち、キャラクター系は o.actor を包み、Math.random は使いません。一般的なモチーフは自由ですが、特定のゲームのスプライト、キャラクター、ロゴを再現しないことがスキルに明記されています。

8 — 自作の手順

node tools/new.mjs arcane/my-spell       # 動くひな形（ループなら --loop）。一度レンダリングもする
node tools/render.mjs arcane/my-spell    # records/arcane/my-spell/contact.png を見る
node tools/check.mjs arcane/my-spell     # はみ出し、継ぎ目、シードなし乱数、遅いフレームを検出

node tools/render.mjs arcane/my-spell --all --zoom 3   # 全フレーム、3 倍
node tools/render.mjs arcane/my-spell --gif --mp4      # 動きを見る（ffmpeg が必要）
node tools/act.mjs arcane/my-spell                     # 12 fps の連続コマでアクトを見る
node tools/compare.mjs "arcane/my-spell-*"             # 複数の下書きを横並びで比較
1 行で言い切る→参照を探す（list.mjs / Hugo の作例）→下書き 3〜5 案→見て、最悪の点を直す（3 周以上）→アクトを付ける→check.mjs が通るまで

契約（AUTHORING.md より）

  • ワンショットは 0..duration で動き、t = duration で何も描かない（最後の煙が消えるまで duration を取る）。ループは継ぎ目なし。
  • o.palette と o.seed を尊重する。fit(o.palette, n) でどんな長さのパレットでも n 段に揃える。x、y、flip、angle、light は予約済み。
  • キャラクター系（actor: 2）は o.actor = { mask, pixels, x, y, w, h, head, chest } を受け取る。消えたり現れたりするなら actorAlpha(t, o) をエクスポートする。
  • Hugo Duprez のファイルから特定のレシピを借りたら、ファイル先頭に 2 行のクレジットを書く。
  • 基準となる 3 本: melee/sword-slash、ice/frost-nova、explosions/small-explosion。

品質基準

基準内容
線と光、塗りではなく1 px の縁、リング、軌跡、火花で組み、明るさは光に任せる。彩度の高い大きな面はほぼ誤り。白熱は芯と縁だけ
光をあらゆる場所に低い k の大きな光だまり、芯の強い光、火花ごとの光、着弾の瞬間に閃いて落ちる Lights、床の暖色・寒色の照り返し
半透明の体積煙、蒸気、塵、霧は SMOKE、VAPOUR、DUST、p.disc で柔らかく。煙にディザの市松模様は使わない
本物の動き火花は速度で伸び、落ちて跳ねる。破片は転がり、跳ね、止まり、消える。着地は土煙を上げる。速い放出、遅い漂い
段階のある振付予備動作（集まる）、放出（1〜2 フレームの白いヒーローフレーム、閃光）、拡散、保持（きらめき）、崩壊、長い減衰
タイミング速い立ち上がり、遅い消え方。大技は 2〜4 秒残り、ヒットは 0.3〜0.8 秒で切れ味を保ちつつフォロースルーを持つ
1 倍で読める焦点が 1 つ、形の中にノイズの斑点がない
クリーンキャンバスに収まり、空で終わるかきれいにループし、決定的で、1 フレーム 2 ms 未満（tools/check.mjs）

見た目の症状と直し方（抜粋）

見える症状直し方
1 倍で泥のように見える色数を減らす、輪郭をはっきりさせる、焦点を 1 つに、形を大きく
浮ついて手応えがない速く入って遅く抜ける（ease.outQuart / outExpo）、1〜2 フレームの白いヒーローフレーム、全体を短く
硬く機械的粒子ごとにサイズ・速度・遅延・寿命を変える。火花、煙、破片の二次的な動きを足す
白く飛んでいる発光を弱める（k 0.2〜0.5）、縁の段を暗く、白は最も熱い芯だけ
ループの継ぎ目cycle、loopNoise(phase)、セル単位の tileNoise スクロール、sin(phase * TAU * n)
良いエフェクトなのにキャラクターが死んでいるアクトを付ける: 振りかぶり、放つポーズ、着弾の停止、反応する的、回復
アクトに重さがない打つ方向と逆の振りかぶり、長めの停止（最大 0.2 秒）、大きな輪郭の変化、揺れ
腕が交差する、ポーズが平板キャラクターは斜め前を向いている。開いた腕では近い手を左（fx < 0）、遠い手を右に置き、turn: 1。yaw で本当に身体を回す

9 — ツール一覧

すべて node tools/<name>.mjs で実行する Node スクリプトです。インストール手順はなく、GIF と MP4 の生成だけ ffmpeg に依存します。

ツール用途主なオプション
render.mjsコンタクトシート（records/<id>/contact.png）、GIF、MP4、スプライトシートを生成。id、カテゴリ、"magic/portal*" のようなパターンを受ける--gif --mp4 --sheet --all --max N --zoom N --scale N --bg dark|ground|sky|light|black|none --seed N --fps N --opts JSON --out DIR --no-actor --loops N
act.mjsアクトを 12 fps の連続コマ（records/act/）、MP4、キャラクター込みのスプライトシートとして出力--from S --to S --step S --cols N --zoom N --bg --out --no-target --seconds S --mp4 --sheet
check.mjsmeta の欠落、キャンバス外描画、空で終わらないワンショット、ループの継ぎ目、シードなし乱数、遅いフレーム、アクトのキー順序・不明なポーズ項目・手の瞬間移動を検査。引数なしで全件id またはカテゴリを列挙
sheets.mjs全エフェクト（または指定カテゴリ）のスプライトシートを sheets/ に書き出し、sheets/index.json を作るカテゴリ名を列挙
list.mjsid、名前、タグ、説明を単語で検索。引数なしで全件検索語
new.mjsテンプレートから src/fx/<category>/<name>.js を作り、一度レンダリングする--loop
compare.mjs複数の下書きを 1 行 1 エフェクトで、同じ時刻を列に並べて比較（records/compare.png）--frames N --out FILE
montage.mjs多数のエフェクトを同時再生するグリッド動画。README やポスト用--ids --category --pick N --cols --rows --cell WxH --scale --seconds --fps --bg --stagger --rest --gap
index.mjsエフェクトファイルから登録表 src/fx/index.js、docs/CATALOG.md、README の件数とカテゴリ表を再生成なし
serve.mjsリポジトリを配信し、ローカルのギャラリー（http://localhost:8080/gallery/）で自作エフェクトも含めて確認ポート番号
build-gallery.mjsギャラリーを dist/gallery（静的サイト）と dist/page（1 ページ + 1 スクリプト、フォント内蔵）にバンドルなし

10 — ギャラリーと公開

公開ギャラリーは patch-gg.github.io/pixelfx です。全エフェクトを再生し、リカラーと反転を試せます。GitHub Actions の gallery.yml が main への push ごとに、依存の導入、全件の check.mjs、ギャラリーのビルド、GitHub Pages へのデプロイを行います。

push to main→npm ci（Node 22）→node tools/check.mjs→node tools/build-gallery.mjs→upload-pages-artifact（dist/gallery）→deploy-pages

検査が通らなければビルドに進みません。ローカルでは node tools/serve.mjs を起動し、http://localhost:8080/gallery/ を開くと、自分が追加したエフェクトもギャラリーに表示されます（登録表の更新に node tools/index.mjs が必要です）。

11 — ライセンスと注意

  • ライセンスは MIT です。 コードもエフェクトも、商用を含め何にでも使えます。
  • 改変元のクレジットがあります。 src/core/sim.js と、ファイル先頭に明記されたエフェクトは Sprite Fusion（Hugo Duprez、MIT）の公開 VFX を改変しています。src/core/act.js のポーズ再生、ヒットストップ、ばね状の的は Hollow Crown（rehan-remade、MIT）の実装を改変しています。詳細は NOTICE.md。
  • ギャラリーのフォントは MIT の対象外です。 gallery/fonts の Patch Pixel は Patch 自身のフォントで、リポジトリの MIT ライセンスには含まれません。gallery/fonts/NOTICE.md を確認してください。
  • npm には公開されていません。 npm i github:patch-gg/pixelfx か、ファイルのコピーで導入します。
  • プロジェクトは新しいです。 最初のコミットは 2026-10-29、0.3.0 は 2026-10-31 で、本ページ作成時点のコミット数は 8 です。API や act のデータ形式は今後変わる可能性があります。
  • 身体の上に描くエフェクトのシートはダミーの色を含みます。 自前のキャラクターで出荷する場合は該当エフェクトを再生成してください（アクトを参照）。
  • GIF / MP4 には ffmpeg が必要です。 コンタクトシート、スプライトシート、検査は Node だけで動きます。
  • スキルは特定ゲームの再現を禁じています。 一般的なモチーフは可、既存ゲームのスプライト、キャラクター、ロゴの再現は不可です。
