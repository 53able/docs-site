OpenFilm

openfilm/openfilm · 動画を HTML で書く形式・CLI・ローカル編集アプリ · npm openfilm 0.3.2 · MIT

01 — コーディングエージェントに動画を作らせ、人が編集する

FILM = WEB PAGES

映像を Web ページとして書き、
ブラウザ上の編集アプリで仕上げる。

OpenFilm は、Claude Code や Codex などのコーディングエージェントに動画を作らせるためのオープンソースのツール群です。エージェントは映画を film.html と複数の HTML ページとして書き、ローカルで動く編集アプリ Studio がその変化をブラウザに表示します。完成後は、手作業でもエージェントへの依頼でも、テキスト・配置・クリップを変更できます。

README は特徴を 3 つにまとめています。1 つの HTML ファイル（film.html）、1 つの関数（各ページの frame(t)）、実用的な編集アプリ（Studio）です。Remotion や HyperFrames のような専用フレームワークは使わず、エージェントが既に知っている HTML・CSS・JavaScript だけで書きます。

02 — 依頼から書き出しまでの流れ

依頼（「20 秒の紹介動画を」）→ openfilm open→ film.html と各ページを書く→ openfilm look で検査→ Studio で手直し→ openfilm render

  1. エージェントがプロジェクトを開く

    エージェントは最初に openfilm を実行して説明（MANUAL.md）を読み、openfilm open <フォルダ> で映画用のフォルダを作ります。表示された Studio のアドレスを、何かを書く前にブラウザで開いておくよう指示されています。人は変更が反映されていく様子を見ながら、同時に編集もできます。

  2. 映画を Web ページとして書く

    編集の骨格は film.html、各ショットは独立した HTML ページです。素材は assets/ に置きます。音楽・効果音・トランジションなどは openfilm get で無料ライブラリから取得できます。

  3. 描画結果を確認する

    openfilm look がコンタクトシートや指定フレームを画像として保存します。エージェントはその画像を読んで各ショットを確認するよう、スキルで求められています。

  4. 人が Studio で直し、書き出す

    Studio での変更は映画のファイルに保存されるため、エージェントは次の編集でその変更を読み、保持します。最後に openfilm render で MP4 などに書き出します。

人とエージェントが同じファイルを編集します。 Studio の操作結果は film.html の属性（位置・CSS・overrides）として書き込まれます。エージェントは変更前に film.html を読み直し、意図した箇所だけを変えるよう指示されています。

03 — 導入

  1. 必要な環境を用意する

    Node 22.2 以上と ffmpeg（macOS / Windows / Linux）。Studio の版の保存を使う場合は git も必要です。初回実行時にヘッドレス Chromium（約 100 MB）がダウンロードされます。

  2. エージェントにスキルを入れる

    npx skills add openfilm/openfilm

    あとはエージェントに「音楽付きで、CLI の 20 秒の紹介動画を作って」のように頼みます。スキルを扱えないエージェントには「npx -y openfilm@latest を実行して、表示される指示に従って」と伝えます。

  3. デスクトップアプリを使う（任意）

    openfilm.dev または Releases から macOS / Windows 版を入手できます。ffmpeg とヘッドレスブラウザを同梱しているため、追加のインストールは不要です。

  4. サンプルから始める（任意）

    npx -y openfilm@latest open https://github.com/openfilm/examples/tree/main/one-prompt

    GitHub 上の映画（リポジトリまたは …/tree/main/<フォルダ>）はプロジェクトライブラリにコピーされてから開かれます。

映画の作成・編集・レンダリングにアカウントは不要で、OpenFilm のライブラリ（音楽・効果音・音声・ステッカー・トランジション・エフェクト・テンプレート）は無料で使えます。音声・音楽・画像・動画を生成する場合は、ElevenLabs、OpenAI、Google、OpenRouter、fal などに自分のキーで接続するか、Studio の Settings → Services で OpenFilm にサインインします。

04 — film.html：トラックとクリップ

映画は film.html を持つフォルダです。<section> 1 つが 1 トラック、その中の要素 1 つが 1 クリップです。

<meta name="viewport" content="width=1920, height=1080">
<style>
  .card { object-fit: cover; border-radius: 24px; }
</style>
<section>
  <iframe src="title.html#t=0,4"></iframe>
</section>
<section>
  <video src="assets/footage.mp4#t=12,18" at="4" speed="0.5" class="card"
         style="left: 160px; top: 90px; width: 1600px; height: 700px"></video>
</section>
<section>
  <audio src="assets/music.mp3" volume="0.6"></audio>
</section>
クリップの主な属性（SPEC.md §1 より）
属性意味
src と #t=in,outファイルと、その何秒目から何秒目を使うか（メディアフラグメント）。静止画と duration を持たないページは長さを決められないため、#t=0,長さ が必須
at映画上の開始秒（省略時 0）。時刻はミリ秒単位に丸められる
speed / volume映像と音のみ。速度は 0.1〜100 でピッチは維持。音量は 1 が元の大きさ
style の left / top / width / height / rotate配置。これ以外の CSS（position、transform、margin など）でクリップを動かすとエラー
class と残りの style見た目（角丸、clip-path、filter、opacity など）。動きは CSS アニメーションで書き、translate / scale / rotate を使う。transition はエラー
overridesStudio で人が加えた変更（JSON）。ページ内要素の移動・文字・スタイル、クリップのフェードなど。エージェントはそのまま残す
disabled / トラックの hidden / muted / lockedクリップの無効化、トラックの非表示・消音・ロック。locked のトラックはエージェントが変更しない

読み取りは厳格

綴りを誤った属性や想定外の要素は無視されず、行番号付きのエラーになります。リファレンス実装は src/film-doc.mjs です。

属性はほとんど増えない

見た目は CSS、タイトルはページ、トランジションはページか重ねたクリップのフェードで表します。属性が増えるのは、それ以外で表せない場合だけです。

音はすべてクリップ

ページは音を持ちません。効果音もナレーションも <audio> か <video> の音として配置し、ミックスと書き出しはホストが行います。

字幕は WebVTT

音声と同名の .vtt（vo/1.wav → vo/1.vtt）が書き起こしです。画面上の字幕は <track kind="captions"> のトラックで表し、ページに字幕を描かない決まりです。

05 — ページと「1 つのルール」

ページは、任意の時刻の絵を描ける Web ページです。window.film オブジェクトを 1 つ公開することだけが決まりで、描画には three.js、WebGL、canvas、SVG、CSS、GSAP など何を使っても構いません。

<script type="module">
window.film = {
  frame(t) { /* t 秒時点の絵を丸ごと描く。Promise を返してもよい */ },
  duration: 4,               // 任意：ページ自身の長さ（秒）
  ready: loadFonts(),        // 任意：フォント・画像・モデル・データの読み込み
  width: 480, height: 320,   // 任意：画面の一部だけを描くページ
};
</script>
同じ t なら、それまでに何を描いていても同じ絵を描く。 フレームは順不同・並列で要求され、モーションブラーのためにフレームの間の時刻も要求されます。このルールを守ったページは、どのサイズでも、どのマシンでも同じ結果になります。

ホストは描画中、ページ内の時計を t に固定します。performance.now()、requestAnimationFrame のタイムスタンプ、Date（2026-01-01T00:00:00Z 起点）、CSS アニメーション、Math.random（t をシードに再初期化）はすべて t と一致します。タイマーと描画の履歴は一致しません。

ルールを守るための書き方（SPEC.md §3）
避ける代わりに
NGx += v のような呼び出しをまたぐ累積OK毎回すべて描き直す。軌跡や物理演算は t から計算するか、ready 中に事前計算して参照する
NGGSAP の to / fromOK開始値と終了値を明示する fromTo。最初の実行時の値を記録する Tween は描画順に依存する
NG独自の時計で動くライブラリをそのまま使うOKtimeline.seek(t)、animation.currentTime = t * 1000、video.currentTime = …（seeked を待つ）などで t から駆動する
NG自走するループや自動再生OKwindow.filmHost があるときは自分で進めない。無いとき（普通に開いたとき）だけ自分で再生する
NGWebGL を既定設定で作るOKpreserveDrawingBuffer: true で作成し、frame 内で描く。そうしないとクリア済みのバッファが取り込まれることがある

スキル edit は、1 ページ 1 ショットにすること、人が変更しそうなものは画像ではなく DOM 要素にすることも求めています。Studio はピクセルではなく要素を編集するためです。Python、Blender、動画生成モデルなど、ブラウザ以外で作った絵は動画か画像として取り込みます。

06 — コマンド

通常はエージェントが実行しますが、npx -y openfilm@latest <command> または npm i -g openfilm で人も使えます。各コマンドの --help でオプションを確認できます。

openfilm のコマンド
コマンド内容
openfilm映画とは何かと、同梱スキルの一覧を 1 ページで表示。エージェントの出発点
open [folder | url]Studio で映画を開く。新規・既存・GitHub 上の映画。引数なしなら現在の映画か最後に開いた映画
look [what] [t | a-b]映画・ページ・メディアファイルを確認する。コンタクトシート、1 フレーム、範囲。レンダー後は --full で全フレームの白飛び・コマ飛び・静止・黒画面を調べ、--loudness=-14 で目標ラウドネスとの差を出す
render [a-b]MP4 を書き出す。--4k、--blur（モーションブラー）、--alpha（.webm / .mov）、--loudness=-14。中断したレンダーは同じオプションで再実行すると続きから描く
get [what]素材を取得する。まず OpenFilm の無料ライブラリ（CC0、オフライン）を探し、なければ接続済みのサービスで生成する
canvas [apply <steps>]編集画面の横にあるキャンバスを読む、またはノート・ファイル・生成ノードを配置する
skills / skill <name>使えるスキルの一覧と、1 つのスキルの本文を表示する
doctorこの環境で OpenFilm が使えるかを出力する。Issue に貼るための情報

look が調べること

README は「モデルが失敗しやすい検査に力を入れている」と説明しています。look はコンタクトシートの各フレームを、シャッフルした 2 通りの順序で 2 回ずつ描き、結果が変わったフレームを報告します。あわせてページのエラー、読み込みに失敗したフォント、見つからない音声ファイル、画面からはみ出した文字も報告します。

07 — Studio とデスクトップアプリ

Studio は手元のマシンで動き、ブラウザで開く編集アプリです。映画の描画と書き出しに使うエンジンと同じ Chromium 系ブラウザ（Chrome、Edge）を使うと、プレビューと書き出し結果が一致します。

EDIT

編集できるもの

画面内の文字とレイヤー、タイムライン上のクリップの位置・見た目・音量・速度、字幕。名前を付けた版を保存して戻ることもできます（git を使用）。

EXPORT

書き出せるもの

動画、GIF、音声とステム、字幕、静止画、スライド、透過動画。タイムライン自体を Final Cut Pro、Premiere Pro、DaVinci Resolve、剪映 / CapCut 向けにも書き出せます。

CANVAS · ⌘E

キャンバス

編集画面と切り替えて使うボード。ノート・画像・クリップ・ナレーション・音楽を並べて結線し、接続済みのサービスで生成して、順にタイムラインへ送ります。ストーリーボードとしても表示できます。

LIBRARY

ライブラリ

素材ドロワーに映像・音声・効果音・音楽・テキスト・ステッカー・フィルター・エフェクト・トランジション・テンプレート、そしてスキルが入っています。

デスクトップアプリで使えるエージェント

デスクトップアプリ（apps/desktop）は Studio の横にチャット欄を置いた Electron アプリです。ソースの定義では、Codex、Claude Code、GitHub Copilot、Cursor、OpenCode、CodeBuddy、Qwen Code、Kimi、MiniMax Code、DeepSeek Harness、Google Antigravity のほか、OpenFilm 自身のエージェントと、自分の API キーを使う方式（Own key）が並んでいます。

08 — 作り方はスキルに書かれている

OpenFilm は、映画の作り方をツール本体ではなくスキルに置いています。openfilm が表示するのは概要 1 ページだけで、詳細はタスクに応じて openfilm skill <name> で読み込みます。

同梱スキル（packages/openfilm/manual）
スキル読むタイミング主な内容
edit映画・film.html・ページを作る、変える、確認する前プロジェクトの構成、トラックへのクリップの置き方、ページの書き方、look での確認。確認する前に「動く」「良く見える」と言わないこと
media音楽・効果音・トランジション・テンプレートなどを足す前、ナレーション・画像・動画・書き起こしを作る前まず無料ライブラリを get … --prompt で探し、--take <id> で取り込む。生成は接続済みサービスで行い、動画生成は高額なため Studio で人の確認を得る
canvasキャンバス、ストーリーボード、キャラクター、ショットの配置を頼まれたときショットごとの行の並べ方、同じ人物を保つための参照画像の結線、ナレーションノードの設定。生成ボタンは原則として人が押す

それ以外のスキルは「ある種類の映画の作り方」で、owner/name の形の名前で識別されます。Studio のライブラリの Discover に、openfilm/skills の公式・コミュニティのスキルが並びます。インストールせずに会話で試すこと、リンクやフォルダから追加すること（openfilm skill add <link>）もできます。インストールしたスキルはすべてのエージェントに提示されます。

項目内容
