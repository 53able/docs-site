1 — 概要

Agent skills / Design

ai-design-skills は、Claude Code、Cursor、Codex、Windsurf など、Markdown のルールファイルを読むコーディングツール向けのデザインスキル集です。各スキルは独立したフォルダで、必要なものだけを導入します。

現在の収録は 2 本です。landing-page-design はランディングページを、ヒアリングからページ構成、コピー、視覚ルールまで一貫した手順で作ります。design-to-motion は Figma フレームなどの静的デザインを、元と同じ見た目の HTML として再構築し、読み込みアニメーションとループ動画に変換します。

3 — landing-page-design: 戦略と構成（Part A）

前提は「ランディングページはホームページではない」です。1 つのオファー、1 つの対象者、1 つの主要アクションに絞ります。Part A で何を言うかと構成を決めてから、Part B の視覚ルールに進みます。

A1 ヒアリング→A2 ページ構成→A3 レイアウト選択→A4 コンバージョン規則→A5 コピー→A6 構築順→A7 SEO / AEO

A1 ヒアリング

目的（主要アクション、オファー、何をコンバージョンとするか）、対象者と文脈（ICP、課題、上位 3 つの反論、流入元、来訪時の前提知識）、証拠と素材（ロゴ、推薦文、数値、スクリーンショット、保証）、制約（ブランドの声、デザインの方向性、モバイル優先か）を集めます。足りない項目だけを 1 回でまとめて聞き、答えが無ければ仮定を 1 行で宣言して進めます。

A2 ページ構成

ファーストビュー（必須）

1–5

  • 成果と対象者を示す見出し
  • 方法を具体化するサブ見出し
  • 主要 CTA（動詞 + 得るもの）
  • 証拠シグナル 1 つ
  • 製品画像・動画
中盤（主張）

6–9

  • 課題から解決へ
  • 成果ベースの利点 3〜5 個
  • 使い方 3 ステップ
  • 推薦文・事例
終盤（反論処理）

10–12

  • FAQ 6〜12 問
  • リスク解消（試用、解約自由、保証）
  • 冒頭と同じ最終 CTA

中盤には、B11 のタグライン表示セクションを必ず 1 つ入れます。

A3 レイアウト選択

型使う場面
A. 標準ヒーロー + セクションヒーローのスクリーンショットで製品が伝わる。最も一般的
B. 長文ストーリー教育して懐疑を解く必要がある
C. 最小コンバージョンページ既存ユーザーへのメールなど意図の強い流入、ダウンロードや waitlist のような短いオファー
D. 比較ページ「X vs Y」「best for」のような代替検索の意図がある。SEO ページと組み合わせることが多い

A4〜A7 の要点

  • 流入元とメッセージを合わせる。 広告からの流入なら、広告の見出しをヒーローに反映します。
  • ファーストビューの CTA は 1 つ。 競合する CTA を並べません。
  • 具体的に書く。 「時間を節約」ではなく「週次レポートを 4 時間から 15 分に」のように書きます。
  • CTA は動詞 + 得るもの。 「Learn more」「Submit」は使いません。
  • セクション単位で作る。 ヒーロー → 利点 → 使い方 → 証拠 → FAQ → 最終 CTA の順で、毎回ページ全体を作り直しません。
  • インデックスの判断。 広告専用や期間限定のページは noindex、検索意図と一致する常設ページはインデックスし、FAQ を AEO 向けの問答形式にします。

コードを書く前の出力

新規作成では、ページ概要、ヒーローのコピー、利点、使い方 3 ステップ、FAQ、SEO / AEO の推奨、レイアウト型とその理由の 7 点を先に提示してから、セクションごとに実装します。

4 — landing-page-design: 視覚ルール（Part B）

すべての視覚的な値を、その場で考えずに以下の規則から決めます。適用範囲はランディングページに限らず、Web UI 全般（コンポーネント、ダッシュボード、プロトタイプ、デザインレビュー）です。フレームワークの既定値と衝突した場合はスキルが優先し、ユーザーの明示的な指示とはユーザーが優先します。

項目規則
B1 書体Geist、Manrope、Geist Mono、Poppins を使う。Inter、Roboto、Arial、Open Sans、Helvetica は禁止。イタリック禁止、900 / black の極太禁止。1 サイトにつき書体は 1 つ（コードや数値 UI の Geist Mono は可）
B1 コピー本文・見出し・ラベルにハイフンを使わない。最終行に 1 語だけ残さない（見出しは text-wrap: balance、本文は pretty）
B1 文字サイズTailwind 標準のタイプスケールに揃える。任意値はひとつ下の段に寄せ、行高も段の値を使う。主ボタンは text-base semibold
B2 余白0、2、4、8、12、16、24、32、40、48、64、80、96px のみ。主ボタンは縦 8px・横 12px
B3 角丸Tailwind の値のみ。入れ子の隙間が 32px 未満なら「内側 = 外側 − 隙間」（結果が 2 を超える場合のみ）
B4 枠線・背景カードの片側だけの枠線は禁止。背景のグラデーションは禁止。ダークモード背景は #000000、#181818、#1F1F1F、#272727、#313131、#131209 のみ
B5 ヒーロー見出しテキストのみ左→右グラデーション（ダーク #FFFFFF→#9B9B9B、ライト #000000→#666666）。見出しとサブ見出しの最大幅は 680px、意味の切れ目で改行する
B6 アイコンPhosphor、Solar、Iconamoon。Material Icons / Symbols は禁止
B7 モーション基本カーブ cubic-bezier(0.22,1,0.36,1)、配置変化は 500ms、ホバーの色・不透明度は 300ms（200ms 未満は禁止）。transform と opacity のみ動かす。スクロール表示は 32px 上昇 + フェードを 600〜800ms、1 回だけ。IntersectionObserver で発火し、間引きのない scroll リスナーは禁止。prefers-reduced-motion では不透明度の変化だけにする
B8 内容の現実味仮置きの文章を使わない。人名・ブランド名・数値を実在しそうな形にする（丸すぎる数値を避ける）。「revolutionize」「supercharge」「cutting edge」などの常套句を禁止。見出しとボタンは sentence case
B9 状態hover、active、focus、loading（実レイアウト形のスケルトン）、empty、error を全インタラクティブ要素に用意する。# へのリンクを残さない
B10 出荷要件プライバシーポリシーと規約のリンク、独自 404、フォームのクライアント検証、スキップリンク、Cookie 同意、favicon、メタタグ、alt、セマンティック HTML、全ページからの戻り導線
B11 タグライン表示（必須）ヒーローとは別に、2 行以上の大きな文字のセクションを置く。文字は 25〜35% 程度の薄い色で始まり、スクロールに合わせて 1 語ずつ読み順に本来の色へ変わる

5 — design-to-motion: 2 つの文脈

このスキルの原則は「ショーケースアニメーションは再デザインではない」です。見る人に、元と同じデザインが、生きて動いていることを見せます。

元と同じフレーム→空の状態→滑らかな読み込み→各ビジュアルのストーリー→継ぎ目のない反復

最初に、ショーケースか Web サイトかを決めます。サイトのコードベース内で作業していれば Web サイト、デザインだけがあればショーケースと判断し、それでも不明なら 1 回だけ確認します。

ショーケースWeb サイト
典型的な依頼「このデザインを動かして」、Figma リンクのみランディングページやサイトの構築・編集
動かす対象フレーム全体条件を満たすセクションのみ
開始ページ読み込み時、空の状態からセクションがスクロールで表示されたとき、1 回
読み込み後ストーリーを再生し、フレームが消えて周期を繰り返すストーリーを続ける。消失と周期はない
テキスト書き出したレイヤー画像（ピクセル単位で一致させるため）サイトのフォントによる HTML テキスト（SEO とアクセシビリティのため）
成果物ページ + MP4（X 用）+ Web 用 GIF + 800×500 GIFサイトのコード内のアニメーション。書き出しは依頼時のみ

Web サイトでの適用範囲

  • bento / 機能カード（テキスト + チャート、リスト、フロー等）: スクロール時にカードが入場し、各ビジュアルでストーリーを再生します。ランディングページでの主な用途です。
  • 製品・ダッシュボードのモックアップ: 面は残して中身を読み込む演出のみ。読み込み後のストーリーを付けるかはユーザーに確認します。
  • ロゴ列・連携一覧: マーキーか、控えめに光る演出。
  • テキストのみのセクション（見出し、推薦文、FAQ、料金、CTA、フッター）: 対象外。

6 — design-to-motion: 忠実度とモーション（Part A / B）

Part A — 元のデザインと一致させる

  • 情報源。 ノード ID 付きの Figma リンクが最適で、個人アクセストークンで REST API を使います。トークンは環境変数か OS のキーチェーンから読み、表示・貼り付け・コミットをしません。平面画像だけの場合は、分離できない部分をユーザーに明示し、スクリーンショットを 1 枚のまま動かしてごまかしません。
  • レイヤー書き出し。 動く要素はそれぞれ 3 倍の PNG として、1 回 20〜25 ID でまとめて書き出します。はみ出しや回転、インスタンスの子要素など、ケースごとの配置規則が表で定義されています。
  • 背景は変えない。 写真やテクスチャの背景は、イントロ、ループ、消失、ズームのどこでも動かさず、ぼかさず、色も変えません。元画像を取得し、PSNR 45 dB 超を目安に検証します。再現できない場合は作る前に伝えます。
  • レイアウトの判別。 サイドバーと本体のようにつながった面で構成される「アプリフレーム」では、面は最初から静止して存在し、中身だけが読み込まれます。bento のような「独立カード」では、カード自体が入場します。
  • 静止画の検証。 ?still を 2 倍で描画し、参照画像と PSNR で比較します（全体 35 dB 超、各コンテナ 30 dB 超が目安）。0.5px 未満のずれは追いません。

Part B — 読み込みの種類

入場は「下から上がり、ぼかしから鮮明に」が基本で、読み順にずらして再生します。フレーム全体のイントロは約 2〜2.5 秒です。

種類対象開始状態
card独立カード全体（影ごと）translateY(24px)、scale(0.985)、blur(6px)、不透明度 0
up / down / leftテキスト・値・行 / 上部ツールバー / サイドバー項目10px / −8px / −10px の移動 + blur(4px)
popアイコン、バッジ、アバター、ボタン自身の中心から scale(0.82–0.88)
photo画像スケルトンのきらめきの後、blur(14px) saturate(0.6) から鮮明に
wipeバー、塗り、ハイライト左から右への clip-path 表示
line / grow / donut罫線・目盛り / リング・ゲージscaleX(0) / scaleY(0)、12 時から時計回りのマスク
tray / rise / fadeシート・トレイ / 下に隠れるレイヤーコンテナ下端から 40px 上昇 / 不透明度のみ

ストーリーループ（主役）

読み込み後に、各ビジュアルが自分の役割を演じ続けることが本題です。読み込んで止まるだけのフレームは未完成とされます。作る前に、ビジュアルごとのストーリーを 1 文で決めます。

ビジュアルストーリーの例
項目の積み重ね（リード、通知、ファイル）新しい項目が上に着地し、他は 1 段下がり、最後の項目が去る
折れ線・面グラフスクラバーが横に進み、点が曲線に沿って動き、ツールチップの値が数え上がる
カレンダーハイライトが空き枠を探し、予定がそこへ移動して戻る
フロー・コネクタパルスが流れの向きに進み、通過したノードが光る
AI プロンプト・フォームプロンプトを消して打ち直し、チップを順に評価し、結果がぼかしから現れる
ロゴ列1 周期でちょうど 1 セット分動くマーキー
ストーリーの規則。 元のデザインの状態で始まり、元の状態に戻ります。デザイン内の要素を使います。テキストを変えるのはカウンターとタイピングの場合だけです。2 秒以内に動いていると分かる程度に動かし、カード同士は同時に動かさず読み順にずらします。1 カード 1 ストーリー、3〜8 秒です。

ループ周期と緩急（ショーケース）

フェーズ既定の時間
入場0 → 2.4 秒
ストーリー2.4 → 11.0 秒
消失11.0 → 11.6 秒（不透明度 0.5 秒）
空の間11.6 → 12.0 秒

イージングは、入場の変形に cubic-bezier(0.16, 1, 0.3, 1)（1.05 秒）、不透明度とぼかしに cubic-bezier(0.33, 1, 0.68, 1)、ワイプや掃引に cubic-bezier(0.65, 0, 0.35, 1) を使います。プロダクト UI の「300ms 以下」の規則はショーケースには適用せず、遅く滑らかにします。ズームとパンは依頼がない限り使いません。

7 — design-to-motion: 収録と書き出し（Part C）

実時間の画面録画はしません。ページに偽の時計を入れ、1 フレームずつ時計を進めてスクリーンショットを撮ります。SKILL.md の例は Playwright の page.clock を使っています。ページ側は ?capture モードで window.__start()、window.__tick(dt)、window.__lt を公開します。

ファイル仕様
<name>-x.mp4H.264、yuv420p、60fps、CRF 14〜15、preset slow、+faststart、最大 1920×1200、偶数サイズ
<name>-loop.gif幅 960px、15〜20fps、約 2〜3MB（Web サイト用）
<name>-800x500.gif常に納品。余白の広いフレームは 1.6:1 で内容に合わせて切り抜き、内容が全面のときは背景色で埋める。20fps（重ければ 12fps）

エンコードには ffmpeg を使います。

ffmpeg -start_number $A -framerate 60 -i frames/%05d.png -frames:v $N \
  -vf "crop=trunc(iw/2)*2:trunc(ih/2)*2" -c:v libx264 -preset slow -crf 15 \
  -pix_fmt yuv420p -movflags +faststart name-x.mp4

エンコード前の検査

検査確認すること
はみ出し角丸を含むコンテナの実形状の外側が、全フレームで変化しない
継ぎ目書き出し範囲の最初のフレームと、1 周期後のフレームが一致する
空の間空の間の全フレームが、__start 前のフレームと一致する（JS 状態のリセット漏れを検出）
静止消失直前のフレームが ?still と一致する（全ストーリーが元に戻った証明）
コンタクトシート主要な時点のフレームを並べ、はみ出し、残像、急な変化、目立たないストーリーを目視で探す

9 — 値の変更

README によると、各スキルのデザイン値（フォント、色、余白、モーション）はファイル末尾付近の 1 セクションにまとまっており、フォークしてそこを編集すれば残りの手順が従います。design-to-motion では Make it yours セクションに、移動距離、ぼかし量、時間、周期、書き出し設定の既定値が表でまとまっています。

landing-page-design は値が分散しています。 現行の SKILL.md には「Make it yours」に当たる独立セクションがなく、書体、余白、色、モーションの値は Part B の B1〜B7 に直接書かれています。変更するときは Part B の各節を編集します（本ページでの確認結果）。

10 — 制約と注意

  • landing-page-design の適用範囲は広いです。 description は、ランディングページに限らず Web UI のあらゆる作業で参照するよう指示しています。既存のデザインシステムを持つプロジェクトに入れると、書体の禁止リスト（Inter、Roboto など）やグラデーション禁止が既存の方針と衝突する可能性があります。導入先は限定することを推奨します（本ページの推奨です）。
  • 規則は作者の美意識に基づく固定値です。 使用可能な書体、余白、ダークモード背景色などは具体値で指定されています。ブランドの規定がある場合は、フォークして値を書き換える前提で使います。
  • design-to-motion は Figma の個人アクセストークンを使います。 スキルはトークンの表示やコミットを禁止していますが、エージェントにトークンを渡す運用自体のリスクは利用者側で判断が必要です。
  • 平面画像だけでは完全には再現できません。 レイヤーが分離できない部分は、その旨をユーザーに伝える手順になっています。
  • 書き出しにはブラウザ自動化と ffmpeg が必要です。 SKILL.md のコード例は Playwright の page.clock API と ffmpeg を前提にしています。README には動作要件の記載がないため、事前の導入が必要かを確認してください。
  • コレクションは開始直後です。 最初のコミットは 2026-07-29、design-to-motion の追加は 2026-10-25 で、README は「More on the way」としています。
